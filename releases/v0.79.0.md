# v0.79.0 — 2026-09-28

DRAFT, unreleased: written on `develop` during development to carry the update to other machines before the release exists; `VERSION` stays `0.79.0-alpha`, no `v0.79.0` tag exists, and `/pfm:release` replaces this file with the notes it derives from `develop`. `pfm install` now owns the host layout: one table of every path pfm owns, reconciled on every install, journaled, and reversible with `pfm install --rollback {id}`. The first install on this version moves an older host onto it — the config into the clone, the state databases to new names, every Claude account's session directories into one shared store, pfm's own entries out of your account files — and refuses before any change while a chat is live or a process holds a database. Until the release exists, a source clone updates with `git pull --ff-only` on `develop` and `make -C pfm host-install`, then `pfm install --yes` at once: work every `#### → For:` line below in order.

## Breaking

- pfm: host layout — the first `pfm install --yes` on this version moves `~/.config/pfm/pfm.config.json` (or `config.json`) and `harvester.config.json` into the clone; `~/.cc/fleet.db` to `~/.local/state/pfm/pfm.db` and `~/.local/state/pfm/fleet.db` to `pfm-cache.db`; each account's `projects/`, `file-history/`, `tasks/` and `session-env/` into `~/.claude/`, linked back; removes pfm-owned hooks, status lines and MCP entries from account `settings.json`, `.claude.json` and `~/.mcp.json`, keeping every other key; repoints the `~/.zshrc` source line to the clone's shim; writes the managed `cleanupPeriodDays` drop-in; removes the staged prompt files, an empty `shared.db` and stray dirs. Two differing files with one name keep the store's copy and park the account's copy in the journal, listed as a conflict.
#### → For: every adopter · before update · live chats — close every Claude chat, every Codex chat and every `pfm ls` picker, leaving pfm's own services running (install stops and restarts them); `ps -axo pid,command | grep -E '[c]laude|[c]odex|[p]fm (ls|chat)'` then lists nothing of yours.
#### → For: every adopter · before update · terminal — run the update from a plain terminal, outside tmux and outside a VS Code chat terminal, and `sudo -v` first so the managed-settings write can use cached sudo.
#### → For: every adopter · after update · host layout — run `pfm install` (preview; a `refuse` row names what to close or fix) and then `pfm install --yes` immediately after the binary is replaced, because the new binary refuses the old config (`config not migrated: run pfm install`) in pfm's services, hooks, the shim's `claude`, the MCP server and `pfm update` until it runs; keep the `{id}` from its last line `install journal: …/migrations/{id}`; `pfm doctor` then shows every layout row `ok`.
#### → For: macOS installs · after update · managed cleanup — `pfm doctor` shows `/Library/Application Support/ClaudeCode/managed-settings.d/pfm.json` present; when it reports it missing, run `sudo -v` and `pfm install --yes` again, because without it Claude Code's default deletes transcripts older than 30 days on any launch outside pfm.
#### → For: every adopter · after update · leftover processes — `make -C {clone}/pfm sweep-stale` ends only pfm processes still running the replaced binary; it prints none remaining.
- pfm: launch registry — every flag, environment value and `--settings` key a Claude chat starts with comes from one registry; pfm passes its hooks, status line and MCP server at launch instead of writing them into your account files.

## Migration

- pfm: backup — the install journal is the primary undo; take a second copy first, never including a credentials file (restoring an old one forks the login).
#### → For: Linux source installs · before update · host backup — `infra/fence/host-backup.sh {dest} quiet` from the clone prints `BACKUP OK`; `infra/fence/host-rehearsal.sh {dest} {scratch}` rehearses the whole install on a copy and writes `REHEARSAL PASS` under `{scratch}/rehearsal/`.
#### → For: macOS installs · before update · host backup — `host-backup.sh` is Linux-only; instead `B=~/pfm-backup-$(date -u +%Y%m%dT%H%M%SZ); mkdir -m 700 "$B"; cd ~; ls -d .claude .cc .config/pfm .local/state/pfm .mcp.json .zshrc Library/LaunchAgents/com.professor.pfm.* 2>/dev/null > "$B/paths.txt"; tar -czf "$B/home.tgz" --exclude='.credentials.json' --exclude='.codex/auth.json' --exclude='.local/state/pfm/harvest-python' --exclude='.local/state/pfm/releases' -T "$B/paths.txt" && cp -p ~/.local/bin/pfm "$B/pfm.before" && echo "BACKUP OK $B"`.
- pfm: rollback — `pfm install --rollback {id}` replays the journal backwards and refuses on drift unless `--force`; a refusal before any change leaves the host untouched.
#### → For: every adopter · after update · rollback — only to undo the update: `pfm install --rollback {id}` with the new binary, then `make -C {clone}/pfm rollback`, then the service start lines the rollback printed (`launchctl bootstrap gui/{uid} …` on macOS, `systemctl --user start …` on Linux), in that order (the reverse is refused unless `FORCE=1`); `pfm ls` then answers on the restored binary.
- Repo: dev fence disk — every image-building `.claude/scripts/dev.sh iso` action now clears stale fence containers (exited, or running over 6 hours unless long-lived), dangling fence images, unused lane images, the old `fence_pfm-dev-*` / `infra_pfm-dev-*` volumes and a Go build cache over 15000 MB, touching nothing that is not fence-owned.
#### → For: machines that run the dev fence · before update · Docker disk — reclaim the space the old fence left, fence objects only: `docker container prune -f --filter label=com.docker.compose.project=fence; docker image prune -f --filter label=com.docker.compose.project=fence; for v in $(docker volume ls -q | grep -E '^(fence|infra)_pfm-dev-'); do docker volume rm "$v"; done; docker volume rm pfm-dev-gocache`; `docker system df` shows the drop.

## Added

- pfm: chat new — `pfm chat new --harness-prompt PATH` launches a Claude seat on another system prompt.
- pfm: install journal — every host write `pfm install` makes is journaled with its backup; `pfm doctor` counts journals and names pending ones.
- pfm: plugins — `pfm install` sets up the cache-live-control and sub-agent-compact plugins on every Claude account; `pfm doctor` checks each account's own install record.
- pfm: project updates — `pfm doctor --project-updates` shows upstream intent for each project file, `pfm init --render` fills tokens once, `pfm update {adopt|pin|ignore|drop}` records the choice.
- pfm: status line — a sub-agent row shows the effort its own requests went out at.
- Global: /tokens — each run carries its cache TTL: `5m`, `1h`, `1h N%` when it wrote both, `—` with no cache writes or an engine that reports no split (Codex).
- Global: quality and research — `/quality:claude-md` (the shape law for orientation files), `/github-marketing`, `reviewer` proving every thread a diff touches, `tracer-rr`, `agent-optimizer` and `token-audit --timeline`.
- Repo: marketplace — the repository is a plugin marketplace for Professor-made plugins.

## Fixed

- pfm: shim — `cx` in a non-interactive shell refuses with a line naming `pfm chat new` instead of doing nothing; `claude` and `codex` skip terminal ownership outside interactive shells.
- pfm: usage limits — one usage-endpoint door with a cross-process lock and a shared 429 backoff.
- pfm: inject and reload — a Claude turn reads busy only on shapes the engine draws; `/reload` stashes only a real draft.
- Global: flights — cross-harness seats are born with `--name`.

## Removed
