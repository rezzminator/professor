# v0.84.0 — 2026-10-30

Prompt files now have one writer: a new launch hook, pcm-guard, refuses any edit to a `CLAUDE.md`, a `.claude/**` prompt file or the clone's `templates/**` by every caller but the `pcm` agent, in every project, so each adopted project needs its `pcm` agent before its chats can change those files. Four always-on machine-global rules now ship and bind every chat and sub-agent on Claude Code, Codex and OpenCode. Every Professor plugin now installs under one id, `{plugin}@professor`, and `pfm install` moves the older ids for you; each plugin points at a fresh release. The release also adds `pfm generate`, Herdr workspaces that follow the picker's places and a Prompt Lint button in the VS Code extension, and fixes a status line that went blank on long chats and a `pfm doctor` failure on hosts without Codex.

## Breaking

- pfm: pcm-guard — a new PreToolUse hook on Edit, Write, MultiEdit, NotebookEdit and Bash refuses a write to any `CLAUDE.md`, to `agents`, `commands`, `rules` or `skills` under a Claude config dir or a project's `.claude/`, and to the Professor clone's `templates/**` from every caller except the `pcm` agent (`templates/themes/**`: only `themer`); the refusal tells the chat to spawn `pcm` with the exact change, and a project with no `pcm` agent cannot have its prompt files changed from a chat at all.
#### → For: every adopter · per project · `.claude/agents/pcm.md` — make sure the project has the `pcm` agent: port the `agents/pcm.md` row of `pfm doctor --project-updates` (create the file from the template when it is missing) and close the row as the report prints, until `pfm doctor --project-updates` ends `clean`.
- Global: professor rule — the always-on rule `templates/global/rules/professor.md` tells every agent that only `pcm` writes prompt files and that everyone else hands `pcm` the change, matching the hook.

## Added

- Global: always-on rules — `templates/global/rules/` ships four machine-global rules that bind every chat and sub-agent: `git-writes-through-gitter` (every git write goes to the gitter agent), `flights-life-cycle` (small work by hand; one worktree and one lander per flight), `rm-rf-absolute-path` (`rm -rf` only on a literal absolute path) and `professor`; engine-sync carries them into Codex's and OpenCode's instructions.
- pfm: rules install — `pfm install` links each `templates/global/rules/*.md` into `{claude config dir}/rules/` and `pfm uninstall` removes the links it owns; a real file already holding a rule's name is kept as a conflict, and `pfm doctor` prints one rules row, naming the move-aside fix for a conflict.
#### → For: every adopter · after update · `pfm doctor` rules row — when the rules row names a conflicting file, move that file aside and run `pfm install` again; done when `pfm doctor` shows the rules row healthy.
- Global: /live-audit — a machine-global command that judges a feature by real use: it exercises the feature through its real trigger in live test chats and audits every occurrence from the raw transcript, with a WORKED, DEGRADED or FAILED verdict per occurrence.
- Global: /quality:rules — the law for writing and certifying rule files, with `check` and `write` modes; the `pcm` agent loads it before any rule-file edit.
- pfm: `pfm generate` — rebuilds the fleet prompts, the Codex config defaults and `developer_instructions`, the global command links and the engine-sync agents from the source clone without a pfm rebuild or a full `pfm install`; `--plan` prints what it would change.
- pfm: Herdr workspaces — a chat born, opened or resumed in Herdr lands in the workspace of its picker place (a nested repo files under its outer root), created when missing; running chats that sit in the wrong workspace are moved at each new tab and at Herdr server start.
- pfm: Prompt Lint — the VS Code extension (0.8.0) shows a Prompt Lint CodeLens over line 1 of prompt and skill files; a click runs `pfm headless exec` with the `/quality:prompt` law as its system prompt and turns the findings into Problems-panel diagnostics with a rewrite quick fix, cancellable while it runs; info findings stay hidden unless `professor.promptLint.showInfo` is on. (opt-in)

## Changed

- pfm: plugin ids — every Professor plugin installs as `{plugin}@professor`: an alpha build from a pfm-owned directory marketplace under `~/.local/share/professor-dev`, a release build from Professor's own marketplace; `pfm install` moves the older `{plugin}@{plugin}` and `{plugin}@{plugin}-dev` installs to the new id, carrying their plugin settings and keeping their data; a legacy copy it cannot move stays in place, disabled, as one install `warn` row naming its id, scope and repair, and `pfm doctor` names any legacy copy left.
#### → For: every adopter · after update · `pfm doctor` plugin rows — when `pfm doctor` names a legacy plugin copy, apply the repair its `pfm install` `warn` row names, then run `pfm install` again; done when `pfm doctor` names none.
- Repo: plugins — every marketplace plugin points at a new release: auto-effort-control 2.0.0, buddy 4.0.0, cache-keepwarm 0.6.0, cache-live-control 0.7.0, callmeter 0.5.0, engine-sync 0.6.0, forward-compaction 2.2.3, harvester 0.2.0 and tool-visibility-controller 0.4.0; the plugins log through one shared library with only errors on screen, and the forward-compaction repository is renamed from sub-agent-compact.
- pfm: callmeter cost ledger — while callmeter is installed, pfm hands it the cost-ledger directory as `CALLMETER_COST_LEDGER_DIR` unless `claude.env` already names it, and `pfm doctor` checks the same key.
- pfm: fleet prompt — the main chat never messages a finished agent again (new work, follow-ups and fixes go to a fresh one), its Verdict leads with the answer when the user asked a question, and thread mode keeps one block per open thread in every reply.
- pfm: status line layout — the Claude quota block is three rows: 5h and 7d-fable side by side, then 7d, then codex-7d, every quota row the same width.
- pfm: /clear on a named chat — `/clear` now hides a named chat from the picker like any other, leaving its numbered successor listed.
- pfm: model prices — `pfm model-cost` knows gpt-6.1-terra.
- Global: /quality:prompt — the law passes its own lint: emphasis is reserved for sacred ground and the anti-pattern catalog shrinks from 23 to 21 items, keeping the numbers other files cite.
- Global: agent compaction nudge — the flights agents and the imaginator no longer carry their own compaction instruction; forward-compaction's nudge carries it.
- Project: pcm and audit templates — `agents/pcm.md` covers rule files and `.claude/rules/`, and `agents/pcm.md`, `commands/audit/code-hygiene.md`, `docs-commands/pcm/references/audit-scopes.md` and `docs-hub/standards.md` name the landing gate and the `pcm` agent in place of "QA" and the retired `/pcm` command.
#### → For: adopters who customized these templates · per project · `pfm doctor --project-updates` — port each `UPDATED` row for these four templates, keeping your own edits, and close it as the report prints, until it ends `clean`.
- Repo: /pfm:release — the maintainer's release command ships develop's tip in one pass with `/pfm:release cut {patch|minor|major} "{summary}" [--dry]`; the releaser agent, the release rehearsal and the READY stamp are retired.
- Repo: CI — every develop push runs the test suite on macOS and a fresh-machine install on Linux and macOS, and tests updating from older releases.

## Fixed

- pfm: status line on long chats — a chat with a very large transcript rendered its status line slower than Claude Code's 5 s limit and showed none; scans now resume from a checkpoint, and renders run in a background worker per chat, served from a cache and refreshed 5 s after the last render.
- pfm: frozen quota — an idle chat's status line no longer shows a stale 5h or 7d reading once a newer reading of the same window exists on another seat or in the usage cache.
- pfm: doctor without Codex — an install with no Codex account, or `--skip-engine codex`, no longer fails `pfm doctor` on a `~/.codex` home it never wrote.
- pfm: stats-cache.json — Claude's `/stats` cache is per account again, so `pfm install` no longer blocks on `account-entry-real` after `/stats`; the installer removes the leftover links and archives the store copy.
- pfm: Herdr — a plugin's AskUserQuestion picker shows its tab as blocked, an unnamed seat finds its own chat through `whoami` and `exit`, a chat moved to another workspace finds its pane, a dead seat is retired once instead of re-probed every refresh, and Herdr result lists and diagnostics are validated and kept.
- pfm: theme sync — theme recovery, cache reads and tmux restore survive a failed step and keep rendering coherent.
- Global: chatlog — malformed Codex usage accounting fails loudly instead of counting wrong, and evidence generations are preserved.

## Removed

- pfm: Herdr tab priority — the opt-in `chat.herdrTabPriority` step that moved a waiting chat's tab to the leftmost slot is gone; a config file that still sets it loads unchanged and the key is ignored.
#### → For: adopters who set chat.herdrTabPriority · after update · `chat.herdrTabPriority` in `pfm.config.json` — delete the line, then `pfm config validate` exits 0.
- Project: /pcm command — `commands/pcm.md` is retired; dispatch the `pcm` agent directly, and `pfm doctor --project-updates` reports a leftover `/pcm` reference as a RETIRED-NAME pointing at it.
#### → For: every adopter · per project · `.claude/commands/pcm.md` — for its `GONE-UPSTREAM` row delete the file and run `pfm update drop .claude/commands/pcm.md`, point each RETIRED-NAME `/pcm` hit at the `pcm` agent, then `pfm doctor --project-updates` ends `clean`.
