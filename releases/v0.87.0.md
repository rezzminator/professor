# v0.87.0 — 2026-11-14

The `/quality:{x}` commands and `/iterative-improvement` are renamed into the `/law:{x}`, `/design:{x}` and `/improve:iterative` families, and the flights agents, the tracer and the reviewers move into the flights plugin under `flights:{x}` names, all the moment your clone moves; a running Herdr now hosts every new chat, pfm's log moves under the clone, and ponytail's `extensions` block in `pfm.config.json` is ignored until the next config write drops it. Herdr panes are what Herdr says they are: pfm no longer reads `herdr-keep` or `herdr-shield` pane holders, and Herdr's own Claude integration reports a native Claude pane. A project can now set its own fleet-prompt addition and environment in a `pfm.settings.json`, Codex and OpenCode chats run a project's own scripts again, and a stopped tmux server no longer hangs the picker. The Herdr indicator daemon stops rereading the cache database on every scan, and pfm's tests now run end to end through a journey tree on Linux and macOS.

## Breaking

- Global: /law and /design commands — the `/quality:{x}` family is renamed: `/quality:prompt` is `/law:prompt`, `/quality:doc` is `/law:doc`, `/quality:description` is `/law:description`, `/quality:claude-md` is `/law:claude-md`, `/quality:rules` is `/law:rules`, `/quality:md-forlint` is `/law:markdown`, `/quality:llm-codebase` is `/design:codebase`, `/quality:integration-suite` is `/design:test-suite`, and `/iterative-improvement` is `/improve:iterative` (its lab stays in `~/.local/state/pfm/iterative-improvement/`, and a lab now tunes across a ladder of larger worlds); `/quality:claude-selector` is removed with no successor; `/law:agent` is new: the law for an agent definition and the bench method that builds one. The old names stop resolving when the clone moves; the update's `pfm install` retires their dead links in `~/.claude/commands` and links the new ones. `pfm doctor --project-updates` has no `RETIRED-NAME` row for the old `/quality:{x}`, `/iterative-improvement` or `writing-code` names, so find them by hand.
#### → For: every adopter · after update · the commands you type — use `/law:{x}`, `/design:{x}` and `/improve:iterative` wherever you typed `/quality:{x}` or `/iterative-improvement`; `ls -L ~/.claude/commands/law/prompt.md` prints the path.
#### → For: every adopter · per project · old command and rule names in project files — replace each `/quality:{x}`, `/iterative-improvement` and `writing-code` mention in the project's own files with its successor above (`rules/coding.md` for `writing-code`); `grep -rnE '/quality:|/iterative-improvement|writing-code' CLAUDE.md .claude` prints nothing.
- Global: flights family — the flights agents leave `templates/global` for the flights plugin, which `pfm install` installs as a default plugin (`flights@professor`): `flights-foreman` is `flights:foreman`, `flights-foreman-sonnet` is `flights:foreman-sonnet`, `flights-lander` is `flights:lander`, `flights-speccer` is `flights:speccer`, `flights-hunter` is `flights:diff-checker`, `flights-spec-walker` is `flights:spec-checker`, `flights-sub-lander` is `flights:usage-checker`; `tracer` is `flights:tracer`, `sub-tracer` is `flights:sub-tracer`, `reviewer` is `flights:reviewer`, `reviewer-pro` folds into `flights:reviewer` (one reviewer that sizes itself by the diff) and `reviewer-nt` is deleted; the `tracetree` and `lander-inventory` skills become `flights:tracetree` and `flights:lander-inventory`, `/tracer:use` becomes `/flights:trace-guide`, and `/flights:doctor` and `/flights:spec` ship in the plugin. #### → For: adopters who read pfm's log files directly · after update · pfm's log folder — read the log through `pfm log` or from `{clone}/tmp/logs/pfm/` in place of `~/.local/state/pfm/`; `pfm log` prints the update's records.
- pfm: Herdr pane holders — pfm no longer reads a pane holder wrapped around Herdr panes (`herdr-keep`, renamed `herdr-shield` in this range and then removed): a Herdr pane is what Herdr says it is, with the agent in the pane's own process tree; Herdr itself stays supported, and a pane still running a holder reads as a plain Herdr pane.
