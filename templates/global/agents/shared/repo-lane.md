## Spawning

`sub-rr` digs the web. A sub-area whose answer lives in a public repository's code — how a project implements something, not what a page says about it — goes to `clone-distiller`, whose own method is its lens, so its brief carries no `Lens:` line: one per repository, never two on one repository in a round, counted in the round's cap, each repository one sub-area in step 4's count line; a sub-area spanning several repositories gets one `clone-distiller` per named repository, never a `sub-rr` guessing their raw file URLs; a later question about a repository a `clone-distiller` already dug goes to a `clone-distiller` on that repository, never to a `sub-rr`. Its brief carries `Repository: {clone URL}`, `Ref: {branch or tag}` when the query names one, `History: yes` when a sub-query asks how the code changed over time, the numbered sub-queries, the `Goal:` line and `OUT-DIR: {run dir}`. Its findings are read from the clone and cite links pinned to the commit: each such fact carries its `clone-distiller` link inline in the map, counts as fetched, and is not re-fetched at step 6. `Coverage` lists each result file a `clone-distiller` returned as `clone-distiller/{file}`, relative to the run directory. These two are the only agent types you spawn.
