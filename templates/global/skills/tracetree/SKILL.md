# tracetree

Run `python3 $HOME/.claude/skills/tracetree/tracetree.py {command}`, the path written in full in every command, `$HOME` and never `~`. Python 3 standard library; it reads the repo and writes only the run directory under `/tmp/{project}/tracer/`. A failure prints `TRACETREE FAILED — {reason}` and exits 2.

| Command | Who runs it | Does |

## The check

A file past 1 MB is searched only within 30 lines of a hop's address and of an answer cite's: a quote further off is `REJECTED` (`quote not within 30 lines of the address`) and a cite's quoted text is not moved there; a file past 128 MB is not read and its hops are `REJECTED`. Each such file is named once, as a `·` note after the WARNINGS block and by `start`.

A hop, a `start` FROM, a `read` block and an answer cite pinned to a git revision of ROOT read `{rev}:{path}:{line}`: the file is that commit's (`git show`, read-only, nothing checked out), stored and printed as `{commit, 12 hex}:{path}:{line}`. It is checked like any hop, never placed in the working tree, never `≈ DRIFTED`; a path the commit lacks or holds as a directory, a file there past 128 MB, or a revision naming no commit is `REJECTED` with that reason, and a git that cannot answer with `git could not say: {reason}`.

Each hop's quote is re-read from its file: found at its address it is verified; found within 30 lines or elsewhere in the file it is re-addressed. A path that names no file from ROOT — `server.go`, `internal/x.go`, `pkg/x.go` for `app/internal/x.go`, `a/../x.go` — resolves to the one file under ROOT ending in it, else to the one file of that basename holding the quote near the line; a quote absent from its named file resolves to the one sibling file holding it within 2 lines of the cited line, else, for a line of 24 or more non-space characters, to the one file of the same extension holding that line and the only file under ROOT that does; each prints as its full path with `(path resolved from …: {how})`. A hop no step places is `REJECTED` — unless it held when walked: its node's write recorded it verified (`{ID}.write.json`), or the commit the run started from (`RUN/BASE`, else the reflog) holds it, and the file changed since; then it is `≈ DRIFTED`, counted apart. A git lookup that fails prints `DRIFT UNKNOWN` and leaves the hop REJECTED. The printout always shows the file's own text, never the node's.

In the answers view, a cite whose backticked text sits on another line of the cited file is moved there (`↻`), and so is a cite at the line its reader gave a hop the kit re-addressed, by that hop's shift; a line citing no verified hop and no quoted text is `unbacked`; a backticked text found in no cited file is `?`; a `SPLIT` child that started and wrote nothing is `MISSING`. A cite whose only hops drifted is `≈`. The last line is `COUNTS:`, the run's tally of nodes, hops, verified, moved, rejected, drifted, placed, followed, refused and flagged lines.

Every `wait` and `check` view opens with the WARNINGS block: a `⚠` header naming how many nodes broke the hop contract, then a `⚠` line per node that named paths the kit had to place away from the cited line, stored hops after a refusal or has REJECTED hops, a run line for drift, and — beside those — one for hops that followed a file moved since the walk, which breaks no contract. A placed hop whose quote sits at its very cited line only miscopied its path: it breaks no contract and prints a `· node {ID}: the kit corrected a miscopied path …` note after the block, or after `WARNINGS: none`. Flagged answers stay in COUNTS alone, so a clean walk prints the single line `WARNINGS: none`. In the answers view every answer line of a node that broke the hop contract, and every line whose cite only such a node's hops back, ends `⚠ node {ID} broke the hop contract`. The MAP line, the page's red block and the JSON's `warnings` carry the same lines, the JSON's `notes` and a quiet block on the page the notes; `write` warns its own node on stderr.
