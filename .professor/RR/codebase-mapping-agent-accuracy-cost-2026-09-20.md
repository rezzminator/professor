# RR — How do others build LLM agents that map one area of a large codebase with maximum accuracy at minimum token cost?

Question: how do other people build LLM agents that answer questions about a large codebase and map one area of it (who writes X, who reads X, where it ends, what schedules/guards it) with MAXIMUM ACCURACY (no hallucinated symbols, quotes, file:line addresses or false "nothing references this" claims) at MINIMUM TOKEN COST. Hunt for implementations, research, posts, papers, code repos and tool hubs.

---

## Answer

The literature converges on a design very close to ours — lexical search is the cost-effective substrate (naive ripgrep already matches graph baselines and runs ~35x faster), cheap skeletons beat full files, and mechanical post-hoc citation checking is the only published hallucination control that works — but it contradicts us on three points worth acting on: **structure-aware deduplication of overlapping hits carries ~90% of the measured accuracy gain in grep-based retrieval** ([GrepRAG](https://arxiv.org/html/2601.23254v3)), **a failed quote should be re-anchored rather than dropped** (~80% of unverifiable citations are mis-addressed, not fabricated — [CiteFix](https://arxiv.org/html/2504.15629v2)), and **our fan-out is the expensive path unless one warm-up call precedes it** (parallel sub-agent calls each pay a cache write, not a read). The single biggest unmitigated risk our design shares with everyone else's: verbatim copying and enumeration recall both collapse as items-per-chunk grows (exact-copy 63% at 100 items → 7% at 500), so bucket size, not model choice, governs whether readers silently drop rows.

## The map

### 1. Retrieval substrate: grep vs index vs graph

**Agentic grep is the mainstream production choice and is competitive in research.** 8 of 13 shipping agents audited at pinned commits are "navigator-style" — general-purpose shell `grep`/`find`/`ripgrep` with the LLM formulating queries; only 5 invest in structure (Aider tree-sitter+PageRank, AutoCodeRover SBFL, Prometheus Neo4j, Moatless FAISS) ([Inside the Scaffold, arXiv 2604.03515](https://arxiv.org/html/2604.03515v2)). Anthropic's own position is a hybrid — upfront CLAUDE.md plus just-in-time `glob`/`grep` that "bypass[es] the issues of stale indexing and complex syntax trees" — argued, never measured ([Effective context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents), UNMEASURED). Cline publishes the strongest anti-index thesis (chunk fragmentation, index decay, embeddings as IP liability) with zero metrics ([cline.bot](https://cline.bot/blog/why-cline-doesnt-index-your-codebase-and-why-thats-a-good-thing), UNMEASURED).

**GrepRAG / "Better Call Grep" is the load-bearing measurement.** Naive GrepRAG — the LLM emitting m=10 ripgrep commands, no index at all — "achieves performance comparable to sophisticated graph-based baselines"; the full system beats the best baseline (RLCoder) by 7.04–15.58% relative EM on CrossCodeEval. Keyword mix across 45,615 real commands: method-name 41.47%, class-name 35.96%, variable-name 18.37%. Retrieval latency 0.0186s vs GraphCoder 0.2582s and RepoFuse 1.64s; on a 754k-LOC Java repo, **1.45s vs >50s (~1/35th)**. Ablation (Code EM): naive 38.61 → BM25 re-rank only 39.12 (+0.51) → **structure-aware dedup only 41.93 (+3.32)** → full 42.29. Code: [github.com/ZJU-ACES-ISE/greprag](https://github.com/ZJU-ACES-ISE/greprag). ([arXiv 2601.23254](https://arxiv.org/html/2601.23254v3))

**Semantic/indexed retrieval beat deep agentic search on repo QA in one head-to-head.** On SWE-QA: semantic search 65.2% correct vs deep agentic search (planner + isolated grep sub-agent) 46.2%, at less than half the cost; **41.8% of deep-agent failures occurred at the planner/sub-agent hand-off and were silent** — fluent, confident, wrong ([arXiv 2608.01507](https://arxiv.org/abs/2608.01507)). Note this measures *delegated* grep, not grep itself.

**Graph retrieval buys accuracy at a large token premium.** CodexGraph (Neo4j + LLM-generated Cypher) reaches CrossCodeEval-Lite EM 27.90% vs BM25 21.20%, SWE-bench-Lite pass@1 22.96% vs BM25 3.11% — but burns **22.16k tokens/query vs BM25's 1.47k** (~15x) and its schema has no call edges ([arXiv 2408.03910](https://arxiv.org/html/2408.03910v2)). LocAgent's heterogeneous graph (directory/file/class/function; contain/import/invoke/inherit; three tools SearchEntity/TraverseGraph/RetrieveEntity; index "a few seconds per codebase") reports SWE-bench-Lite file Acc@5 **77.74% (Claude-3.5) vs BM25 38.69% and Agentless 72.63%**, function Acc@10 77.37% vs BM25 36.86%; cost/issue **$0.66 → $0.09 (32B ft) → $0.05 (7B ft)** ([arXiv 2503.09089](https://arxiv.org/html/2503.09089v2), [code](https://github.com/gersteinlab/LocAgent)). RepoGraph (line-level def/ref nodes) lifts four host agents by **+32.8% relative on average** as drop-in context ([arXiv 2410.14684](https://arxiv.org/html/2410.14684v2), [code](https://github.com/ozyyshr/RepoGraph)). OrcaLoca: function match **65.33%**, file match **83.33%**, resolved 41.00% vs Agentless-1.5 58.67/78.67/34.67, at ~$0.87/instance for search ([arXiv 2502.00350](https://arxiv.org/html/2502.00350v2), [code](https://github.com/fishmingyu/OrcaLoca)). RepoUnderstander (MCTS) resolves 21.33% vs SWE-agent 18.00%, **no cost reported** ([arXiv 2406.01422](https://arxiv.org/html/2406.01422v1), UNMEASURED on tokens).

**At scale, BM25 wins on both axes — on a non-code corpus.** 512K documents / 601M tokens: BM25 combined score **50.5 vs File-System Agent 30.7 vs DenseRAG 29.9**; BM25 costs **0 construction tokens and 5.8K scale-invariant query tokens** vs the agent's **226K–343K per question (39–60x)**; MS-GraphRAG stalled at 10.6M construction tokens, LightRAG extrapolated to ~102B ([arXiv 2607.26497](https://arxiv.org/html/2607.26497v2)). Enterprise text, not code — transfer is unverified.

**Vendor positions, mostly unmeasured.** Aider: tree-sitter tags → NetworkX personalized PageRank (chat files ×50, mentioned identifiers ×10, private `_` ×0.1) → binary search to fit `map_tokens=1024` default; **no published benefit ablation** ([repomap.py](https://raw.githubusercontent.com/Aider-AI/aider/main/aider/repomap.py), [post](https://aider.chat/2023/10/22/repomap.html), UNMEASURED). Cursor: tree-sitter chunks + embeddings + Merkle-tree sync (50k-file workspace ≈3.2 MB of hashes), simhash index reuse cutting p99 index time 4.03h → 21s; the only accuracy claim is "**improved response accuracy by 12.5% on average**" with **no baseline named** ([cursor.com](https://cursor.com/blog/secure-codebase-indexing)). Sourcegraph/Cody **did publicly abandon embeddings** — "now that Cody Enterprise is generally available, we're leaving them behind (for now)" (third-party processing, freshness, vector DBs not scaling past ~100k repos), replaced by **native BM25/keyword search, not SCIP and not agentic search** ([sourcegraph.com, 15 Feb 2024](https://sourcegraph.com/blog/how-cody-understands-your-codebase)). The widely repeated "**Amp dropped vectors**" claim has **no first-party source** — [ampcode.com/news](https://ampcode.com/news) and the owner's manual never contrast with embeddings; kill that citation. Greptile publishes a graph story with no benchmarks ([docs](https://www.greptile.com/docs/how-greptile-works/graph-based-codebase-context), UNMEASURED). Continue: local MiniLM embeddings, `nRetrieve: 25` → rerank → `nFinal: 5`, `@Codebase` now deprecated ([docs](https://docs.continue.dev/reference/deprecated-codebase)). Cognition's SWE-grep: RL-trained retrieval-only model, **8 parallel tool calls × max 4 turns** (vs 10–20 serial), 2,800+ tok/s (mini) vs Haiku 4.5 at 140 tok/s, scored on **precision-weighted F1** because "context pollution is more detrimental than leaving some context out" — against a private eval ([cognition.com](https://cognition.com/blog/swe-grep), public numbers UNMEASURED).

### 2. Cheap structure: what a skeleton buys

**Agentless's skeleton level is the cheapest accuracy win published and it beats full text.** Level 1: repo structure in `tree` format + issue → top-3 files; recall 81.67% combined with an embedding search, ~$0.02–0.05. Level 2: **class/function declaration headers, signatures and docstrings only**, cutting input from >3000 to <800 LOC and scoring **58.33% vs 53.67% for complete files** — cheaper *and* more accurate — at $0.02. Level 3: full code with line numbers, sampled 4× at T=0.8 (56.33% vs 49.67% greedy). Localization totals ~$0.06–0.10 against $0.70 end-to-end ([arXiv 2407.01489](https://arxiv.org/html/2407.01489v2), [code](https://github.com/OpenAutoCoder/Agentless)).

**Signature-only compression has no independent measurement and one contrary signal.** Repomix's `--compress` keeps signatures/types/class structure, drops implementations, is labelled **experimental, and publishes no percentage at all** — the circulating "~70% reduction" is third-party ([repomix.com](https://repomix.com/guide/code-compress)). Repomix itself notes compression is "generally not needed since `grep_repomix_output` allows incremental content retrieval" ([MCP guide](https://repomix.com/guide/mcp-server)) — an endorsement of grep-first. Contrary signal: giving models only ground-truth signature/premise lists **decreased** performance vs summaries carrying usage and related types ([arXiv 2509.25197](https://arxiv.org/pdf/2509.25197), magnitude UNMEASURED here).

### 3. Structural indexes: zero-setup reality and the miss list

|---|---|---|---|
| universal-ctags | yes | definitions only | all references, cross-file ([repo](https://github.com/universal-ctags/ctags)) |
| tree-sitter / ast-grep | yes, ad-hoc `sg run -p` | 20+ langs | **no cross-file or type resolution** — cannot follow an import or resolve an interface ([ast-grep](https://github.com/ast-grep/ast-grep)) |
| SCIP / LSIF | **no** | 10 mature indexers | **every one marked "Requires Build: Yes"**; no cross-repo for Kotlin/Rust/C# ([Sourcegraph](https://sourcegraph.com/docs/code_navigation/references/indexers)) |
| stack-graphs | **yes** — "purely syntactic… requires no configuration… does not need to invoke a build" | Python in prod since Nov 2021 | accuracy **UNMEASURED**; paper explicitly "loosen[s] this restriction to allow ambiguous and missing bindings"; <100ms query target ([arXiv 2211.01224](https://arxiv.org/pdf/2211.01224)) |
| LSP (Serena) | partial | 40+ langs via solidlsp | cold-start per request in most MCP bridges, **stale data with no way for the agent to know** ([Serena](https://github.com/oraios/serena), [agent-lsp](https://blog.blackwell-systems.com/posts/agent-lsp/)); Serena now GPL-3.0 |
| CodeQL | build required for compiled langs; `build-mode: none` for C/C++, C#, Java, Rust with documented accuracy loss | broad | generated code omitted without build ([docs](https://docs.github.com/en/code-security/reference/code-scanning/codeql/build-options-for-compiled-languages)) |
| Joern CPG | **yes — no compilation** | C/C++, Java+bytecode, Kotlin, Python, JS/TS, LLVM, x86 | Scala CPGQL DSL; no first-party MCP ([repo](https://github.com/joernio/joern)) |
| Kythe | no — instrumented compiler | C++, Java only | effectively unusable ad-hoc ([kythe.io](https://kythe.io/docs/kythe-overview.html)) |
| Semgrep CE | yes | 30+ langs | **"can only analyze interactions within a single function"**; cross-file is paid, full-scan-only, falls back above 5 GB or 3 hours ([docs](https://docs.semgrep.dev/semgrep-code/semgrep-pro-engine-intro)) |

**The miss list is quantified and it is severe.** Median static call-graph recall against a runtime oracle on 31 Java programs is **0.884**; best dynamic-feature support reaches only 0.935 "with a hefty performance penalty"; the dominant unsoundness was **not reflection** but objects via native methods and **JVM-initiated invocations with no matching call site** ([ICSE 2020, DOI 10.1145/3377811.3380441](https://doi.org/10.1145/3377811.3380441)). In framework-heavy code it collapses: 13 static tools over 1,000 Android apps **missed 61% of dynamically-executed methods on average**, with the line "a high level of precision in call graph construction is a synonym for a high level of unsoundness" ([arXiv 2407.07804](https://arxiv.org/abs/2407.07804)). Frequency of the voiding constructs: dynamic language features in **78% of 461 Java projects / 79.4 MSLOC**, with 21% using dynamic proxies, 38% exceptions for non-exceptional flow around reflection, 55% storing meta-objects in generic collections ([ICSE 2017](https://aserebre.win.tue.nl/ICSE2017.pdf)); 550,358 `eval` calls across >10,000 web sites ([ECOOP 2011](https://link.springer.com/chapter/10.1007/978-3-642-22655-7_4)); 49,296,059 `eval` calls in 15,401 R packages ([OOPSLA 2021](https://dl.acm.org/doi/pdf/10.1145/3485502)). The soundiness manifesto's framing is the honest template: no realistic whole-program analysis is sound, all deliberately under-approximate a known feature set, and the prescription is to **name the unsoundness explicitly** ([Soundiness CACM](https://yanniss.github.io/Soundiness-CACM.pdf)).

**Consequence for a mapper: on string-mediated wire names, grep is not a poor substitute for the index — it is the only layer that sees them.**

### 4. Cross-language / string-mediated coupling

Microservice architecture recovery, 13 static tools on a 17-app benchmark: best single tool **F1 0.86 (Code2DFD)**, four-tool ensemble 0.91 — but per characteristic Code2DFD is **0.98 components, 0.87 connections, 0.66 endpoints**, MicroDepGraph precision 1.0 / recall 0.76, and Prophet (folder/annotation heuristics) collapses to **precision 0.56, recall 0.15, F1 0.23** ([arXiv 2412.08352](https://arxiv.org/html/2412.08352v1)). Detection is literally keyword matching ([Code2DFD, arXiv 2304.12769](https://arxiv.org/pdf/2304.12769)). The benchmark is REST/RPC-only; **no tool reported external/third-party components and queue topics are not in the ground truth** — async wire names are UNMEASURED.

Traceability-link recovery is the adjacent field: LiSSA (ICSE 2025) does RAG-based TLR across requirements↔code, docs↔code, architecture↔model, "significantly outperform[ing] the state of the art on code-related tasks" but the project page publishes **no P/R/F1** ([ardoco.de](https://ardoco.de/approaches/lissa/), [replication](https://github.com/ArDoCo/Replication-Package-ICSE25_LiSSA-Toward-Generic-Traceability-Link-Recovery-through-RAG)). **Nothing found crossing code ↔ config ↔ DB schema ↔ UI** — the literature's axis is NL-document↔code.

**No peer-reviewed source quantifies the string-mediated share of total coupling** — two rounds of searching. Circulating figures ("73% of deployments", "31–94% hard-coded dependencies") trace to vendor and patent pages ([Augment](https://www.augmentcode.com/tools/microservices-impact-analysis), [USPTO 8949812](https://image-ppubs.uspto.gov/dirsearch-public/print/downloadPdf/8949812)) — UNMEASURED marketing.

**Data lineage is the one place the ORM boundary is genuinely crossed.** Accuracy comparison over ~7,000 BigQuery SELECTs / ~2,000 CTAS: **DataHub 99% table / 86% column** on SELECT and 98%/76% on CTAS; **sqllineage 92%/27% and 88%/9%**; openlineage-sql 97%/44% and 92%/15% — with the authors' caveat that only DataHub had schema access, which is the whole differentiator ([datahub.com](https://datahub.com/blog/extracting-column-level-lineage-from-sql/)). Documented limits: scalar UDFs resolve only to input columns, multi-statement SQL and stored procedures unsupported, dynamic identifiers yield **no lineage at all**, each row carrying a 0–1 `confidence_score` ([docs](https://docs.datahub.com/docs/lineage/sql_parsing)). SQLGlot silently degrades to unresolved leaves without a schema, and unexpanded stars make positional mappings "silently shift" ([sqlglot.com](https://sqlglot.com/pdoc/lineage.html)). For code→table: Meurice/Nagy/Cleve's JDBC+Hibernate+JPA analysis extracts queries for **71.5%–99% of database accesses with 87.9%–100% valid**, over systems of 250–2,054 kLOC ([CAiSE 2016](https://link.springer.com/chapter/10.1007/978-3-319-39696-5_30), numbers snippet-level UNVERIFIED); its tool SQLInspect does path-sensitive backward string analysis from hotspots with a parser that **tolerates unresolved fragments**, benchmarked at 157.9s on 797 kLOC ([ICSE 2018 PDF](https://csnagy.github.io/research/pdfs/2018/Nagy-ICSE2018.pdf)). For **Prisma/Drizzle/SQLAlchemy/ActiveRecord: nothing usable found** — and nothing published chains symbol → column → API field → frontend component end to end.

### 5. Finding every spelling (our grep-recall problem)

**The industry default cannot support an absence claim.** Zoekt indexes **positional trigrams, not tokens** — a search for `user_id` does not find `userId` because the trigram sequences differ; case-insensitivity expands to case variants only ([zoekt design.md](https://github.com/sourcegraph/zoekt/blob/main/doc/design.md)). Sourcegraph's search-based "find references" is explicitly "a case-sensitive word-boundary cross-repository plain-text search for the symbol" ([docs](https://sourcegraph.com/docs/code-search/code-navigation/search_based_code_navigation)). ripgrep's `-w` is "roughly equivalent to putting `\b` before and after all patterns", so since `_` is a `\w` char the boundary never falls between `camel` and `Case`, while `-` in kebab-case creates boundaries mid-identifier — **one `-w` query provably cannot cover the convention set** ([rg(1)](https://manpages.debian.org/testing/ripgrep/rg.1.en.html)), and there is an open incomplete-match bug under `-w` ([issue #2574](https://github.com/BurntSushi/ripgrep/issues/2574)).

**Feature-location research solved the vocabulary problem by normalizing the corpus, and measured it.** The standard IR-FLT pipeline is split → case-normalize → filter stopwords/keywords → stem ([PMC8550475](https://pmc.ncbi.nlm.nih.gov/articles/PMC8550475), 8 baseline FLTs over 12 systems of 482–123,732 methods). Vocabulary normalization (split **plus abbreviation expansion**, `avglen` → `average-length`) raised MAP by **+52pp over conservative splitting and +49pp over GenTest** on 40 auto-generated queries (p<0.0001), **+58pp/+55pp on the shortest queries**, Cohen's d 1.42–1.71 — with the explicit conclusion that "**splitting alone… does not expose all of the important vocabulary**" ([Binkley ICSM 2012 PDF](http://www.cs.loyola.edu/~binkley/papers/icsm-12-concept-location.pdf)). TRIS reports F=0.9328 on 974 JHotDraw identifiers, beating CamelCase/Samurai/TIDIER/GenTest ([WCRE 2012 PDF](https://assets.ptidej.net/Publications/Documents/WCRE12b.doc.pdf)). The field's comparability crisis is itself documented: **170 articles, 60+ distinct metrics, 272 subject systems, 235 benchmarks** — no FL number is directly reusable as a recall target ([EMSE](https://link.springer.com/article/10.1007/s10664-019-09734-5)). The "0.60 → 0.95" figure circulating for normalization is **UNVERIFIED**.

**No published study or agent prompt systematically enumerates spelling variants** (plural, abbreviation, string-literal, SCREAMING) at query time — the prior art normalizes the corpus instead. This is genuinely open ground and directly our design's differentiator.

### 6. Safe negatives and confidence tiers

**Do not let a model assert absence.** AbstentionBench (20 datasets, 20 frontier LLMs): abstention is unsolved, scaling barely helps, and **reasoning fine-tuning degrades abstention by 24% on average** ([arXiv 2506.09038](https://arxiv.org/abs/2506.09038)) — aimed squarely at a reasoning-model composer emitting "nothing references this".

**Shipped tools express absence-uncertainty two ways.** Vulture publishes a provenance-derived confidence scale — **100%** unused arguments/unreachable code, **90%** imports, **60%** attributes/classes/functions/variables, with `--min-confidence` — and concedes static analyzers "are likely to miss some dead code", with `getattr(greeter, func_name)` as the canonical voiding construct handled by whitelists ([repo](https://github.com/jendrikseipp/vulture)). Rust's `dead_code` uses **scope restriction instead of confidence**: it exempts `pub` items entirely because the lint is crate-local ([rustc lints](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html), [rust#120079](https://github.com/rust-lang/rust/issues/120079)). Knip publishes **no confidence tier and no FP rate**, enumerating voiding constructs instead (template strings in dynamic imports, external-library API references, named exports via member access on a `require`d variable) and arguing "a surprising result is usually a real finding or a configuration gap" ([knip.dev](https://knip.dev/guides/handling-issues)). Brakeman's High/Medium/Weak tiers are analysis-derived and the docs self-disclaim: "Brakeman can easily guess wrong" ([brakemanscanner.org](https://brakemanscanner.org/docs/confidence/)). SARIF has a confidence field that "almost no tool populates… but Brakeman does" ([boostsecurity](https://boostsecurity.io/blog/sarif-cant-save-you-now)).

**Evidence that tiers help a consumer is indirect.** 35–91% of static-tool warnings can be ignored; 56% of SAST warnings across 30 OSS Java projects were never addressed; learned actionability rankers reach median AUC 92%, identifying >90% of actionable warnings while telling humans to ignore 70–80% ([arXiv 2006.00444](https://arxiv.org/pdf/2006.00444), [survey](https://arxiv.org/pdf/2312.00324)) — ranking concentrates attention, but **hand-authored tiers as the cause is UNMEASURED**.

**The one principled safe negative:** external reachability is undecidable from in-repo data, but for non-externally-visible symbols "unreferenced in-repo" genuinely means dead — i.e. absence is assertable only inside a visibility-bounded scope ([code-indexer issue 1835](https://github.com/LightspeedDMS/code-indexer/issues/1835)).

### 7. Hallucination control: quotes, citations, verification

**Quote-first is Anthropic's own guidance, unmeasured.** For documents >20k tokens, extract word-for-word quotes first and base analysis only on them, with a "No relevant quotes found" escape hatch ([long-context tips](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices) — exact wording UNVERIFIED-by-fetch, hallucination-reduction rate UNMEASURED).

**Academic attribution uses entailment, not string matching.** ALCE scores citation recall/precision by NLI, and even the best systems lack complete citation support ~50% of the time on ELI5 ([arXiv 2305.14627](https://arxiv.org/abs/2305.14627)); Bohnet et al. define AQA and AutoAIS ([arXiv 2212.08037](https://arxiv.org/abs/2212.08037)); GopherCite enforces verbatim copying by construction with abstention, rated high-quality 80% on NaturalQuestions, 67% on ELI5 ([arXiv 2203.11147](https://arxiv.org/abs/2203.11147)). InteGround's finding is the argument for our mechanical check: **NLI verifiers are high-precision/low-recall and paraphrase-brittle, while LLM verifiers rationalize incomplete evidence into "entailment"** ([arXiv 2509.16534](https://arxiv.org/pdf/2509.16534)). FActScore shows a cheap automated verifier can substitute for humans: **<2% error vs human FActScore**, evaluating 6,500 generations that would have cost $26K in labour ([arXiv 2305.14251](https://arxiv.org/abs/2305.14251)).

**The closest published twin to our pipeline.** "Citation-Grounded Code Comprehension" mandates a `CITATION: [file:start-end]` line, extracts it by regex, and tests **interval overlap against the retrieved chunk set** — a **post-hoc filter, not a pre-generation constraint**; a citation outside retrieved context is **flagged as a hallucination, not regenerated**, and responses with no valid self-citation get an **auto-cite fallback to the top-ranked chunk, triggered in 32% of responses**. Retrieval is a weighted sum (α=0.45 BM25 + β=0.55 BGE-base-en-v1.5, k=28) plus 1-hop Neo4j BFS over IMPORTS edges only — no call graph, no data flow. "92% citation accuracy" = share of 1,080 responses containing ≥1 mechanically-verified citation; "zero hallucinations" is the **post-filter** state; validation was a 30% manual sample (324 responses), 97% of flagged hallucinations genuine, **no inter-rater agreement reported** ([arXiv 2512.12117](https://arxiv.org/html/2512.12117v1); code listed as [code_comprehension_sdk_design_with_citation_verification](https://github.com/jahidul-arafat/code_comprehension_sdk_design_with_citation_verification), availability UNVERIFIED). **Caveat we should carry: the 32% auto-cite fallback may be where much of the 92% comes from.**

**Re-anchor, don't drop.** CiteFix: baseline Model C had **80.6% of factual points incorrectly cited**; purely post-hoc mechanical correction (keyword + semantic string matching, no generator re-invocation) cut that to **33.3%**, +15.5% relative MQLA — and **~80% of unverifiable facts are mis-citation, not fabrication** ([arXiv 2504.15629](https://arxiv.org/html/2504.15629v2)).

**Hallucinated entities, measured.** 576,000 code samples across 16 LLMs produced **205,474 unique hallucinated package names**, commercial models ≥5.2%, open-source ≥21.7% ([arXiv 2406.10279](https://arxiv.org/abs/2406.10279)). **No paper measures hallucinated file paths or line numbers specifically** — our actual failure mode (UNMEASURED).

### 8. Cheap models as constrained extractors — the reliability ceiling

**Verbatim copying degrades steeply with item count.** Exact-string inclusion of constants a model must copy: mean **63.46% at N=100, 15.65% at N=300, 7.12% at N=500**, with **zero perfect runs above N=100**; gpt-oss_120b 100/73.9/35.9 vs llama3.2_3b 99.7/11.3/1.0; **45.2% of N=300 runs contained zero expected values** — silent truncation, not paraphrase ([arXiv 2601.03640](https://arxiv.org/html/2601.03640v1)). For a *single short* span, mini-class is ~80–90% exact: TimeStampEval reports GPT-5 ~92%, GPT-5-mini ~88%, GPT-5-nano ~82%, Gemini 2.5 Flash ~89%, Flash-Lite ~81% ([arXiv 2511.11594](https://arxiv.org/html/2511.11594v1)).

**Line-number errors are real, layout-sensitive, and mostly ±1.** Off-by-one index errors run **12–16% under JSON output with the query placed after the text, dropping to ~5% under a text-first / query-before layout**, with a "ladder effect" where model size moves errors from complete miss → off-by-one → exact ([TimeStampEval](https://arxiv.org/html/2511.11594v1)). Narrowing the context mechanically cut cost-per-correct **$0.0547 → $0.0045 (~12x)** — evidence that shrinking the input beats upgrading the model.

**Enumeration recall is the silent killer.** Long object-list extraction: LLM-only baselines ~50% recall, retrieval-augmented ~75–80% at stage 1, falling to **48% recall@P50 and 30% recall@P80** after precision filtering; head/tail split 90%+ vs 65–81% ([arXiv 2405.02732](https://arxiv.org/html/2405.02732v1)). The recall-vs-true-list-length curve is **UNMEASURED**.

**Structure helps extraction and hurts reasoning.** JSON-mode drops GSM8K 86.5→23.4 (Claude-3-Haiku), 76.6→49.3 (GPT-3.5) — but **helps** classification/extraction: DDXPlus Haiku 33.8→52.0, Gemini-1.5-Flash 41.6→60.3, GPT-3.5 44.1→55.5. The cause is key-ordering forcing answer-before-reasoning, not parse failure (0.148% parse errors coexisting with a 38-point gap), and a two-step "NL-then-format" prompt recovers it ([arXiv 2408.02442](https://arxiv.org/html/2408.02442v3)). JSONSchemaBench counters that with real grammar engines "constrained decoding consistently improves downstream tasks up to 4%", while schema coverage varies wildly (Guidance 0.41 vs Outlines 0.03 on GitHub-Hard) ([arXiv 2501.10868](https://arxiv.org/html/2501.10868v1)). Sub-4B models keep field-level F1 0.89–0.95 while **document-level validity collapses** (Gemma3-1B 0.10, Phi3-3.8B 0.01 vs GPT-4o 0.52) — values right, envelope broken, exactly what a mechanical verifier catches cheaply ([arXiv 2602.14743](https://arxiv.org/html/2602.14743v1)).

**Retry vs escalate is unmeasured for extraction.** The decision rule: resampling gains are bounded by the cheap model's own ceiling; escalation dominates when the strong model's error reduction exceeds the cost multiplier ([arXiv 2605.06350](https://arxiv.org/pdf/2605.06350)). FrugalGPT reports up to 98% cost reduction at GPT-4-level quality, but on QA with a learned scorer, not a deterministic verifier ([arXiv 2305.05176](https://arxiv.org/abs/2305.05176)).

### 9. Orchestration and token economics

**Multi-agent multipliers.** Agents use ~4x the tokens of chat, **multi-agent ~15x**; Opus-4 lead + Sonnet-4 subagents beat single-agent Opus 4 by **90.2%** on an internal research eval; **token usage alone explains 80% of performance variance**; and the named anti-pattern is domains "that require all agents to share the same context or involve many dependencies between agents", with **most coding tasks having fewer parallelizable subtasks than research** ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Sub-agents "returns only a condensed, distilled summary… (often **1,000–2,000 tokens**)", with the risk named but unquantified: "overly aggressive compaction can result in the loss of subtle but critical context" ([context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

**The controlled study says our shape is the good one.** 180 configurations, 5 architectures, 4 benchmarks, 3 model families: **+80.9% for centralized coordination on parallelizable tasks**, but **−39% to −70% on sequential tasks**, with error amplification **17.2x for independent agents vs 4.4x centralized** ([Google Research](https://research.google/blog/towards-a-science-of-scaling-agent-systems-when-and-why-agent-systems-work/)). MAST (1,642 traces, 7 frameworks, κ=0.88): **System Design 43.7%, Inter-Agent Misalignment 45.5%, Task Verification 10.8%**; targeted fixes gave +15.6% (adding a verification step) and +9.4% (termination authority) ([arXiv 2503.13657](https://arxiv.org/html/2503.13657v3)). Cognition's "Don't Build Multi-Agents" supplies the two principles — share full traces, and actions carry implicit decisions — with **zero quantitative data** ([cognition.com](https://cognition.com/blog/dont-build-multi-agents), UNMEASURED).

**Caching decides whether fan-out is cheap.** Anthropic: **5-min cache write 1.25x base, 1-hour 2x, cache read 0.1x**; the cache is keyed on exact prefix and isolated **per workspace, not per conversation**, so sibling calls hit it — **but "a cache entry only becomes available after the first response begins… If you need cache hits for parallel requests, wait for the first response before sending subsequent requests"** ([pricing](https://platform.claude.com/docs/en/about-claude/pricing), [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)). A simultaneous N-reader burst therefore pays N cache *writes*. OpenAI discounts cached input up to 90% with a 1,024-token minimum and caches shared within an org ([docs](https://developers.openai.com/api/docs/guides/prompt-caching)). Batch is a flat 50% off on both vendors and **stacks with caching**; Haiku 4.5 $1/$5 → $0.50/$2.50 batch, cache read $0.10/MTok; gpt-5-nano $0.05/$0.40. Two traps: Claude 4.7+ tokenizers produce **~30% more tokens for the same text**, and the tool-use system prompt adds 496–588 tokens per Haiku 4.5 request.

**Cost structure of agent loops.** Agentic coding consumes ~1000x the tokens of code chat, **input tokens dominate even with caching**, same-task runs vary up to **30x**, accuracy peaks at intermediate cost, and models predict their own cost at only ρ≤0.39 ([arXiv 2604.22750](https://arxiv.org/abs/2604.22750)); the per-category split (tool results vs reasoning vs re-sent context) **is not quantified in that paper** — UNMEASURED. One documented session: 940K cached reads (~94.5%), 50K cache writes, 5.3K output, $0.55 total ([Augment](https://www.augmentcode.com/guides/ai-coding-cost-analysis-agent-token-spend)).

**Context rot is the empirical case for small isolated readers.** 18 models × 8 input lengths × 11 needle positions: performance is **non-uniform in input length even on trivial tasks**; low needle-question similarity degrades faster with length; and **shuffled haystacks beat coherent ones across all 18 models** ([Chroma](https://www.trychroma.com/research/context-rot)).

**Compression trades accuracy.** ContextSniper (n=50/agent): OpenClaw **1.36M → 0.66M tokens (−51.5%), cost −36.4%, tool calls −46.4%, resolve rate 26.0% → 24.0%**; Claude Code −38.9% tokens, 32.0% → 30.0% — machinery is L0/L1/L2 memory fused by weighted RRF over embeddings + BM25 + ctags + graph relations **with a ripgrep fallback** ([arXiv 2607.01916](https://arxiv.org/html/2607.01916v3)). Active Context Compression reports 22.7% overall reduction ("up to 57%" is a per-instance max) at zero accuracy delta — but **N=5**, no statistical power ([arXiv 2601.07190](https://arxiv.org/abs/2601.07190), UNMEASURED at useful confidence). Codebase-Memory (tree-sitter KG over MCP, 66 languages, 31 repos): **10x fewer tokens and 2.1x fewer tool calls at 83% answer quality vs 92%** for a file-exploration agent — cheaper and 9 points worse ([arXiv 2603.27277](https://arxiv.org/abs/2603.27277)).

**A perfect ledger does not save the composer.** TRAJEVAL over 16,758 trajectories: **60–69% of capable-model failures reach and edit the correct functions** and still fail; Edit-Quality is 56.9% of SWE-Agent failures, of which **Coherence Collapse is 39.7%**; 5 of 97 Near-Correct cases produced a **bit-identical-to-gold patch mid-trajectory and then destroyed it**, all 5 passing on resubmission ([arXiv 2603.24631](https://arxiv.org/html/2603.24631v2)).

### 10. Benchmarks we could actually score ourselves on

- **CORE-Bench** — publicly released (HF `zhangfw123/CORE-Bench`, eval code `CORE-Bench-Eval`); **Level 2** is 5,061 queries / 632 repos / 9.38M chunks, patch-aligned labels, NDCG@10 + Recall@100; **Level 3** is 2,580 queries with **41.27 gold docs per query scored by Recall@100 — blast-radius recall in all but name**. Any ranked file/chunk list is scorable. Qwen3-Embedding-8B zero-shot L1 63.0 → **L2 20.3 NDCG@10**; L2+L3 context lifts agent resolve 43.2% → 69.0% ([arXiv 2606.11864](https://arxiv.org/html/2606.11864v3)).
- **Multi-file change localization** (arXiv 2606.11976) — real PRs at a pinned base commit, micro-F1 **plus an explicit "all-gold recall"**; its headline finding is that a Sonnet baseline wins micro-F1 by predicting few files, with **much lower all-gold recall** — exactly the failure a map benchmark must punish ([abs](https://arxiv.org/abs/2606.11976)).
- **SWE-QA** — 720 QA pairs / 15 repos, taxonomy What 13.3% / Why 23.1% / Where 28.4% / How 35.2%, 90.9% multi-hop; GPT-5.1 Direct 61.41 → RAG ~66.6 → SWE-agent 69.20 → **OpenHands 70.79**, at roughly **100x the tokens of direct answering** ([arXiv 2509.14635](https://arxiv.org/html/2509.14635v2)). SWE-QA-Pro adds 260 long-tail questions and **abandons RAG entirely** for keyword search + scoped file viewing ([arXiv 2603.16124](https://arxiv.org/html/2603.16124), [code](https://github.com/TIGER-AI-Lab/SWE-QA-Pro)).
- **Code-QA-Bench** — 528 code-derivable + 100 doc-dependent tasks over 10 pinned SWE-bench repos; gold answers carry `key_files[]` and ≥3 `code_evidence[]` items, and **key file paths are validated against the filesystem with a re-prompt on miss**; §6.1 exposes a pluggable async `(repo_path, question) -> answer` interface, CC BY 4.0 — but **no GitHub URL in the paper** ([arXiv 2605.29277](https://arxiv.org/html/2605.29277v1)).
- **StackRepoQA** — 1,318 real SO Q&A over 134 Java repos; **file-RAG alone (5.66) scored *worse* than direct prompting (6.67)**, Graph-RAG 6.12; post-cutoff questions drop scores ~1 point, documenting memorization ([arXiv 2603.26567](https://arxiv.org/html/2603.26567v2), [Zenodo](https://doi.org/10.5281/zenodo.18276514)).
- **RepoQA** — 500 needle-function tasks, 50 repos, 5 languages; SOTA ~90.6% ([arXiv 2406.06025](https://arxiv.org/html/2406.06025)).

**Ground-truth recipe for "all references to X": TraceEval's execution-as-oracle.** It takes the tracer's recorded edge set as ground truth, explicitly rejecting manual annotation ("rater disagreement and annotator drift") and static tools ("trade recall for precision and disagree across tools"): harvest permissive repos ≥50 stars, extract single-definition files ≥20 LOC, have an LLM add an entry-point driver and stub external imports, then trace (Python `sys.settrace`, JS AST instrumentation, Java runtime stack) and **accept only if it runs clean, yields ≥2 cross-function edges, and produces an identical edge set across three independent runs**; 10,583 programs, edge-level P/R/F1 ([arXiv 2605.11006](https://arxiv.org/html/2605.11006v1), [code](https://github.com/yikun-li/TraceEval)). *Total Recall?* (ISSTA 2024) uses the same convention with coverage-guided fuzzing ([PDF](https://www.opal-project.de/articles/TotalRecall@ISSTA24.pdf), numbers did not extract).

### 11. Evidence-ledger implementations outside code

**GroundedRAG** decomposes answers into `AnswerClaim` objects each bound to `EvidenceId[]`, then runs a **purely deterministic, zero-LLM verifier gate** — citation completeness → surface consistency (entities/numbers/units must match evidence text) → rule-conflict arbitration → sufficiency — emitting PASS / ANNOTATE / REFUSE; evaluated only on a 19-case synthetic benchmark ([repo](https://github.com/StevenTsai/grounded-rag)). **EEA rag-facts-check** is more production-shaped: LLM claim extraction with verbatim spans → batched per-claim verification → a **5-stage evidence span matcher** (quote/ellipsis strip, exact, `\s+`-flexible regex, `[\W_]+` boundary, `SequenceMatcher` fuzzy) → 0–10 score with citation and contradiction penalties — **no published accuracy numbers** ([repo](https://github.com/eea/rag-facts-check)). **No published project both builds a verified file:line+verbatim-quote ledger as a separate artifact and lints the final answer against it** — our pipeline appears to have no direct published twin.

### 12. MCP servers and tool hubs

Repository-graph servers (CodeGraph, GitNexus, CodeGraphContext with tree-sitter **or SCIP** backends, Codebase Memory), symbol/LSP servers (Serena, now GPL-3.0-or-later for the app), and packers (Repomix MIT with token budgeting, code2prompt, Aider's repo-map) are surveyed at [rywalker.com](https://rywalker.com/research/code-intelligence-tools). Repomix's MCP exposes `pack_codebase`, `read_repomix_output`, **`grep_repomix_output`** plus sandboxed reads ([repomix.com](https://repomix.com/guide/mcp-server)). CodeGraph's "80% more retrieval context remaining" is **vendor-run over seven repos from its own benchmark doc**, and a larger resident footprint is a cost as much as a benefit ([repo](https://github.com/colbymchenry/codegraph)).

**Free zero-setup primitives.** GitHub `GET /search/code`: **10 req/min, 1,000 results max, files <384 KB, default branch only, query ≤256 chars, ≤5 boolean operators** — and **regex is web-UI only, not in the REST API** ([docs](https://docs.github.com/en/rest/search/search), [discussion #79139](https://github.com/orgs/community/discussions/79139)). `git log -S` finds commits changing the *count* of a literal; `-G` matches diff *lines* by regex ([git-log](https://git-scm.com/docs/git-log)). Evolutionary coupling finds dependencies static analysis cannot see — "modules can be change coupled and have no detectable dependencies in the source code" — but ROSE identified them only **~25% of the time**, with tangled commits a documented false-positive source ([EMSE, DOI 10.1007/s10664-020-09921-9](https://link.springer.com/article/10.1007/s10664-020-09921-9), fetch failed, figures from excerpts — provisional).

## Ranked shortlist: the 8 most worth stealing

1. **Structure-aware deduplication of overlapping hits.** Parse each hit's physical line range and concatenate overlapping/adjacent snippets into contiguous blocks before any model sees them; apply to the top-50% of ranked candidates. It carried **+3.32 of GrepRAG's +3.68 EM gain (~90%)** while BM25 re-ranking carried only +0.51. Pure script work, zero token cost, code public. ([GrepRAG](https://arxiv.org/html/2601.23254v3), [code](https://github.com/ZJU-ACES-ISE/greprag))

2. **Re-anchor before you drop.** Our verifier currently drops failing rows. **~80% of unverifiable citations are mis-citation, not fabrication**, and mini-class line-number errors are dominated by **±1 shifts (12–16% → ~5% with the right prompt layout)**. A ±N re-anchor search on the quoted text, then drop only on genuine no-match, recovers most of the loss for free — CiteFix cut mis-citation 80.6% → 33.3% with string matching alone and no generator re-invocation. ([CiteFix](https://arxiv.org/html/2504.15629v2), [TimeStampEval](https://arxiv.org/html/2511.11594v1))

3. **Cap rows per bucket, and put the source text before the question.** Exact verbatim copying collapses with item count (**63% at 100 items → 7% at 500, zero perfect runs above 100**) and enumeration recall runs 50–80% and falls with list length — so a large bucket silently under-reports rather than failing loudly. Text-first/query-before layout alone buys ~7–11 points of address accuracy, and mechanically shrinking context cut cost-per-correct **~12x**. This is a bucket-sizing law, not a model-choice question. ([arXiv 2601.03640](https://arxiv.org/html/2601.03640v1), [Recall Them All](https://arxiv.org/html/2405.02732v1), [TimeStampEval](https://arxiv.org/html/2511.11594v1))

4. **Reason free-form, emit rows second.** Strict row schemas are the *right* shape for extraction (+11 to +18 points on extraction-style tasks) but folding reasoning into the schema is what destroys quality (Haiku GSM8K 86.5 → 23.4), and the cause is key-ordering, not parsing (0.148% parse errors). Let each reader think in prose, then emit the row block. Sub-4B models keep field-level F1 0.89–0.95 while document-level validity collapses — precisely what our mechanical check catches cheaply. ([arXiv 2408.02442](https://arxiv.org/html/2408.02442v3), [LLMStructBench](https://arxiv.org/html/2602.14743v1))

5. **Add a skeleton tier between the survey and the readers.** Agentless's declaration-headers-and-docstrings level cut input from >3000 to <800 LOC and was **more accurate than full files (58.33 vs 53.67)** at ~$0.02. A tree-format repo skeleton plus per-file signature skeletons is the cheapest way to let the widening step choose buckets without reading bodies. Caveat: signatures *alone* underperform summaries carrying usage and related types, so keep it as a routing tier, not the evidence tier. ([Agentless](https://arxiv.org/html/2407.01489v2), [code](https://github.com/OpenAutoCoder/Agentless), [contrary signal](https://arxiv.org/pdf/2509.25197))

6. **Serialize one warm-up call before the fan-out.** Anthropic's cache is workspace-keyed and shared across sibling calls, but "a cache entry only becomes available after the first response begins" — so a simultaneous N-reader burst pays **N cache writes at 1.25x** instead of N−1 reads at **0.1x**, a ~12x swing on the survey prefix. Batch (50%) stacks with caching. Also budget the ~30% tokenizer inflation on Claude 4.7+ and the 496–588-token tool-use preamble per call. ([prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [pricing](https://platform.claude.com/docs/en/about-claude/pricing))

7. **Adopt query-time spelling expansion as a named, provenance-carrying step — the field's open ground.** Zoekt's trigrams mean `user_id` provably does not find `userId`; ripgrep `-w` cannot span the convention set; Sourcegraph's "find references" is one case-sensitive word-boundary search. Feature-location research answers this by normalizing the **corpus** (split + abbreviation expansion, worth **+52pp MAP over conservative splitting**), and no published agent enumerates variants at **query** time. Our absence rows are only as sound as this enumeration, so it must be a scripted, logged step whose covered-spelling set is printed with every absence claim. ([zoekt](https://github.com/sourcegraph/zoekt/blob/main/doc/design.md), [Binkley ICSM 2012](http://www.cs.loyola.edu/~binkley/papers/icsm-12-concept-location.pdf), [rg#2574](https://github.com/BurntSushi/ripgrep/issues/2574))

8. **Tier the absence row by provenance and bound it by visibility — never by model judgement.** Copy Vulture's construct-derived scale (100% / 90% / 60%) and Rust's scope restriction (a `pub`/exported symbol is never assertably dead from in-repo data), and ship the soundiness disclosure with it: name the constructs that void the claim (reflection, `getattr`, dynamic import, DI containers, string-keyed dispatch, framework-initiated entry points). This is not pedantry — static call graphs miss **61% of dynamically-executed methods** in framework-heavy code, dynamic features appear in **78% of Java projects**, and **reasoning fine-tuning degrades abstention by 24%**, so the model must never be the one deciding "nothing references this". ([Vulture](https://github.com/jendrikseipp/vulture), [rustc](https://doc.rust-lang.org/rustc/lints/listing/warn-by-default.html), [Soundiness](https://yanniss.github.io/Soundiness-CACM.pdf), [arXiv 2407.07804](https://arxiv.org/abs/2407.07804), [AbstentionBench](https://arxiv.org/abs/2506.09038))

**Runners-up worth a look:** a composer guard, since **60–69% of failures happen after reaching the right code** and consensus-of-3 bought +3.0pp ([Coherence Collapse](https://arxiv.org/html/2603.24631v2)); scoring ourselves on **CORE-Bench Level 3's Recall@100** as a blast-radius proxy; and **TraceEval's three-run-identical execution oracle** as the only credible way to build our own "all references" ground truth.

## Rabbit holes left open

**Confirmed gaps in the literature (searched, genuinely absent):**
- **No benchmark evaluates "prove nothing else references this"** — exhaustive reference recall as a first-class task. CORE-Bench L3 Recall@100 and arXiv 2606.11976's "all-gold recall" are the nearest proxies, both patch-derived rather than reference-derived.
- **No peer-reviewed quantification of the string-mediated share of coupling** (SQL in strings, REST route strings, GraphQL fields, queue topics, env vars). Two rounds of searching; circulating percentages are vendor/patent material.
- **No measurement of hallucinated file paths or line numbers specifically** in code agents — the package-hallucination literature covers a different entity type.
- **No published "small extractor + big composer" cascade for code**, and no retry-vs-escalate data for extraction; FrugalGPT is QA routing with a learned scorer, not a deterministic verifier.
- **No ORM-boundary tool for Prisma, Drizzle, SQLAlchemy or ActiveRecord**, and nothing chaining symbol → column → API field → frontend component. The Java JDBC/Hibernate line (SQLInspect) is the only published crossing.
- **No independent measurement of signature-level compression** (Repomix's ~70% is third-party and its own docs publish no figure).
- **No published twin of our full pipeline** — verified ledger as a separate artifact plus a lint of the answer against it.

**Failed or degraded fetches (named, not treated as absence):** *Total Recall?* ISSTA 2024 recall tables (ACM 403 + binary PDF); Sui/Dietrich APLAS 2018 per-tool recall (wrong bitstream retrieved); the Dit/Poshyvanyk FL survey full text (Wiley 403); LiSSA's P/R/F1 (IEEE/ACM paywall); cDep's cross-stack fraction (PDF text layer); the evolutionary-coupling EMSE numbers (Springer redirect — ROSE's ~25% is provisional); DeepRepoQA via OpenReview (verification wall; arXiv HTML succeeded).

**Unverified claims carried in the map:** Cursor's 12.5% accuracy figure has no stated baseline; Cognition's SWE-grep downstream wins are against a private eval; Greptile's 82% bug-catch rate has no fetched primary; Gemini's implicit-cache discount and TTL are undocumented by Google; MASAI's $1.96/issue is snippet-level; the "0.60 → 0.95" normalization figure is unconfirmed and should not be quoted.

**Most valuable unexplored threads:** whether arXiv 2512.12117's **32% auto-cite fallback** is where its 92% actually comes from (it would change how we read the closest twin); the recall-vs-items-per-chunk curve, which would set our bucket cap empirically rather than by guess; whether grammar-constrained decoding eliminates or merely reshapes verbatim transcription corruption; per-KLOC frequency of Python `getattr` dispatch and DI-container wiring, missing from every frequency study we found; and the ALEXANDRIA code-change impact dataset (arXiv 2512.19481), whose numbers and download URL were never confirmed.
