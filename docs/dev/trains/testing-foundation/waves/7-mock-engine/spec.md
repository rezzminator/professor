# Wave 7 — mock-engine for every commit; a weaker real model for the release rehearsal

## mock-engine (Tier A, no model, no credential)

One scripted stand-in binary, `pfm/internal/mockengine` + `cmd/mock-engine` (built only for tests), that speaks what pfm needs from an engine: Claude Code's TUI pane shapes, hook invocations (UserPromptSubmit/Stop/PreToolUse with real JSON), statusline input, transcript JSONL writes, `/exit` and resume; Codex's rollout files, appendix hook and MCP-over-HTTP client calls; OpenCode's session store and MCP client. Behaviour comes from a script file per scenario (turns, delays on the fake clock, tool calls, a busy period, a background sub-agent, a menu left open, a crash). It replaces the three ad-hoc fakes in `pfm/e2e` (`fakeEngine`, `newFakeCodex`, `writeFakeHarnessClaude`) — one implementation, selected as `claude`/`codex`/`opencode` by argv[0], never a fourth engine in pfm's own engine list. Every Tier B lane beat that does not need a real model's judgement gets a Tier A twin on mock-engine, so the sequence's pfm-side logic is gated on every commit.

Staleness guard: mock-engine's protocol shapes are pinned by golden files captured from the real engines by the Tier B lanes (`lanes/capture-shapes.sh` writes them); a lane run whose real capture differs from the golden is a red row naming the drifted shape — the mock can never silently imitate an engine that no longer exists.

## Release rehearsal on a weaker model (Tier B, real)

The update rehearsal — express in the fence, the adopter chat shown which template files changed (`pfm update check`'s report) and asked to re-adapt them — runs on a non-frontier model on purpose: Codex with the Terra model at high effort by default (`run.sh --rehearsal-engine cx --rehearsal-model <id> --rehearsal-effort high`; the id lives in `lanes/budgets.yml`, never hard-coded). If a less instruction-following model still ends at `pfm update check` clean with express's own suite green, the adopter instructions are good; a frontier model passing proves much less. Pass = asserted end state + clean activity log (Wave 6), never the model's own claim.

Scenario schema (`MOCK_ENGINE_SCENARIO=<file>.json`; `<file>.cursor` carries the step position across processes):

1. `version` — the `--version` line (defaults: `2.1.270 (Claude Code)`, `codex-cli 0.154.0`, `1.14.30`).
2. `session_id` — Claude sid / Codex thread id / OpenCode session id; `--session-id`, `--resume`, `resume <id>`, `--session` override; empty → UUID.
3. `model`, `reply` (default `ok`), `busy_ms` (default 200), `tokens{input,output,cache_read,cache_creation,context_window}` — the defaults every step falls back to.
4. `steps[]` — consumed in order; a prompt runs steps until a terminal one (`turn`, `menu`, `crash`, `exit`); `hold`, `tool_call`, `background_agent`, `compact`, `mcp` happen inside that turn; an exhausted list is a default turn.
5. `turn{reply,busy_ms,tokens,structured}` · `hold{until_gone}` · `tool_call{tool,input}` · `background_agent{name,status}` · `menu{options[],selected}` · `compact{post_tokens}` · `crash{exit_code}` · `exit{exit_code}` · `mcp{server}`.
6. `pane{busy,compacted,composer}` — Codex/OpenCode pane strings; absent → `ExitUnpinned` (3) naming them.
7. `jail{proc_root,sid_dir}` — the seat bindings a jail cannot derive (proc entry, sid crumb).
8. `record_dir` — the mock's own telemetry (`argv`, `prompts`, `mcp-<server>.json`); evidence, never the judge.
9. Typed slash commands are built in: `/exit` (dialog only over background work), `/compact`, `/rename <name>`, `/clear` (Claude).
10. `MOCK_ENGINE_ENGINE` picks the engine when argv[0] is not one (the launcher execs `versions/<v>` by path).

Doors pinned by a pfm reader and exercised by a test through that reader: `inject.IsBusy` / `SelectorLine` / `CompactionReceipt` (pane); `transcript.ReadMeta` + `transcript.Parse` + `index.SyncClaude` → `store.Transcripts` (Claude JSONL: `type`, `cwd`, `timestamp`, `sessionId`, `message{role,model,content,usage}`, `isSidechain`, `isMeta`, `isCompactSummary`, `custom-title`, `compact_boundary`); `hookentry.ExploreDeny` / `ReloadIntercept` / `ExitIntercept` / `ExitClose` over the recorded hook payloads; `statusline.Render` over the statusline stdin; `headless/run.Run` over the `-p --output-format json` envelope (`result`, `structured_output`, `usage`, `modelUsage`, `total_cost_usd`, `is_error` — run.go:677-683); `codexmeta.ReadHeader` + `index.SyncCodex` → `store.Rollouts` / `CxNames` + `codexmeta.DecodeSessionIndexLine` (rollout + session_index); `codexappendix.Run` over the hooks.json payload AND over the rollout the mock wrote (developer message found; `compacted.replacement_history` read); `mcpserv` HTTP handler answering the mock's `initialize` + `tools/list`; `index.ReadOpenCodeSessions` over the sqlite store; `gather.RealProcFS` + `reload.SessionFromCrumb` over the jail bindings.

Refused by name (`ExitUnpinned`): Codex pane text (`pane.busy`, `pane.compacted` — `testdata/shapes/codex/{busy,compacted}.txt` are UNPINNED markers); OpenCode pane text (`pane.busy`, `pane.compacted`, `pane.composer`) and OpenCode MCP wiring; `codex exec --json` (run.go:773 reads it; not scripted here); `codex app-server` / `mcp-server` JSON-RPC (statusline/refresh_codex.go:87 reads `rateLimits`; not scripted here); Claude `mcp` step (no pfm reader consumes Claude's handshake). Named gaps that are not refusals: the cwd→`projects/<dir>` slug follows `cmd/pfm/chat_satellite_command.go:664` (`/`→`-`, `.`→`-`) while `index/incremental.go:32` replaces only `/`; OpenCode's store ignores `XDG_DATA_HOME` as pfm's reader does; the ANTHROPIC_BASE_URL sink body the doctor's harness capture reads is not spoken.
