# pfm testing manual

Fixed headings, fixed order. Detail lives in `pfm/CLAUDE.md` § Testing Rules, `pfm/TESTPLAN.md` and `docs/dev/testing/`; this file states what a change owes. How to write a test is the `testing` rule's (`~/.claude/rules/testing.md`); this manual holds pfm's facts and how its tests run.

## Tiers

- Unit: a package test beside its package, no real tmux server, no real engine process, no network: it injects its resolver and HTTP client. Plain `go test ./...` in `pfm/` is this tier: it compiles no `*_jail_test.go` and re-runs in the fence as a jail binary does until `unitNetArmed` (`pfm/internal/testjail/unitnet.go`) is on; once on, it runs in place on any machine inside testjail's unit net (`HOME`, `XDG_*`, `TMUX_TMPDIR` and `PATH` point at empty directories, `TMPDIR` at the binary's own `u{N}` directory, the inherited seat variables emptied).
- Jail: every `*_jail_test.go` starts with `//go:build jail` (arch-check C34 `jail-tag`); `go test -tags jail` adds this tier. A jail, e2e or journey binary runs only in the fence or on a GitHub-hosted runner and re-runs its package in the fence from anywhere else (`pfm/internal/testjail/fence.go`).
- `JAIL`, `JAIL+tmux`, `JAIL+sh`, `LIVE-READ`, `UNPLAYED`: `pfm/TESTPLAN.md` § Legend. The boundary that decides: whether the test needs a real tmux server (a scratch socket inside the jail's `TMUX_TMPDIR`); a flow the fake engine cannot play is `UNPLAYED`, named in `TESTPLAN.md` § "Flows the fake engine does not yet play".
- e2e: the tagged suite under `pfm/e2e/` (build tag `e2e`, `PFM_DEV_FENCE=1`), run only inside the fence.
- Journey, the live tier: the tagged suite under `pfm/journey/` (build tag `journey`), one tree of owner steps (`pfm/journey/tree_test.go`, a `step_{name}_test.go` file per step) typed through a real terminal on a disposable machine; design `docs/design/integration-suite/journey-tree.md`.
- CI: `.github/workflows/ci.yml` runs on a pull request into `main` and by hand on any branch (`gh workflow run ci.yml --ref {branch} -f exclude='{jobs}'`). Its Linux jobs `gate ({unit|e2e|race|mirrors|rest})` run the fence gate's own step list (`infra/fence/checks.sh` `gate_run`) natively on ubuntu-latest through `dev.sh gate all`, each a slice by `PFM_GATE_ONLY` / `PFM_GATE_SKIP` (extended regexes matched against whole step names); `PFM_GATE_ONLY='pfm\.unit' .claude/scripts/dev.sh iso gate` runs that slice in the fence. `macos ({unit|e2e})` (macos-15, `.github/actions/macos-suite/`: `go -C pfm test ./...` and `go -C pfm test -tags jail ./...`, then the tagged `pfm/e2e/` suite with the Darwin installer and release-upgrade e2e) and `fresh-install ({ubuntu-latest|macos-15})` (`scripts/fresh-install-test.sh`, system Bash 3.2 on macOS) run what the fence cannot; `journey ({linux|macos})` runs the whole journey tree, on Linux through `infra/fence/journey/run.sh`, on macos-15 as the runner's owner after `infra/fence/journey/prepare.sh`, each uploading the run's profile and evidence as `journey-{os}`, green or red, the Linux job its coverage too (raw counters included); the macOS job measures no coverage, its clock too coarse for Go's coverage meta-file names; `-f exclude='gate journey fresh-install build scan release'` runs the `macos` jobs alone. Nothing local proves a macOS job.

## Where a test lives

- `<file>_test.go` beside the source file, same package; end-to-end jail tests under `pfm/cmd/pfm/`.
- A single-implementation rule (naming precedence, the kill ratchet, row classification, run-string synthesis) gets a table-driven test; an emitted shell line gets a golden file.
- The plugin lab's hermetic self-tests live in `infra/plugin-lab/tests/` (fence step `templates.plugin-lab`); its live, metered runs of a plugin checkout run on the host through `infra/plugin-lab/lab run`: `docs/dev/testing/plugin-lab.md`.

## Suite duties

- A new or changed owner-visible command or flow lands in one commit with the journey step that walks it, watched red: a `pfm/journey/step_{name}_test.go` hung in the tree `pfm/journey/tree_test.go`; a removed one takes its step with it.
- CI's `journey ({linux|macos})` jobs run the whole tree on every pull request into `main`; while fixing, the touched branch alone: `bash infra/fence/journey/run.sh -run 'Journey/{path}$'`.
- An escaped bug's fix lands with its assertion on the step or test that walked past it, watched red on the unfixed code, the step's comment naming the escape (`escape {area}/{entry}`).
- Shared-core files with one editor per flight: `pfm/journey/tree_test.go`, `pfm/journey/harness/`, `pfm/journey/doors_test.go`, `pfm/journey/doors_cells_test.go`, `pfm/scripts/known-skips.tsv`.
- The most coverage with the fewest steps: a new check is an assertion in the step that already walks the path.
- A step needing only its parent's state hangs beside its siblings, never at a chain's end.
- The whole tree stays at 90 s or under on its profile's `wall` line, herdr-mesh at 40 s or under; the runner fails a run only past `budget` (`pfm/journey/journey_test.go`).
- A step reads machine-wide state (schedules, the picker's rows, the chats list) only through an id it created: every branch of the day shares one machine.
- A picker step moves to its row and reads it as the owner does (`newChatSelected`, `rowIs`), never assuming the cursor: a chat whose schedule fired unseen is pinned above "New chat" with the cursor on it.
- Every chat function is played through both doors, `pfm chat {verb}` and the chat MCP tool, from inside a live Claude chat by the cells in `pfm/journey/doors_cells_test.go`; a new chat verb or MCP tool lands with its cells.

## Mock boundary

- A fake does what the real engine does at every seam pfm listens on; an assertion of absence stands only beside proof the fake can produce the presence. The fake Claude fires SessionStart matched on its source (`startup|resume|clear`); the fake Claude and Codex run SessionEnd hooks to completion on a hangup; the fake Codex fires only the `hooks.json` handlers its `config.toml` `hooks.state` trusts; the fake OpenCode loads pfm's staged Herdr plugin from `OPENCODE_CONFIG_CONTENT` and reports `start`, `working`, `title`, `idle` and `end` through `pfm internal herdr-state`.
- Always real in a `*_jail_test.go`, e2e or journey test: the filesystem under the jail, tmux on a scratch socket, and in e2e and journey SQLite; a unit or jail test's SQLite runs in memory per `.claude/rules/pfm-unit-test-isolation.md` (a fresh store `store.OpenMemory`, the shared half alone `fleetdb.OpenSharedStateMemory`: same migrations, no file), and a unit test fakes tmux per that rule. Never real in a test: a live `cc-*` / `cx-*` socket, the real `/tmp/cc-sid`, a provider account. Engine processes are played by `internal/mockengine`; the process table and the kernel behind the kill door by `internal/gather/gathertest` (a `ProcFS` holding owners, start times and executables, a `Kernel` recording every signal sent, `gathertest.Door` wiring both).

## Environments and cleanup

- Every test runs under `internal/testjail` (`testjail.Run` in `TestMain`; `ShortRoot`, `Fleet`, `InstalledHome`, `CleanHome` build the homes). The `PFM_*` overrides in `pfm/internal/paths/` are the only knobs; `TMUX_TMPDIR = t.TempDir()`. `testjail.Run` clears the operator's `PFM_INSTALL_MARK` and each jail sets its own home's mark, so a jailed child never carries the operator's install. `C25-testmain-jail` fails a test package whose `TestMain` does not reach `testjail.Run`; with `PFM_TEST_ARTIFACT_DIR` set (the gate sets `$run/profile`) every package process leaves `summary.json`, and a red or timed-out one a `DIAGNOSIS.txt` bundle: `docs/dev/testing/profiling.md`.
- Code flights build inside the fence through `.claude/scripts/dev.sh iso`. The host's `~/.local/bin` and the real `$HOME` are never test targets.
- A shared fence call's scratch is RAM, capped and never swapped: `/dev/shm` (`PFM_FENCE_SHM_MIB`, mode 1777) always, and `/root` (`PFM_FENCE_HOME_MIB`, private, mode 0700), `/tmp` (`PFM_FENCE_TMP_MIB`), `/var/tmp` (`PFM_FENCE_VARTMP_MIB`) once admitted, sizes defaulted in `fence_config_init` — free cgroup memory (`memory.max` minus `memory.current` under `$PFM_FENCE_CGROUP_ROOT`, default `/sys/fs/cgroup`) must cover every tmpfs cap plus `PFM_FENCE_HEADROOM_MIB` headroom; every mount `noswap`, a kernel lacking it failing the call; they count against the container's memory cap (`PFM_FENCE_MEM`). Short or unreadable memory binds those three onto disk under the call's run directory and prints one `shared-run: disk scratch:` line with free and needed MiB (`cgroup read failed`, free unknown, when unreadable). The Go build, module and lint caches under `/cache` stay on disk. A test needing real device semantics writes under `$PFM_FENCE_DISK_DIR` (`/pfm-disk`): disk-backed, private to the call, removed at its exit; `fsync` and durability tests stay enabled.
- Live traffic (a real page, the harvester's browser rung, a walled or lazy-loaded site) runs in the real-simulation fence: `.claude/scripts/dev.sh iso sim '<command>'` — Google Chrome (headless only, no display) and `pfm` plus the standalone `harvester` installed from their source checkouts with the browser rung on; the harvester state persists per worktree. Its first line is `sim: chrome=… browser-rung=on` or `sim: BOOTSTRAP-FAILED — <step>`. A live check proves behavior; the regression test is still a fixture-driven unit test.

## Run commands

- Plain `go test ./...` of pfm, the unit tier, re-runs in the fence until `unitNetArmed` (`pfm/internal/testjail/unitnet.go`) is on, then runs in place on any machine inside the unit net; every other test, dependency installs (`npm ci`) and formatters run only in the fence, through `.claude/scripts/test.sh` or `.claude/scripts/dev.sh iso`, against the tree holding the change (the main checkout or its `.worktrees/{flight}/` worktree), never on the host; CI is never a debug loop: every CI suite the fence can run passes here first, and only the macOS jobs (§ Tiers) are proved in CI alone.
- The full gate runs once per change: on a flight once per worktree, right before its merge, by the lander; on small work by the main chat, before the commit; development runs only the tests the change affects. A suite green on a tree never reruns on that tree. A red gate is fixed with `.claude/scripts/test.sh <failing paths>` until green, then the full gate runs once more.
- A change is verified by one `.claude/scripts/test.sh` call over every file it touched, once, at the end of the work, before the commit — the foremen's whole test duty; a red is fixed, only the red test or check runs again until green, then the whole call once more.
- Affected, the only way to run a test: `.claude/scripts/test.sh <path>[::<selector>]...` — `pfm/` and every other path in one call, in the fence. Each path brings its affected tests (a `_test.go` file its package under `-tags jail`, `pfm/e2e/` under `-tags e2e`, `-run` the `::selector`, else every Test and Fuzz func of the file; any other `.go` file its whole package; a shell, node or python test file itself, a source file its same-named test: the map is the script's header), then the static checks of exactly the named paths: for `pfm/` paths `fmt` on the named `.go` files, `typecheck` (`go vet`, untagged then `-tags jail`, of the named `.go` files' packages and every module package importing one, the whole module when no `.go` file is named), `lint-new` on those packages (a finding on another file is burn-down, never its red, except a typecheck finding), `arch` (size ceilings, 240 source lines and 400 for a front door, every `x.go` has its `x_test.go`, every package's front-door menu naming its files), `launch-literals`; for every path rumdl on the named `.md` files and the leak scan on the named files; for the other paths the clone ratchet, placeholders, scratch paths, output styles, descriptions, codex markers. It prints one `TEST` line per test invocation, a `TEST UNCOVERED` line per named file no test maps to (a named gap, not a failure), and one `CHECK` line per check, then `TESTS`, `STATIC`, `VERDICT PASS|FAIL` and last `log: /tmp/{project}/test/{UTC}-{pid}.log`; exit 0 PASS, 1 FAIL, 2 usage. No setup step comes first: every tool is the fence image's. A runner that exits 0 without proving a test (no test ran, an unlisted skip) is red; timeout 600 s.
- The fence mounts the checkout read-only, so the two routes below write only inside a scratch copy in the fence.
- A plugin's own suite (npm, vitest) has no `test.sh` route: `PFM_FENCE_NET=shared .claude/scripts/dev.sh iso run 'D=$(mktemp -d) && tar -C {plugin dir} --exclude=node_modules -cf - . | tar -C "$D" -xf - && cd "$D" && npm ci --no-audit --no-fund && npm test'`, through the `dev.sh` of the checkout holding the plugin, `{plugin dir}` relative to its root (`plugins/{plugin}` or `plugins/{plugin}/.worktrees/{flight}`).
- Formatting (`make -C pfm fmt`, `gofmt -w`, `golangci-lint fmt`) lands as a patch: `mkdir -p /tmp/{project}/fmt && .claude/scripts/dev.sh iso run 'D=$(mktemp -d) && cp -a pfm "$D/a" && cp -a pfm "$D/b" && make -C "$D/b" fmt >&2 && cd "$D" && { diff -ruN a b || [ $? = 1 ]; }' > /tmp/{project}/fmt/pfm.patch`, then on the host `patch -p1 -d pfm < /tmp/{project}/fmt/pfm.patch`; a patch with no `@@` line has nothing to apply.
- The test scripts' own suites: `scripts/test-test.sh` tests `.claude/scripts/test.sh`, `scripts/test-unit-path.sh` tests `.claude/scripts/unit-path.sh`; each is the templates-gate step `templates.{test|unit-path}-tests`, which CI's `gate (rest)` slice runs; a change to either script runs its suite through `test.sh`.
- Full: `.claude/scripts/test.sh --full` (`dev.sh iso gate`) — pfm, templates, e2e and the fence self-tests (`infra/fence/tests/`) as concurrent steps in one run, a `step · verdict · seconds` table in the run's `gate.tsv` (verdicts PASS, FAIL, NOT-RUN, TIMEOUT; rows `STEPS` and `BUDGET`), a `PROFILE` block pointing at each red step's diagnosis in the run dir, the run dir itself named by the output's last line `RUN DIR: <absolute host path>` (read it there, never the newest `run.*`), the wall judged against `infra/fence/gate-budget.yml`; one run closes the pfm and templates gates both; timeout 600 s, background past that.
- Fresh-machine install: `.claude/scripts/dev.sh iso run 'bash scripts/fresh-install-test.sh'` runs the CI script in the fence on Linux: it snapshots the working tree into a scratch repository tagged as `VERSION` names, runs every `INSTALL.md` bash block marked `<!-- fresh-install` as written in a fresh HOME (only `https://github.com/${REPO}.git` swapped for that repository), requires `pfm doctor` to exit 0 or 1 with no FAIL row, then runs the release-upgrade e2e tests (`pfm/e2e/release_upgrade_e2e_test.go`) against the repository's real tags; it ends `fresh-install: PASS` or `fresh-install: FAIL {step}: {cause}`. Tags come from env: `PFM_E2E_PREVIOUS_TAG` (default the newest tag), `PFM_E2E_OLD_TAG` (default the fifth-newest, never older than `e2eOldestUpdatable` in `pfm/e2e/release_upgrade_e2e_test.go`, the oldest release this tree updates from), `PFM_E2E_CURRENT_TAG` (the candidate; default the newest tag's next minor). A change to a marked `INSTALL.md` block or to the install or update path runs it.
- Journey: `bash infra/fence/journey/run.sh [--keep] [-run 'Journey/{path}$']`, from the host, boots its own disposable machine (systemd in a container, no network), runs `pfm/journey` (tag `journey`) in it as the owner and removes the machine; it prints a step timeline (`PASS N · FAIL N · BLOCKED N`), then `journey: profile {path}/summary.md`, and ends `RUN DIR: {path}`, kept on a failure or with `--keep`; a failed step BLOCKS only its descendants. Every run, green or red, copies its artifacts into the checkout's ignored `tmp/journey/{run id}/` (`latest` links the newest, the last ten kept): `steps.tsv`, `waits.tsv`, `summary.md`, `coverage.html`, `coverage-packages.tsv`, `coverage-funcs.txt` (unreached functions first), `coverage.out`, the raw counters in `covdata/`, `timeline.tsv`, each failed step's evidence (every terminal's screen, its log slice, the processes) and the machine's pfm logs in `logs/{user}/`. `prepare.sh` gives every login and service `GOCOVERDIR` and `GOFLAGS="-cover -covermode=atomic -tags=pfmcover"`, so the pfm the install builds is instrumented; after the tree the suite SIGTERMs the owner's pfm processes to flush their counters, about 7-12 s a run; a SIGKILLed pfm writes none, so coverage is a lower bound. The install step runs `pfm theme on --json` after the install, so every Herdr tab label is `{mark} {name}` (`markedLabel`). The suite refuses to run where `testjail.Disposable` is false; `.claude/scripts/test.sh` only vets it under its tag, for Linux and `GOOS=darwin`. With `--ci-linux` and/or `--ci-mac` it runs `journey (linux)` + `gate (e2e)` and/or `journey (macos)` + `macos (unit)` + `macos (e2e)` on GitHub Actions over the checkout as it is on disk, from a temporary branch it deletes on every exit (one that would not go is named with its delete command); it prints the run URL, a line per job, each failed step's log path under `{checkout}/tmp/journey/ci/{run id}/`, exits 0 only when every selected job succeeded, and 2 on a refusal before the run starts; a push, so only on the owner's ask.

## Concurrency

- Fence knobs: every run-shaping default (CPU, memory, cpuset, `GOMAXPROCS`, test and e2e flags, step concurrency, timeouts, budgets) is one row of `fence_config_schema` (`infra/fence/shared.sh`), `name|desktop-default|type|native-default`, `=` inheriting desktop. `fence_config_init` fills every unset name and validates it by type before `dev.sh iso` or the in-fence test, e2e, all and gate paths do any work: a malformed value exits non-zero with `iso: {name} must be {type} (got '{value}')`. Types, every row and the measured native values: `docs/dev/isolated-dev-foundation.md` § Fence knobs.
- Profile: `PFM_FENCE_PROFILE=auto|desktop|native`, default `auto`, which reads `docker info` (`OperatingSystem`, `NCPU`, `MemTotal`, never the hostname). Docker Desktop is `desktop` (6 CPUs, 5g); a native Linux daemon with at least 12 CPUs and 12g is `native` (12 CPUs, 12g, unit `go test -p 6`, `STEPS_JOBS` 6, `STEPS_HEAVY_JOBS` 2), a smaller one `desktop`; a failed or unreadable detection is a named `iso: PFM_FENCE_PROFILE …` error. Each run's `fence:` line names its `profile=`, `cpus=`, `mem=`, `cpuset=` and `GOMAXPROCS=`.
- Per-host config: a knob set in the environment, even to empty, beats the profile. Set it on the `test.sh` or `dev.sh` command line for one run (`PFM_FENCE_PROFILE=desktop .claude/scripts/test.sh …`), or export it in that host's shell profile for every run there. Retuning the native default for every native host is one field of its schema row (`PFM_FENCE_CPUS|6|cpu|12` → `PFM_FENCE_CPUS|6|cpu|8`), desktop unchanged.
- Caps: the CPU, memory and cpuset caps are the one shared container's and change only under the host admission lock while no other run is live. A caller whose caps differ from a live run's changes nothing, prints `CAPS CONFLICT` and runs under the effective caps, so concurrent runs never fight over them; the gate ledger records the effective caps, never the requested.
- Package and test concurrency is set by `TESTFLAGS` in `pfm/Makefile`, `-parallel` from `PFM_FENCE_TEST_PARALLEL` and `-p` following the fence's CPU cap (`PFM_FENCE_TEST_P`, else the container's cgroup quota; `make -s -C pfm testflags` prints it; the pick: `docs/dev/testing/concurrency-sweep.md`); callers may override it. The tagged e2e rows take `-p`, `-parallel`, `-count` and `-timeout` from `PFM_FENCE_E2E_P`, `PFM_FENCE_E2E_PARALLEL` (empty: go's default), `PFM_FENCE_TEST_COUNT` and `PFM_FENCE_E2E_TIMEOUT`. A test that mutates process state (`t.Setenv`, `t.Chdir`, or a package variable) stays serial; a jail contained in a subprocess may use `t.Parallel` with `testjail.FleetEnv`.
- No two runs share a writable tree, a database or a fixture directory: each flight works in its own `.worktrees/{flight}/` worktree, the fence mounts it read-only and gives each call its own namespaces, HOME, `/tmp` and scratch copy, and each test gets its own `testjail` temp root, SQLite included.
- Packages pinned in `pfm/scripts/test-shard.sh`'s `SHARDS` table run split by top-level test across concurrent processes of one compiled test binary (`docs/dev/testing/timing.md` § Sharded packages): a test never depends on another top-level test of its package having run in the same process, nor on a fixed port, path or name another process of that package could hold.
- `go test -race` runs in the fence with cgo on for that command alone: `.claude/scripts/dev.sh iso run 'cd pfm && CGO_ENABLED=1 go test -race …'` (the pfm-dev image carries gcc; every other build stays `CGO_ENABLED=0`). The `pfm` and `all` gate targets require `pfm.race`, selecting from `CHECKS_PFM_RACE_TESTS` in `infra/fence/checks.sh`. Each named test requires an exact module-qualified package/test pass event; missing, skipped or unbuilt tests, unreadable source and tool/build/race errors fail the step. A test guarding a race joins its module's list. A `t.Parallel` change is proven by `-count=3` in the fence, under load once, and by `-race` over its package. A test whose ceiling the race detector breaks (`testing.AllocsPerRun`) skips on its package's `raceEnabled` constant (`//go:build race`) with a `race-mode` known-skips row.
- A top-level e2e test calls `t.Parallel` unless a comment names the shared resource that keeps it serial.

## Gates and floors

- Coverage `pfm/.testcoverage.yml`: total 77, package 52, in the fence: `.claude/scripts/dev.sh iso cover pfm`; the full gate does not run it.
- Unit isolation: `bash pfm/scripts/test-kinds.sh [--list]` classes every Test and Fuzz func outside `pfm/journey/`, `pfm/e2e/` and `testdata/` by the worst thing its body or a test-file function of its directory it names touches (`nothing`, `temp-dir`; `real`, a test in a `_jail_test.go` file, kept until a fake or the journey can play it, its file's count ratcheted by arch-check C33 with the per-directory move counts; to move: `home-sqlite`, `process`, `tmux`) and prints `KINDS unit {n} (…) · real {n} · move {n} (…) · total {n}`, `--list` a `{kind}\t{dir}\t{file}\t{func}` row per test, `KINDS ERROR {why}` and exit 2 when it cannot look; the `pfm` and `all` gate targets print that line after the `PROFILE` block, `PROFILE kinds NOT RECORDED` when it fails, the verdict unchanged. `bash pfm/scripts/test-coverdiff.sh {journey coverage.out} {out dir} [pfm dir]`, in the fence (`dev.sh iso run`), runs each directory's unit and move tests apart and writes per package the statements only the move tests hold, neither the journey nor a unit test (`report.tsv`, `move-only.txt`, `runs.tsv`), ending `COVERDIFF …`; exit 1 on a red or unrecorded run, a killed job named `killed` in runs.tsv, 2 on `COVERDIFF ERROR` (a reused out-dir included); nothing the fence writes outlives the call, so read the outputs in that same call. Kinds reads test text only, an estimate both ways (a production call reaching a real dependency unseen, a same-named method on another receiver counted); coverdiff collects no child-process coverage, so its move-only list is a lower bound.
- Wall-time budget per suite and per package: `pfm/.testtiming.yml`, per gate target `infra/fence/gate-budget.yml`, derived and judged per `docs/dev/testing/timing.md`; an unbudgeted package fails. A suite over budget has its slowest tests measured (its timing TSV, the gate's `gate.tsv`) before any test joins it.
- Every skip is a row in `pfm/scripts/known-skips.tsv` (`pfm/scripts/skip-check.sh`); an unlisted skip fails.
- `iso gate` runs under `infra/fence/egress.sh` inside its run's own network namespace, so its verdict covers that run alone: `EGRESS PASS`, or red as `EGRESS FAIL` (each DNS name and destination listed) or NOT RECORDED; that verdict is the only network check.
- Every gate run is appended to the host ledger `$HOME/.local/state/pfm/gate-history/<project>/ledger.tsv`, and the count of runs live in the shared fence container when it started (`concurrent_runs`) to `concurrent.tsv` beside it, and its effective caps (`profile`, `cpus`, `mem`, `cpuset`, `gomaxprocs`) to `caps.tsv` beside it; `bash infra/fence/gate-history.sh report` shows per-step medians, regressions and verdict flips.

## Tricks and traps

- A long `TMUX_TMPDIR` fails with "File name too long" and reads as a tmux bug: keep scratch socket paths short (`testjail.ShortRoot`).
- A tool the fence image lacks makes `test.sh` print `CHECK FAIL image (the fence image lacks: …)` and run no check, exit 1: the fix is `infra/fence/pfm-dev.Dockerfile`, never a host install. A fresh worktree lacks the engine mirrors, and `iso gate`'s `templates.mirrors` needs none: the step copies the tree under test (tracked and unignored files, no submodule checkout) into `$TMP_BASE/engine-sync/mirror-tree`, builds the mirrors there with the engine-sync built from its mounted source, under a scratch home whose `.claude/engine-sync.json` is the tree's `templates/global/engine-sync.json`, and every mirror gate reads that copy — so a rename, a stale host build or the host's installed engine-sync policy never turns it red; the worktree's own `AGENTS.md`, `.codex/**` and `.opencode/**` are for the host's tools, not the gate.
- The fence mounts the worktree read-only: `PFM_UPDATE_GOLDENS=1` regenerates in a writable scratch copy through `dev.sh iso run`; diff the result against the tracked golden, then apply it on the host.
- `codex` is a shell function on a developer host: a test or script calls `command codex`.
- A probe that launches an engine closes stdin (`</dev/null`) or it hangs.
- The e2e harness refuses to run without `PFM_DEV_FENCE=1`: that red on a host is the fence law, not a defect; suites and provisioning scripts gate on `scripts/platform.sh` `platform_in_fence` (the variable AND `/.dockerenv`), never the variable alone.
- `internal/hookentry` (socket path length) is red on a macOS host and green in the fence.
- A shell poll counts its bound in 0.1 s ticks or from `$EPOCHREALTIME`, never whole `date +%s` seconds (a 1 s bound then waits up to 2 s); a fixed grace is a parameter a self-test can shorten.
- A closed listener keeps accepting while a parallel test's fork holds its fd until exec: a test expecting a refused dial on a closed port stays serial.
- A closed `gather.AcquireAccountGuard` keeps its flock while a parallel test's fork holds the open file description until exec: `AcquireAccountGuard(dir, false)` retries a busy lock for `accountBusyGrace` before it refuses, and a test that expects the busy refusal calls `acquireAccountGuardWithin(dir, false, 0)` (in `gather`) or holds the guard for longer than the grace.
- A file a test writes then runs goes through `testjail.WriteExecutable` (`C26-exec-write` fails a bare exec-mode `os.WriteFile`: a parallel test's fork mid-write makes it ETXTBSY), and in `internal/deps` and `internal/config`, which testjail imports, through their local `writeExecutableUnderForkLock`; a file the code under test only resolves, stats or hashes, and nothing runs, through `testjail.WriteExecutableNeverRun` (test-kinds: temp-dir), never a plain write plus an exec-bit `os.Chmod` or a link to the test executable; a scripted engine child plays its output through `deps.FakeRunner.ScriptStartOutput` (`deps.StartOutput`: stdout, stderr, exit code, an `AtStart` hook).
- engine-sync in a unit test plays through `testjail.FakeEngineSyncRunner`, an in-process `deps.Runner` answering as `testjail.FakeEngineSync` and writing its record files, handed in at the package's runner seam (`installer.Options.EngineSyncRunner`, `action.Dependencies.EngineSyncRunner`, `reload.Options.EngineSyncRunner`, the runner argument of `workbench.EnsureMirror`/`workbench.CheckMirror` and `action.PersonaMirror`, `hookentry.CodexLaunchWith`; nil = the real process runner); its binary is written through `WriteExecutableNeverRun` and exits 97 if run past the runner; `testjail.FakeEngineSync`, which really runs the stand-in, is for jail tests only. codexappendix's app-server child starts through `appServerRunner(ctx)` (`codexappendix.go`): the runner `codexappendix.WithAppServerRunner(ctx, runner)` put on the context (the installer hands its `Options.ProcessRunner` through it), else the package's `processRunner` (codexappendix's own tests set it), else the real process runner; a fake is scripted with `deps.FakeRunner.ScriptInteractive([]string{codexBinary, "app-server"}, …)`.
- A unit test scripts every other child at its package's seam: git through `fakegit.Runner` (`pfm/internal/testjail/fakegit`, its fixture verbs through `Must`), the professor store's git through `professor.StubStoreRunnerForTest`; a call answered at call time (a hang until the deadline, state across calls) through `deps.FakeRunner.Handle`; tmux client calls through `tmux.WithClientRunner`, the `herdr agent attach` child through `herdr.WithAttachRunner`; the package runners `stats.ackRunner`, `usagehook.usageRunner`, `reap.ClaudeAgents.Runner`, `agentopen.ExecCommands.Runner`; hookentry's `GitGuardWith`, `EngineGuardWith`, `LaunchWith`, `SeatHostWith`, `CodexLaunchWith`; cmd/pfm's `commandRunner` (`scriptManagers` scripts systemctl and launchctl behind it); the installer's `installer.NewCommandRunner`.
- `PFM_TEST_PROFILE=cpu` kills a test's exec'd children (SIGPROF survives execve): never in a gate.
- A test binary started by a profiled test inherits `PFM_TEST_PROFILE_PARENT` and is a helper (summary only); a test that re-execs its own binary to prove profiling removes it from the child's env.
- A test that reads process-wide allocation or heap counters (`testing.AllocsPerRun`, `runtime.ReadMemStats`) is serial and calls `testjail.PauseFlightRecorder(t)` first: the always-on flight recorder allocates in its own goroutine.

## What not to test

- A model's words: a step asserts from pfm's own report or the pane.
- A value one run printed about its data (a count, an id).
- That an event did not happen (a network call, a DNS query, a sleep, a fork): the egress verdict and the fenced measurements prove those, never a test.
