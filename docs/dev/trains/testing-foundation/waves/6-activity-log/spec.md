# Wave 6 — the activity log: one structured log at every corner, per environment

**Why:** the engine has ~50 log calls, no central destination, no level switch, and only scattered one-off files (the reload worker's `reload-*.log`, a few installer probes). A failed lane step, a field report, or an alpha tester's bug cannot be diagnosed from what pfm writes today. **Law (the user's):** a lane step passes only on its asserted result AND a clean activity log.

## Framework

Go's standard `log/slog` — levels, structured fields, handlers per environment, no new dependency. One package, `pfm/internal/obs` (name checked against the tree before creation): `obs.Logger(ctx)` returns the process logger; `obs.With(ctx, "chat", id, "seat", n)` scopes it; `obs.Span(ctx, "reload.waitIdle")` logs entry, exit, duration and error of a unit of work.

## Destinations and environments

- One JSON-lines file per pfm home: `<home>/.local/state/pfm/log/pfm.jsonl`, exposed as `paths.Values.LogFile` — so the fence, a test jail, a lane container and the live host each write their own file and can never mix (the environment separation IS the home jail; no second mechanism).
- Size-capped rotation written in-tree (keep N files of M MB; both in `pfm.config.json`), so no rotation library is added.
- Time-based retention (part B): `log.keepDays`, default `30`; at open and at every rotation, a rotated file whose newest record is older than `keepDays` is deleted. It works beside `log.keepFiles`/`log.maxMB` — whichever limit is reached first wins; `0` disables the time limit. The live file is never deleted, only rotated. The JSONL file stays the single write path: a database is never the log's destination (a log must outlive the store it reports on); a queryable index, if ever built, is a separate rebuildable `log.db`, never `fleet.db`, and is its own spec.
- Four levels, all used, one meaning each (part B assigns one to every migrated call): `ERROR` — the verb or operation failed; `WARN` — it succeeded but something was off (a retry, a fallback, a stale link, a degraded answer); `INFO` — one line per meaningful action (a verb ran, a chat was reloaded, a link was written); `DEBUG` — everything needed to reconstruct the action (every middleware record below, every state transition). `warning` is accepted as an alias of `warn` wherever a level is read; `off` is a fifth accepted value that records nothing.
- Level by build and by switch: a `-alpha` `VERSION` defaults to `debug`, a release build to `info`; `PFM_LOG_LEVEL` and `pfm.config.json` `log.level` override; `PFM_LOG=stderr` mirrors to stderr for a foreground run. Tier U tests get a buffer handler from `obs.Test(t)` and assert on records.
- Every record carries: `ts`, `level`, `msg`, `cmd` (the pfm verb), `pid`, `version`, and where known `chat`, `seat`, `engine`, `sock`, `dur_ms`, `err`. Never a credential, a token, a prompt body, or a transcript line — a redaction test pins that.

## Coverage — every corner

Each `cmd/pfm` verb (entry, args shape, exit code, duration); every hook entry (`hookentry`: which hook, decision, reason); the MCP daemon (tool, target, result shape, duration); every tmux façade call (argv, exit, duration — at `debug`); every `deps.Runner` call (same); installer steps (each write/link/prune with its ledger row); reload/inject/self-compact state machines (each transition); reap/heal/kill decisions (what and why); usage hook fetches (seat, status, cache age); updatecheck. Existing `log.Printf` calls move onto it — one logging path, never two. The seams from Wave 3 are the choke points: `deps.RealRunner`, the tmux façade and `clock` make most of this one wrapper each, not 300 call sites.

## Middleware — every door that can take one takes the logger (part B)

Wherever pfm owns a choke point that every call of one kind passes through, a logging middleware wraps it once; call sites are not touched. Each record carries `comp` (the component name below), the operation, its scrubbed arguments' shape, the result's shape, `dur_ms` and `err`. At `DEBUG` the middleware dumps the full scrubbed arguments and result, each field capped (2 KB, a `…(truncated N bytes)` marker); at `INFO` one line per call; failures at `ERROR` whatever the component's level. The redaction law above is not relaxed by `DEBUG`: credentials, tokens, authorization headers, prompt bodies and transcript lines never reach the file — `Scrub` runs inside the handler, so no middleware can bypass it.

The doors, by `comp` — this list is tracer-mapped closed-world BEFORE the build dispatch (root `CLAUDE.md` § Subagent dispatch, map before dispatch); the map's additions are written into this list, and a door found without a wrapper after the build is a defect:

- `cli` — the `cmd/pfm` dispatcher: verb, argument shape, exit code, duration (`cmd.start`/`cmd.end` exist from part A; part B adds the rest). One named gap: a bad global config fails before the log opens — that failure stays on stderr and never reaches the file.
- `mcp` — both MCP servers (the chat server and `harvestmcp`), one tool-registration middleware per server shared by stdio and HTTP: tool, target, argument shape, result shape or error, duration. The harvester prompt callback uses the same safe operation wrapper with `kind=prompt`; it is not an unlogged side door.
- `http.in` — three handler chains: chat MCP `mcpserv.NewHTTPHandler`, harvester MCP `harvestmcp.Service.NewHTTPHandler`, and the remote harvester bridge `harvestmcp.RemoteServer.Handler`; method, route, status, bytes, duration.
- `http.out` — one `http.RoundTripper` wrapper on every outbound client: harvest (including SearXNG, DoH, Chrome and the harvester MCP client), usage and limits, `updatecheck`, installer theme fetches, harvestpy provisioning, MCP daemon-status probes and Docker-identity probes. It records method, host, path, status, bytes, duration and retry count — never a query string carrying a key, headers or a body. Injected clients and custom transports keep their existing redirect, proxy, cookie and resolver policy under the wrapper.
- `runner` — `deps.RealRunner` (`Run`, `Start`, `LookPath`): scrubbed argv, exit code, duration; `Start` also logs the pid and, on `Wait`, the exit. Four direct process doors are included until they migrate behind it: the bounded dependency probe, dependency-registry `exec.LookPath`, and the Codex App Server commands in statusline and codexappendix. Nine more are frozen in the C24 baseline (`pfm/.arch/unwrapped-door.txt`) until the same migration: `internal/professor/store.go`, `internal/action/claude_spawn.go`, `internal/installer/update_metadata.go`, `internal/update/run.go`, `internal/doctor/doctor.go`, `internal/doctor/harness_prompt.go`, `internal/doctor/prepush.go`, `internal/picker/update_row.go`, `internal/action/process_darwin.go`.
- `tmux` — every façade terminating at `internal/tmux` (`action`, `agentopen`, `inject`, `kill`, `reap`, `resolve`, `spawn`, hook launch and direct CLI calls), plus gather's direct tmux probes until they migrate behind that façade: subcommand, target, exit, duration. A constructor returning `*exec.Cmd` is not a completion door; the wrapper owns execution or uses `deps.Runner`, so it sees the result exactly once.
- `hooks` — `hookentry`: which hook, decision, reason, duration.
- `db` — the `fleetdb` operator-state layer, transcript `store`, shared `sqlitedb` open/transaction layer and the direct heal/index operations: operation name, database kind, table, rows affected or returned, duration, busy-retries — never SQL text or a bound value.
- `harvestpy` — one-shot conversion/provision/check processes and the long-lived browser sidecar: start, request result, stop/kill, exit code, duration, and each stderr line as a `WARN` record.
- `installer` — `engine.change`/`ok`/`skip`, the existing central ledger doors for every write, link and prune; `installer.Run` records failures before a ledger row exists. Presentation-only `say` is not a second event stream.
- `state` — coordinator transitions in reload and its worker; inject, self-compact and then-delivery; kill, reap and heal; action open/solo/self-switch; nudge and rearm; archive/end flows. Professor's project-update and scaffold operations, fleet scan/reconcile, and the mutating chat end/kill/unkill/name/KillServer/new-registration operations are coordinator doors; their baseline/store, account/data and target/list/open helpers remain leaf writer or read doors. Each transition carries prior state, next state, cause and result, never a prompt, transcript, pane capture or injected body.

**Control — all of it in `pfm.config.json`, all of it overridable per run:** `log.level` sets the default for every component; `log.components.<comp>` sets one component to `debug`/`info`/`warn`/`error`/`off` (for example `"db": "off"`, `"mcp": "debug"`); `log.level: "off"` turns the whole log off and writes no file. `PFM_LOG_LEVEL` overrides `log.level`, and `PFM_LOG_COMPONENTS` (`mcp=debug,db=off`) overrides the per-component map, for one foreground run. An unknown component name or level is an error naming the accepted values and the setting that stays in force — never silently ignored. `pfm doctor` prints the level in force per component and where each came from (build, config, env). `pfm install` writes the safe default visibly: when `pfm.config.json` has no `log` block it writes `"log": {"level": "info", "keepDays": 30}` — so an adopter sees the switch where they would look for it — and it never overwrites a `log` key that exists (an installed choice survives every re-install and update; test: install over a config carrying `"level": "off"` leaves it `off`). `info` records one line per action plus every warning and error; an adopter who wants warnings and errors only sets `warn`. The `-alpha` build default of `debug` applies only when the config carries no level. The lanes set `PFM_LOG_LEVEL=debug` inside their container, so an adopter's `off` can never blind the clean-log law.

## Reading it

`pfm log [--since 10m] [--level warn] [--chat X] [--cmd reload] [--comp mcp] [--follow]` — a filter over the JSONL; `pfm doctor` names the log path and its size. The lanes' `lib.sh` snapshots the file's offset before each beat and, after it, fails the beat on any `error` record not declared expected by that beat (`expect-log <pattern>`), attaching the beat's slice of the log to a red row.

## Proof

Red-first: a test per corner asserting the record exists with its fields (watched failing before the call is added); the redaction test; a level test per environment; `pfm log` filter tests; C22-style ratchet `C23-bare-log` counting `log.Print*`/`fmt.Fprint*(os.Stderr` outside `obs` and `cmd/pfm` user-facing output — baseline measured, only shrinks. Part B adds: a retention test per limit (`keepDays`, `keepFiles`, `maxMB`, and `keepDays: 0`) on a fake clock; one test per middleware door asserting its record and its `comp`, watched failing before the wrapper exists; a per-component level test (`off` writes nothing, `debug` dumps, an `ERROR` passes a component set to `warn`), the `warning` alias, the invalid-value error; a truncation test at the field cap; and the redaction test re-run at `DEBUG` through every middleware with a planted secret in arguments, headers and results; and ratchet `C24-unwrapped-door` — a production census counting `http.Client` construction and `http.DefaultClient` outside the `http.out` wrapper, direct `database/sql` calls outside the `db` access layers, and tmux/`os/exec` call sites outside their doors — baseline measured, only shrinks, so a client added later cannot skip the logger. The committed baseline `pfm/.arch/unwrapped-door.txt` is the census, not this paragraph: 48 doors in 34 files at the wave's close — 9 http, 1 sql, 38 process/tmux; read the file for the exact rows.
