# v0.89.0 — 2026-11-20

A project's pfm settings file is now `pfm.config.json` at the project root, the same name as the machine file: a leftover `pfm.settings.json` is no longer read, so a project that has one launches without its `envs` and `harnessPrompt` until you move them, and eight `claude.*` launch keys of the machine file are retired as no-ops whose values now live in `claude.settings`. Every Claude launch now carries three new defaults, the fleet prompt on a host with a Professor clone, the terminal's own cursor and the fullscreen renderer, each removable with a `null` in `claude.settings`. Sub-agent rows are now drawn by the new in-tree `professor` Claude plugin, on by default, so a machine that sets its own `claude.plugins` list must add it. pfm now sends an anonymous install ping at install and once a day, which `DO_NOT_TRACK=1` or `PFM_INSTALL_PING_OFFLINE=1` turns off, and Herdr users get pfm's key bindings from `herdr.keys` and named spaces through `pfm chat space` and `/pfm:space`.

## Breaking

- pfm: project config file — a project's settings file is `{project}/pfm.config.json`, one file name at two scopes: the machine file `{clone}/pfm.config.json` takes every key, and the tracked project file is read only for `envs`, `harnessPrompt` and `claude.settings`, layered shipped launch defaults < machine file < project file < a `--settings` you type, per key. `pfm.settings.json` is no longer read: a launch in a project that still has one goes on without it and warns, `pfm doctor` warns `pfm.settings.json is no longer read: move its keys into pfm.config.json`, and any other key the project file sets is ignored with a warning. `pfm --config X` now also feeds X's `claude.settings`, `envs` and `harnessPrompt` to the launch.
#### → For: every adopter · per project · pfm.settings.json — where the project root holds a `pfm.settings.json`, move its `envs` and `harnessPrompt` into `{project}/pfm.config.json` (create it, or merge into the one the `NEW` row of `templates/project/pfm.config.json` brings) and delete `pfm.settings.json`; then `pfm doctor` run in the project prints no `pfm.settings.json is no longer read` line.

- pfm: retired launch keys — the machine keys `claude.webSearchesPerSession`, `claude.autoCompactWindow`, `claude.helperModel`, `claude.tmuxTruecolor`, `claude.nativeCursor`, `claude.maxSubagentSpawnDepth`, `claude.maxConcurrentSubagents` and `claude.cleanupPeriodDays` still load but are never read, and `pfm doctor` warns, naming its replacement, for each one whose value would launch differently from the shipped defaults, while a `null` or a value the defaults already carry stays silent, so a machine file seeded by v0.88.1 warns once, for `"nativeCursor": false`; their values ship as launch defaults (`pfm config claude` lists them). A value you set through one of them, `"nativeCursor": false` or `"tmuxTruecolor": false` included, no longer takes effect until you set it in `claude.settings`, where a `null` removes a default. Headless runs no longer strip an inherited `CLAUDE_CODE_NATIVE_CURSOR` or `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`.
#### → For: adopters who set a retired claude key · after update · pfm.config.json claude.* — for each `is retired` line `pfm doctor` prints, write the key's value at the path the line names (`claude.helperModel` → `claude.settings.env.ANTHROPIC_SMALL_FAST_MODEL`, `claude.cleanupPeriodDays` → `claude.settings.cleanupPeriodDays`, `"nativeCursor": false` → `"CLAUDE_CODE_NATIVE_CURSOR": null` under `claude.settings.env`) and delete the old key; a retired key no line names already matches the defaults and is simply deleted; then `pfm doctor` prints no `is retired` line.

## Added

- Project: pfm.config.json — `templates/project/pfm.config.json` is the project's pfm config file with every key empty (`envs` `{}`, `harnessPrompt` `null`, `claude.settings` `{}`), so it overrides nothing until the project sets a key; `pfm init` scaffolds it, and an existing project receives it as a `NEW` row of `pfm doctor --project-updates`. A key the project file sets overrides the machine file's for every chat in that project, so the copy keeps only what the project means to set differently.
#### → For: every adopter · per project · templates/project/pfm.config.json — on the `NEW` row, write `{project}/pfm.config.json` holding only the `envs`, `harnessPrompt` and `claude.settings` entries this project sets apart from the machine file (the template as it ships, every key empty, when none), then `pfm update pin --template pfm.config.json pfm.config.json`; `pfm doctor --project-updates` no longer lists the row.

- pfm: professor plugin rows — each sub-agent's row under the main statusline is drawn by the new `professor` Claude plugin (the in-tree `plugins/professor/`, listed in Professor's marketplace) from one pfm door, `pfm statusline --agents TRANSCRIPT [ID…]`: a context pulse, spend, model and effort, state, tool errors and cache, opening with the count of working and total agents below it (`1/3`, `?/?` when pfm could not list them). pfm's own sub-agent rows are removed. `professor` joins the default `claude.plugins` list, so a machine with `claude.plugins` unset gets it enabled at the update's install; a machine whose `claude.plugins` is set and does not name it draws no sub-agent rows.
#### → For: adopters whose pfm.config.json sets claude.plugins · after update · pfm.config.json claude.plugins — add `"professor"` to the list, run `pfm install --yes`, then `pfm doctor` prints `doctor: claude_plugins ok`; a chat opened afterwards draws the rows.

- pfm: install ping — pfm sends an anonymous install ping (a random id, the pfm version, OS, architecture and the Professor plugins enabled; no IP stored) once at `pfm install` and at most once per UTC day from the statusline worker, to a counter Professor runs; `pfm install` prints whether it is on. It is on by default; `PFM_INSTALL_PING_OFFLINE=1` or `DO_NOT_TRACK=1` turns it off, CI, the fence and development builds never send, and `pfm install --offline` skips only the install ping.
#### → For: adopters who do not want the install ping · before update · shell profile — export `DO_NOT_TRACK=1` (or `PFM_INSTALL_PING_OFFLINE=1`) in your shell profile and open a new shell before running `pfm update`, so the update's install and every chat started from that shell inherit it; `pfm install --yes` then prints `pfm: install ping off (…)`.

- pfm: herdr.keys — `pfm install --yes` writes pfm's Herdr key bindings into Herdr's config, in a `# >>> pfm herdr keys >>>` block that owns the `[keys]` table: `prefix+i` and `prefix+m` switch to the previous and next workspace, and `prefix+a` opens a new tab running the pfm picker in the active workspace. `herdr.keys` in the machine `pfm.config.json`, Herdr's `[keys]` table as JSON, merges over that keymap per action (`null` removes pfm's binding; a `command` entry holding only `key` removes pfm's command of that key) and is refused at load with the exact path of a fault; a hand-written `[keys]` table that differs stays yours, and `pfm doctor`'s `herdr-keys` row warns when the block is missing, out of date or a pfm mapping is absent. A running Herdr applies the keys at `herdr server reload-config` or its next start.
#### → For: Herdr users · after update · Herdr server — run `herdr server reload-config` (or restart Herdr); `pfm doctor` then prints no `herdr-keys: WARN` row.

- pfm: pfm chat space — `pfm chat space NAME` puts the calling chat in a named Herdr space, saved per chat and kept through reload, resume and restore; the picker files the chat under that space, a bare `pfm chat space` returns it to its folder's place, new chats never inherit a space, and a space named `~` is refused. The space is stored in a new state-database table (schema 7), and a pfm older than this release refuses a state database stamped 7, so going back to v0.88.1 after this update stops at `schema version 7 is newer than binary version 6`.
- Global: commands/pfm/space.md — `/pfm:space [name]` runs `pfm chat space` for the current chat, and `/pfm` lists `space` among the chat verbs.

- pfm: doctor rows — `pfm doctor` gains `pfm_build` (the running pfm against the clone's `VERSION` and `HEAD`; `BEHIND`, `AHEAD`, `DIVERGED`, `UNSTAMPED` and `UNVERIFIED` are warnings, so a `pfm update` never rolls back on them), `system-prompt` per account, `git_push` (whether this host can push to the clone's GitHub origin), `leak_terms` (whether the pre-push leak gate has its denylist), a stale-theme check compared as a JSON subset, and, on an alpha build, an uninitialised plugin submodule as a FAIL. `git_push` and `leak_terms` warn on any host that does not push from its clone and carry the ids `git-push` and `leak-terms`.
#### → For: adopters who never push from the Professor clone · after update · pfm.config.json doctor.ignoreWarnings — add `"git-push"` and `"leak-terms"` to `doctor.ignoreWarnings`; `pfm doctor` then reads `IGNORED` on both rows.

- Global: rules/pcm-guard-routes.md — a new always-on rule tells every agent but `pcm` that inline code or a heredoc naming `CLAUDE.md`, `.claude` or `templates` can be refused by the `pcm-guard` hook, and to put that code or text in a file passed by path.

## Changed

- pfm: Claude launch defaults — every Claude launch layers a shipped defaults file under pfm's computed `--settings`, then the machine and project `claude.settings`, then a `--settings` you type; `pfm config claude` lists the defaults with their reasons. Three are new: the fleet prompt (`claude.systemPrompt` unset now means `professor` where a Professor clone is recorded, so every launch but a one-shot query carries Professor's main-chat system layer; `"production"` opts out), `CLAUDE_CODE_NATIVE_CURSOR=1` (the prompt blinks the terminal's own cursor) and `"tui": "fullscreen"` (Claude Code's fullscreen renderer, with `CLAUDE_CODE_NO_FLICKER`); a `null` for any key in `claude.settings` removes its default, and `"tui": "default"` also turns fullscreen off. `pfm install` sets `leftArrowOpensAgents` to `false` in every account's `.claude.json`, so ← on an empty prompt no longer opens the agents view. A `claude.settings.env` naming a variable pfm reserves is refused as in `envs`. (cost)
- pfm: statusline — the context strip is an 8-cell ▰▱ gauge of the window share and a pulse of the last 30 s of growth in three dot sizes (· none, • under 5,000 tokens, ● 5,000 or more, ↓ a drop), with no reverse video, and at rest the pulse widens so the percentage stays on one cell; line 2 is rebuilt on the same strip; every line and sub-agent row fits the terminal's width, dropping parts in a fixed order below 120 columns, and the quota row keeps every label whole and shrinks its bars first.
- pfm: alpha plugin installs — on an alpha build, `claude.plugins` unset now plans exactly the default list, and every other plugin in the clone's marketplace is installed from its checkout and kept disabled; a release build is unchanged.
- pfm: model prices — the price table adds `gpt-6.2-astra` and `gpt-6.2-sol`.
- Global: commands/pfm.md — `/pfm` § Config documents the one `pfm.config.json` at two scopes, `claude.settings` and its layers, and the retired launch keys.
- Global: rules/flights-life-cycle.md — a lander message not opening with PASS, FIXED, FAIL, REVIEWED or BLOCKED is a stall the main chat resumes at once, and foremen run their projects' unit suites before returning; `rules/rm-rf-absolute-path.md` now covers every `rm`, never only `rm -rf`. The always-on global rule set is over its 9,216-byte budget, so `engine-sync doctor --machine` warns `GLOBAL-BUDGET`.
- Repo: plugins — pinned at their releases: auto-effort 3.2.0 (any model is steered, the turn reminder asks for `set_effort` only when the work needs another level), cache-keepwarm 0.8.0 (typing in the prompt box no longer ends a keep-warm wait; `/keepwarm on` arms the standing wait), flights 2.0.1 (the lander and reviewer wait for their checkers inside the turn, waits end at 170 s, foremen run unit suites before returning) and harvester 0.3.0 (an anonymous daily install ping from `harvester mcp`, off with `HARVESTER_INSTALL_PING_OFFLINE` or `DO_NOT_TRACK`); forward-compaction stays at 2.3.1.
- Repo: INSTALL.md — rewritten: what every Claude launch carries, verifying the install, contributing from a clone, installing Herdr and initialising the plugin submodules.
- Repo: infra/install-ping — the Cloudflare Worker and D1 counter that receives the install pings, with its stats query.

## Fixed

- pfm: picker dead Herdr seats — a dead native Herdr seat with no transcript no longer lists in the picker, `pfm chat kill` of a dead seat hides its row and ends any live seat that resumed the same chat, and the picker skips rows it cannot address.
- pfm: handoff --then — a handoff's `--then` no longer dies when Herdr has not yet registered the restarted Claude; the successor chat gets its prompt.
- pfm: reload numbered prompt — a reload no longer refuses a chat whose last prompt opened with a numbered list (`open selector menu on the pane — refusing to /exit`); a real numbered menu in a Codex chat now refuses a reload too.
- pfm: native Herdr tab after /clear — a native Herdr tab no longer paints dead (⬛) after `/clear`.
- pfm: pfm chat open under tmux — `pfm chat open` no longer fails to name its caller when an unrelated tmux server lists a pane with a blank pid.
- pfm: statusline figures — a session that ran a sub-agent no longer shows `+?` on the main line, in sub-agent rows or in `pfm tokens`; a zero growth figure draws blank instead of `+0`; token counts round half up (1,950 → 2.0K).
- pfm: MCP spawn config — an MCP server pfm spawns reads the config at spawn time, never a copy from when pfm started.
- pfm: Linux process reads — on Linux, a process that exits while pfm reads its `/proc` entry reads as gone, so the Herdr fleet scan no longer logs `read supervisor ancestry N: read /proc/N/stat: no such process`.
- pfm: non-interactive Claude launch — a Claude launch pfm starts with no terminal on stdin (from a script or a pipe) no longer hangs for up to seven days when Claude exits at once; it returns Claude's exit status.
- Repo: leak gate — raster images are excluded from the leak scan by design, a private term in a binary or undecodable line is judged the same on macOS as on Linux, and a match the judge loses is a `SCAN-ERROR` (issue #63).
- Repo: fence — the fence runs on RHEL-family and SUSE hosts (`PFM_APT_MIRROR`), a gate on a slow Mac no longer fails the `internal/paths` time budget (issue #63), and a mkdir lock is no longer held twice under uutils `mkdir`.

## Removed

- Repo: glama.json — Professor leaves glama.ai; Harvester is listed there under its own repo.
