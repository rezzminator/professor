# v0.81.0 — 2026-10-13

Update the engine-sync plugin to 0.3.0 before this update: the install that ends `pfm update` now refuses an older engine-sync, and the update rolls back. The GPT twins `gpt-foreman`, `gpt-lander` and `gpt-executor` are now `gpt-flights-foreman`, `gpt-flights-lander` and `gpt-flights-mechanical-executor`, `terra` is gone, and the twins install only with `claude.gptAgents` set to true. In each project the prompt-file guard hook and `/rnd` are retired, `/pcm`'s protocol moves into a new `pcm` agent, and pfm gains the verbs that close every `pfm doctor --project-updates` row, while plain `pfm doctor` now warns about each adopted project with open rows. The machine-global `documenter` agent writes permanent docs from a caller's handoff, `/ultimate-spec` specs a vision and builds it with sub-agents, and the `agent-effort` plugin is now `effort-live-control`. Agents still compact with sub-agent-compact's `compact` tool, the plugin now pinned at 0.4.1; a host that installed its 0.4.0, which turned that tool off, updates the plugin after the update, because `pfm install` never updates an installed plugin.

## Breaking

- pfm: engine-sync 0.3.0 — the install that ends `pfm update` is run by the newly built pfm, which requires engine-sync 0.3.0-alpha.4 or later; against the 0.2.0 binary v0.80 required it stops with `engine-sync {version} is older than required 0.3.0-alpha.4 — update the plugin`, and the update rolls back (exit 5). engine-sync 0.3.0 also refuses `machine.modelMap` (use `codex.modelMap`), `machine.variants` and `opencode.agent` (use `engines.opencode.permission` in the agent's own header) in an engine-sync config file you wrote, and skips any agent whose header still carries a flat `codex-model`, `codex-effort`, `codex-sandbox`, `opencode-model` or `opencode-mode` key, naming its new home (`codex-model moved to engines.codex.model`): per-engine settings now sit in an `engines:` block of the agent's own header. An agent header that is not valid YAML, apart from single-line values Claude Code itself accepts, is reported `FRONTMATTER-INVALID {file}:{line} — {error}` and that agent is skipped.

## Added

- Global: documenter agent — the machine-global `documenter` (sonnet) writes permanent docs — the docs hub, a project's `docs/`, runbooks, design specs, backlog and epics — in modes `update`, `audit`, `registry` and `epic [name]`, loading `/quality:doc` first. It works only from a caller-written handoff, one row per change (the current-state fact, its symbol and file names, the target doc when known), writes claims only about code present in the tree and returns a `DEPENDENT` row for a change whose code is absent; an `update` or `epic` brief without a handoff returns `NO HANDOFF`, a repository without a docs layout `NO DOC LAYOUT`, and a stop return leads its reply.
- Global: /ultimate-spec and the ultimate agent — `/ultimate-spec [vision | file]` writes a spec for a vision through the new `ultimate` agent (opus) and builds it with sub-agents, returning the work and its spec path; `/ultimate` stays the command for one piece made in the chat.
- Global: new review agents — `reviewer-nt` is `reviewer` without tracers, on opus at high effort; with `claude.gptAgents`, `gpt-reviewer` and `gpt-reviewer-pro` run `reviewer` and `reviewer-pro` on GPT sol at high effort, and `gpt-flights-lander` reviews with them.
- Project: pcm agent — `/pcm`'s protocol moves into the new `pcm` agent (`templates/project/agents/pcm.md`, opus, loads `/quality:prompt` before any prompt-file edit), with its audit scopes in the new `templates/project/docs-commands/pcm/references/audit-scopes.md`; `templates/project/commands/pcm.md` becomes a user-only dispatch that hands the request to the agent verbatim, so a model routes edits to `.claude/**` and `CLAUDE.md` to the agent instead of asking the user for `/pcm`.
#### → For: every adopter · per project · `/pcm` — adopt the two `NEW` rows (`pfm update pin --template <template> <local>` as each row prints) before porting the `UPDATED` `templates/project/commands/pcm.md`, carry your local `/pcm` protocol edits into `.claude/agents/pcm.md`, then `pfm update pin .claude/commands/pcm.md`; `pfm doctor --project-updates` lists none of the three.
- pfm: project-update verbs — `pfm update pin <local> --keep "<what you did not take, and why>"` records a deliberate non-port of one `UPDATED` file as a `KEPT` row (`--unkeep` clears it once ported), and `pfm update accept <path> --reason "<why>"` closes a `RETIRED-NAME` hit that must stay (`--undo` reverses it); a `NEW` row still closes by adopting it or `pfm update ignore`. Each `UPDATED` row lists the upstream commits behind its diff, and the report carries a guide that ends every row in a verb until it reads `clean`. A project that records a keep or an accept gets a version-2 `.professor/baseline.json`, which pfm before v0.81.0 reports as `UNREADABLE BASELINE-VERSION 2: unsupported`. This update runs v0.80.1's pfm, so the report it appends inside a project and the update chat's instructions lack these verbs; `pfm doctor --project-updates` shows them once the update is done, and the update chat instructions that end each project at `clean` first run on the next update.
#### → For: every adopter · per project · `pfm doctor --project-updates` — after this note's other `per project` actions, close every remaining row with the verb its guide names, running the verbs one at a time, and re-run until it exits 0 and ends `clean`, or `INCOMPLETE` when a text file over 1 MiB is only partly scanned, which no verb closes in this release.
- pfm: doctor project ledger — `pfm doctor` prints one `doctor: warning project_updates root={path} unresolved={n}` row per adopted project with a row no verb has closed, covering the current directory and every project a chat on this host ran in, and naming `pfm doctor --project-updates --root {path}`; the rows change neither doctor's exit code nor its closing tally. Every `pfm doctor` run, including the runs inside `pfm update`, builds those reports four at a time, bounded at 60 s for the whole ledger. (cost)
- Repo: gpt-gateway middleware — the `plugins/gpt-gateway` pin moves to gpt-gateway v0.3.0: its `middleware/advisor_cache.py` adds prompt caching to Claude Code's advisor tool, off until listed in the gateway's `settings.json`, and its `status_label` middleware takes `"answer": "marked"` to answer only the sub-agent summary requests that cache-live-control's `/cache summaries off` marks; its README's Shipped middleware section turns either on. (opt-in)
