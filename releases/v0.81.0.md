# v0.81.0 — 2026-10-13

Update the engine-sync plugin to 0.3.0 before this update: the install that ends `pfm update` now refuses an older engine-sync, and the update rolls back. The GPT twins `gpt-foreman`, `gpt-lander` and `gpt-executor` are now `gpt-flights-foreman`, `gpt-flights-lander` and `gpt-flights-mechanical-executor`, `terra` is gone, and the twins install only with `claude.gptAgents` set to true. In each project the prompt-file guard hook and `/rnd` are retired, `/pcm`'s protocol moves into a new `pcm` agent, and pfm gains the verbs that close every `pfm doctor --project-updates` row, while plain `pfm doctor` now warns about each adopted project with open rows. The machine-global `documenter` agent writes permanent docs from a caller's handoff, `/ultimate-spec` specs a vision and builds it with sub-agents, and the `agent-effort` plugin is now `effort-live-control`. Agents now list sub-agent-compact 0.4.0's handoff tool and the flights agents hand off at a compaction nudge; `pfm install` leaves an installed plugin at its version, so update sub-agent-compact after the update.

## Breaking

- pfm: engine-sync 0.3.0 — the install that ends `pfm update` is run by the newly built pfm, which requires engine-sync 0.3.0-alpha.4 or later; against the 0.2.0 binary v0.80 required it stops with `engine-sync {version} is older than required 0.3.0-alpha.4 — update the plugin`, and the update rolls back (exit 5). engine-sync 0.3.0 also refuses `machine.modelMap` (use `codex.modelMap`), `machine.variants` and `opencode.agent` (use `engines.opencode.permission` in the agent's own header) in an engine-sync config file you wrote, and skips any agent whose header still carries a flat `codex-model`, `codex-effort`, `codex-sandbox`, `opencode-model` or `opencode-mode` key, naming its new home (`codex-model moved to engines.codex.model`): per-engine settings now sit in an `engines:` block of the agent's own header. An agent header that is not valid YAML, apart from single-line values Claude Code itself accepts, is reported `FRONTMATTER-INVALID {file}:{line} — {error}` and that agent is skipped.

## Added

- Global: documenter agent — the machine-global `documenter` (sonnet) writes permanent docs — the docs hub, a project's `docs/`, runbooks, design specs, backlog and epics — in modes `update`, `audit`, `registry` and `epic [name]`, loading `/quality:doc` first. It works only from a caller-written handoff, one row per change (the current-state fact, its symbol and file names, the target doc when known), writes claims only about code present in the tree and returns a `DEPENDENT` row for a change whose code is absent; an `update` or `epic` brief without a handoff returns `NO HANDOFF`, a repository without a docs layout `NO DOC LAYOUT`, and a stop return leads its reply.
- Global: /ultimate-spec and the ultimate agent — `/ultimate-spec [vision | file]` writes a spec for a vision through the new `ultimate` agent (opus) and builds it with sub-agents, returning the work and its spec path; `/ultimate` stays the command for one piece made in the chat.
- Global: new review agents — `reviewer-nt` is `reviewer` without tracers, on opus at high effort; with `claude.gptAgents`, `gpt-reviewer` and `gpt-reviewer-pro` run `reviewer` and `reviewer-pro` on GPT sol at high effort, and `gpt-flights-lander` reviews with them.
- Project: pcm agent — `/pcm`'s protocol moves into the new `pcm` agent (`templates/project/agents/pcm.md`, opus, loads `/quality:prompt` before any prompt-file edit, names `mcp__sub-agent-compact__handoff` beside `mcp__sub-agent-compact__compact` on its `tools:` line and has a new agent's `tools:` name both), with its audit scopes in the new `templates/project/docs-commands/pcm/references/audit-scopes.md`; `templates/project/commands/pcm.md` becomes a user-only dispatch that hands the request to the agent verbatim, so a model routes edits to `.claude/**` and `CLAUDE.md` to the agent instead of asking the user for `/pcm`.
#### → For: every adopter · per project · `/pcm` — adopt the two `NEW` rows (`pfm update pin --template <template> <local>` as each row prints) before porting the `UPDATED` `templates/project/commands/pcm.md`, carry your local `/pcm` protocol edits into `.claude/agents/pcm.md`, then `pfm update pin .claude/commands/pcm.md`; `pfm doctor --project-updates` lists none of the three.
- pfm: project-update verbs — `pfm update pin <local> --keep "<what you did not take, and why>"` records a deliberate non-port of one `UPDATED` file as a `KEPT` row (`--unkeep` clears it once ported), and `pfm update accept <path> --reason "<why>"` closes a `RETIRED-NAME` hit that must stay (`--undo` reverses it); a `NEW` row still closes by adopting it or `pfm update ignore`. This update runs v0.80.1's pfm, so the report it appends inside a project and the update chat's instructions lack these verbs; `pfm doctor --project-updates` shows them once the update is done, and the update chat instructions that end each project at `clean` first run on the next update.
#### → For: every adopter · per project · `pfm doctor --project-updates` — after this note's other `per project` actions, close every remaining row with the verb its guide names, running the verbs one at a time, and re-run until it exits 0 and ends `clean`, or `INCOMPLETE` when a text file over 1 MiB is only partly scanned, which no verb closes in this release.
- pfm: doctor project ledger — `pfm doctor` prints one `doctor: warning project_updates root={path} unresolved={n}` row per adopted project with a row no verb has closed, covering the current directory and every project a chat on this host ran in, and naming `pfm doctor --project-updates --root {path}`; the rows change neither doctor's exit code nor its closing tally. - Repo: gpt-gateway middleware — the `plugins/gpt-gateway` pin moves to gpt-gateway v0.3.0: its `middleware/advisor_cache.py` adds prompt caching to Claude Code's advisor tool, off until listed in the gateway's `settings.json`, and its `status_label` middleware takes `"answer": "marked"` to answer only the sub-agent summary requests that cache-live-control's `/cache summaries off` marks; its README's Shipped middleware section turns either on. ## Fixed

- pfm: status line — a sub-agent row that fails to read, parse or render shows a red `pfm statusline: {cause}` row with the cause on stderr, where every row used to turn plain silently; the agent panel reads up to 16 MiB of input (was 1 MiB), and an overflow shows as a fault.
- pfm: retired-name scan — the `RETIRED-NAME` section of `pfm doctor --project-updates` no longer flags a name inside a URL, or a command, agent or skill the project defines in its own `.claude/commands`, `.claude/agents` or `.claude/skills` file. A retired path that still exists in the project also hides that path's mentions, so close the `MOVED` and `GONE-UPSTREAM` rows before trusting a `clean` section.
- pfm: GPT foreman Stop hook — with `claude.gptAgents`, the Stop hook of `gpt-flights-foreman` and `gpt-foreman-pro` lets through a stop whose last message carries a well-formed `<handoff>` or `<compact-now>` block — a closed, non-empty tag pair outside backticks, the grammar sub-agent-compact accepts — and leaves that plugin to hold it as a compaction step, where it could block a `<handoff>` stop for lacking a `DONE`, `PARTIAL`, `FAILED` or `BLOCKED` first line; an unclosed, empty or backticked marker, `<compact-now>` included, now gets that first-line check like any other stop, and a well-formed marker the plugin does not take (its `handoffTool` or `compactTool` off, a handoff below its first nudge point, a second marker stop before a compaction) still ends the run without a return line. The install that ends the update stages it.
- pfm: chat await — `pfm chat ask` and `pfm chat new --await` no longer read the record sub-agent-compact 0.4.0 writes when it installs a chat's stored handoff at a compaction (a user turn opening `[sub-agent-compact: handoff]`) as a second message: a wait on a chat nobody else spoke to no longer exits 7 with `another message reached {chat} while this one was waiting`, that record no longer counts as delivery of the message waited on, and the printed answer keeps what the chat said before it. A real second message, before or after the install, still exits 7.
