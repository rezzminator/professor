# v0.87.0 — 2026-11-01

Codex and OpenCode chats can no longer write git or framework files: this update's `pfm install` adds an engine guard that denies every git write and every change to `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.codex/`, `.opencode/` and the engine config dirs to the main chat and every role on those engines, gitter included, so such changes now go through a Claude chat or by hand. The auto-effort-control plugin is renamed auto-effort: `pfm install` moves the installed copy, and pfm reads the old name in `pfm.config.json` with a doctor warning until you rename it. pfm now works inside herdr-keep-protected Herdr panes, and the Herdr tab-indicator daemon stops burning CPU and disk on every chat's turn. On a release build, `pfm install` refreshes Claude Code's listing of Professor's plugin marketplace before installing from it, so the renamed and new plugins install on this update. New machine-global rules `writing-code`, `testing` and `integration-tests` carry the coding and test laws; the new opt-in rule-control plugin keeps the first two to the build agents, and without it every Claude loop receives them.

## Breaking

- pfm: engine guard — `pfm install` writes a `PreToolUse` hook running `pfm internal engine-guard --engine codex` (matcher `Bash|apply_patch`) into each Codex home's `hooks.json` and stages `pfm-engine-guard.js` in the `plugins/` directory beside the OpenCode config path as written, even when that config file is a symlink, with `pfm doctor` naming it MISSING, STALE or UNREADABLE until it is current; on Codex and OpenCode the main chat and every role, gitter included, may only read git (plus named-file `git checkout --` or `git restore`, `git apply` to the working tree and `git stash list|show`), and a write to any `CLAUDE.md`, `AGENTS.md`, `AGENTS.override.md` or `opencode.json(c)`, to `.claude/`, `.codex/`, `.opencode/` or `.git/`, to the Claude, Codex or OpenCode config dir, to the Professor clone's `templates/` or to the pfm binary is denied, the denial handing the exact change back to the user; it is installed during this update, so it binds from the after-update steps on.
#### → For: Codex and OpenCode users · after update · git writes and framework files — make commits, merges, pushes and edits to `.claude/`, `CLAUDE.md`, `AGENTS.md` or `~/.claude/` from a Claude chat (its `gitter` and `pcm` agents) or by hand, including every action of this update that edits one of them; done when `grep -c 'engine-guard' {Codex home}/hooks.json` prints 1 or more for each Codex home and `pfm doctor` prints no `pfm-engine-guard.js` row.

## Added

(cost)

## Fixed

- pfm: herdr-keep panes — inside a herdr-keep-protected Herdr pane, the caller, kill, reload, the seat host, tab indicators and restore see the real engine through `herdr-keep list --json`; killing a protected pane waits for its shell to end and, when the shell outlives the close, keeps the seat and names `herdr-keep kill {id}`; `pfm doctor`'s Herdr resume-off row asks herdr-keep's own doctor, so a herdr-keep that refuses to guard panes is a named warning. Without herdr-keep nothing changes.
- pfm: Herdr tab indicators — the `pfm internal herdr-indicators` daemon no longer runs a full fleet scan every 500 ms (~40-50% of a core for days), re-reads OpenCode's store on every pass or rescans on any chat's turn: it rescans only when a cheap probe of the tabbed chats changes or 10 s pass, skips an unchanged OpenCode store, stops with its Herdr server, and leaves the directory it was started from, so removing that worktree no longer breaks its scans; this update's `pfm install` replaces a running painter left by the old binary.
- pfm: Herdr seats — a scheduled wake of a dead Herdr-born chat revives it on its recorded Herdr host instead of in tmux beside the old pane; `cx` typed in Herdr is born natively; a native tab follows the seat that owns its terminal; a retired seat whose supervisor is dead no longer makes its old pane's owner ambiguous; a native seat restarts on the current Claude build after version retention prunes its recorded one; ⌃X on a lost native chat hides it; a zsh shell that sourced the previous `cx` and types `cx` with a prompt in Herdr is refused with `this shell's cx predates this pfm` instead of birthing the chat without its prompt.
#### → For: Herdr users who type `cx` · after update · zsh shells opened before the update — in each, run `source ~/.zshrc` or open a new shell before typing `cx` with a prompt; done when `functions cx | grep -c 'rc == 3'` prints 1 in that shell.
- pfm: continued Claude chats — a chat Claude Code continues under a new session id stays one chat: the picker lists it once, `pfm chat open`, restore and `pfm chat reload` resume the newest segment and refuse while another live chat holds it, and its schedule shows on the seat.
- pfm: doctor and install rows — a deferred plugin-copy retirement is a `deferred: {reason}` warning, never a failure, and a chat holding both a session and a launch claim counts once; the crumb audit accepts pfm's own native-seat end and kill-exit logs; the ponytail plugin's per-account state files classify as ignored runtime.
- pfm: plugin installs from GitHub — on a release build, `pfm install` runs `claude plugin marketplace update` once per pass on a marketplace Claude Code already knows, before its first plugin install, so a listing cached before this release no longer hides a plugin it adds or renames; a failed refresh is a warning, and the install failure that may follow names the refresh command; a disabled install record of a Professor plugin is brought to its marketplace's current version before it is enabled; `pfm doctor`'s `not enabled` row names the version that record holds.
- pfm: macOS caller lookup — on macOS pfm reads a calling process's environment, so `pfm chat open`, chat-server, launch and `pfm doctor`'s Herdr backend check find their caller instead of failing.
- pfm: tmux 3.8 dead panes — a dead pane, which tmux 3.8 lists with no process id, no longer fails pfm's read of its tmux server, and never roots a process-tree walk.
- pfm: Codex rollouts — pfm reads Codex's compressed `.jsonl.zst` rollouts wherever it reads plain ones.
- pfm: price catalog — OpenAI's pricing page parses again and gpt-6-rosalind is priced.
- pfm: settings and shell words — removing a JSONC member no longer damages string values restored into VS Code settings at uninstall, shell splitting keeps backslashes inside double quotes, and generated hook and shell files switch their quoting and are rewritten once by `pfm install`.
- pfm: detached children — long-lived pfm processes, such as the paced statusline worker, reap their detached children instead of leaving zombies.
- pfm: MCP daemon handoff — an exiting MCP daemon whose environment reads back torn no longer fails the install's daemon handoff.

## Removed

- Repo: plugin-log library — Professor's shared plugin logging library, its sync script and drift gate are gone; each plugin owns its logging module and installs on its own, and every marketplace plugin ships a root marketplace named `professor`, so a plugin added straight from its own repository installs as `{plugin}@professor`, the same id Professor's marketplace gives it.
- Repo: self-hosted manifest gate — `.professor/manifest.json` keeps only `installed_from.repo`, and `infra/check-self-hosted-manifest.sh` is deleted.
- Repo: statusline design doc — `docs/design/context/` is deleted.
