# pfm (Professor-Fleet-Manager) TESTPLAN — the complete flow matrix

Every pathway through the fleet tooling: the Go engine (`pfm/`), the embedded zsh launcher shim, the `pfm chat` surface and its two-line compatibility delegate, the MCP server, the history helper, and the self-installer. One row per flow.

Go paths are relative to `~/.professor/pfm/` (the engine lives at the repo root — it is a program, not a template); embedded helper paths live under `internal/installer/assets/`. Absolute paths are absolute.

## A — `pfm` CLI subcommands and flags

### A.1 — engine-sync callers and the retired `pfm {codex|opencode}` commands

The Codex and OpenCode compilers are engine-sync's: pfm imports none of its packages and execs the binary per `plugins/engine-sync/docs/interface.md`. Every pfm test runs a fake engine-sync the jail installs on `$ENGINE_SYNC_BIN` (`internal/testjail/enginesync.go`), never the real binary; the compiler's own matrix lives in engine-sync's suite.

`StageGlobalAgents` uses the shared `scripts/agent-source-inventory.py` header inventory (Python3 + PyYAML), links originals and stages generated declaration stand-ins with their root `role`; shared files below a subdirectory never enter the jail registry. `internal/testjail/registry_test.go` pins this fixture boundary. Installer compatibility tests require `MinimumVersion` 0.3.0-alpha.4: an older compiler would link declarations raw.

pfm's `claude` launcher (`assets/bin/claude`) never symlinks the canonical binary straight into `~/.local/share/claude/versions/`, so Claude Code's own updater reports version cleanup disabled and every build it ever installs accumulates. The launcher asset delegates to `pfm internal claude-launch`; `ClaudeLaunch` calls `ResolveClaudeBinary`, which calls `InspectClaudeVersions` for its native-version fallback. `internal/installer/claude_versions.go` splits the work in two: `InspectClaudeVersions` (enumeration, ordering, and the structural protections — newest, unparsed name, configured `claude.binary`, displaced native target) never touches a process table at all, because the launcher's hot path only needs the selected binary; `ProbeLiveClaudeVersions` is the separate, deliberately optional live-process half only `pfm doctor` and pruneClaudeVersions call. That probe scopes candidates the same way `internal/stale.Find` does (stale.go:53-89): a pid is worth `Image`'s cost only when its argv[0] names the Claude binary, lives inside the versions directory, or its own basename parses as a version — anything else, and any Cmdline read that fails, is skipped before `Image` is ever called, and a candidate's `Image` failure is refused (named "probe failed") UNLESS the pid has already exited (`kill(pid,0) -> ESRCH`), which is skipped instead. `PlanClaudeVersionPrune` decides what a prune may remove: everything outside the keep window and not otherwise protected, or nothing at all when the live probe could not vouch for every candidate.

The focused Limits tab uses a sixty-second cache TTL and a two-second result poll (decaying to 30s while untouched). Accounts refresh independently with one pending request per account; leaving the tab or closing the picker cancels pending requests without recording provider backoff. Successful cache reads retain the provider's confirmation time. Empty or future-dated payloads cannot suppress a fresh fetch. The shared `acct-<id>.json` and `codex-<id>.json` caches retain HTTP 429 backoff of at least ten minutes and other provider failure backoff of sixty seconds; the prompt hook keeps its 180-second default TTL.

Both the Limits tab and the prompt hook reach the usage endpoint only through `usagehook.Fetch`, in order: a fresh `cc-rate-limits` statusline snapshot of the seat; a cache record fresh within the caller's TTL; an active shared backoff; then the `O_EXCL` refresh lock `acct-<id>.lock` (`RefreshLockPath`; stale after 30 seconds; a caller that cannot take it answers from the cache; the holder re-reads the cache first); then one request carrying `User-Agent: pfm/{version}`. Two callers against an expired cache spend exactly one request. A 429 is the shared backoff from `BackoffFor` (`Retry-After`, ten-minute floor), including one the hook met. A rate-limited account's status reads `rate-limited — retry HH:MM` first and says `limits unavailable` at most once — the sampler's status string (`TestLimitsSampler429StatusSaysUnavailableOnceWithTheRetryTimeFirst`, `internal/stats`) — and the card `renderLimitCards` draws from a sampled 429 keeps the retry time and that phrase at most once at 118 and 50 columns (`TestRateLimitedLimitCardSaysUnavailableOnceAndKeepsTheRetryTime`, `internal/ui`, through the stats sampler to the rendered card). `fillLine` alone ends a line cut at the pane width in `…` (`TestFillLineMarksACutWithAnEllipsis`, the helper, no card).

An independent five-second UI clock advances quota reset countdowns, confirmation ages, and the Cosmos ledger while fleet scans and sky animation are parked, including with `--no-sky`. Delayed sample, fleet, and animation timestamps cannot rewind time. Limits percentages explicitly say `used`; a window past its reset says neither, rendering an em dash with no bar. Rendering remains bounded at 40-, 60-, 80-, and 120-column widths.

### Composer transport boundaries

The current boundaries are `ClaudeInlineMax=720` and `CodexInlineMax=900` in `internal/call/types.go`. Fixture tests check pfm's transport choice and delivery receipts; actual engine composer thresholds remain UNPLAYED. An engine-side probe uses a scratch working directory and a fresh `probe-*` tmux socket, sends payloads with distinct head/tail markers, compares the transcript or rollout with pane capture, and checks `#{pane_dead}`. A failure edge is the first payload that collapses into a paste block and fails to reach the transcript or rollout on one Enter.

| engine | transport | boundary input | next size | composer symptom to probe |
| ------ | --------------------------- | ------------------------- | ------------- | -------------------------------------------------------------------- |
| Claude | literal `send-keys -l` | 1,024 chars | 1,025 chars | `[Pasted text #N]`; one Enter left the block in the composer |
| Claude | bracketed `paste-buffer -p` | 800 chars | 801 chars | `[Pasted text #N]`; one Enter left the block in the composer |
| Codex | literal `send-keys -l` | 1,000 chars | 1,001 chars | `[Pasted Content N chars]`; one Enter left the block in the composer |
| Codex | bracketed `paste-buffer -p` | 1,000 chars | 1,001 chars | `[Pasted Content N chars]`; one Enter left the block in the composer |

The per-engine inline boundary uses the smaller transport edge and rounds down at 90%: Claude `floor(801 × 0.9) = 720` runes; Codex `floor(1001 × 0.9) = 900` runes. The comparison is against the complete signed wire message, so a signature consumes part of the safety margin.

On live delivery this is the inline-`SendLiteral`-vs-bracketed-`SendPaste` boundary: a message over it reaches the pane through tmux's bracketed paste (`load-buffer` + `paste-buffer -p`), checked by a tail match in the capture or the fixture composer's collapsed-paste placeholder (`[Pasted text #N]` / `[Pasted Content N chars]`). The auto-file store (`~/.local/state/pfm/call-bodies`, mode 0600, pruned past seven days) is a rescue when paste delivery cannot be proven, reported through the receipt and `Result.AutoFilePath`. On the dormant/resume path (`PrepareForResume` writes into a transcript, with no live composer) the boundary remains inline-vs-file: an 8 KiB body becomes a byte-exact pointer. Slash commands travel in locked 512-rune literal chunks, with Enter after the final chunk; the `/compact` fixture checks the complete command.

## Residual known divergences

1. **Store-only rows carry no parent link** (`index/codexstate.go`). The fake engine covers current same-thread resume behavior; a distinct parent-link shape remains UNPLAYED. Detect it by grouping same-cwd rows with the same first message.
2. **`mcpserv/backend.go:303-308` counts `Agent` as live** while `ui/model.go:467-471` does not. An agent row is capture-probed for busy state in MCP and treated as non-live in the TUI.
3. **Stats `TOKENS` is transcript traffic, not cost.** Claude assistant records add `cache_read_input_tokens` on every turn, so a long chat repeatedly counts its cached prefix. The open product question is whether this total should remain traffic or become a billed-cost metric; the live-rate change deliberately leaves the total unchanged.
4. **`lerpRGB` and `luma` still contract on an FMA architecture** (`ui/cosmoscanvas.go:20-22,37` remain the only fused-multiply-add sites in the package's arm64 assembly). Measured, not assumed: re-rendering every golden with EVERY fusable expression in `ui/cosmos.go` and `ui/cosmoscanvas.go` contracted the way arm64's rules contract them moved exactly one byte, and it was the Bezier's. Colour reaches the frame through `quantRGB`'s 8-step quantisation, which absorbs a 1-ULP difference everywhere the current fixtures land. Re-open if a golden goes red on an FMA host at a colour escape rather than a glyph.
