# v0.91.1 — 2026-11-24

A patch release with no action to take. Claude chats pfm launches after the update find every tool the account's login shell puts on PATH (mise, nvm, asdf, brew shims), even when pfm itself was started from a bare PATH such as a systemd unit or the chat MCP server, and a chat started in a Herdr pane keeps its pane shell's PATH order. The cost: each Claude launch from a fresh pfm process, every interactive `claude` start through pfm included, first runs the account's login shell once, for up to 3 s. The picker no longer drops its oldest resumable chats on each refresh, its header counts hold still between the first frame and the full one, and a forked Codex thread in a Herdr pane no longer leaves a duplicate resume row.

## Changed

- Repo: release check — the release scope counts pfm's new login-shell package among the update-path files a release reviews.
- Repo: pfm tests — the journey types a long mock-engine directive in 256-byte pieces, each sent once the composer shows the text before it, so a loaded macOS runner no longer cuts it mid-string; the MCP listing check passes when the `herdr-mesh/alone` step runs alone.

## Fixed

- pfm: Claude launch PATH — a Claude chat pfm launches (interactive, passthrough, headless or in a Herdr pane) now gets the tools the account's login shell puts on PATH, so the chat's Bash tool, which reads no startup file, no longer misses `go`, `node`, `npm`, `python` or `gofmt`: once per pfm process and shell, pfm runs the account's login shell (from `getent` on Linux, `dscl` on macOS, `$SHELL` when that lookup fails) as an interactive login shell in a clean login environment, capped at 3 s, and adds each absolute folder of its PATH the launch PATH lacks. A chat started in a Herdr pane keeps the pane shell's own PATH first and gains only those missing folders after it; a chat pfm starts directly keeps its launch PATH's order and places each missing folder where the login shell puts it, so shims the login shell lists ahead of `/usr/bin` stay ahead of it; a persona's own `PATH` is the base and is written as it is. A login shell that is slower than 3 s or prints no PATH leaves the launch PATH as it was and writes a `claudelaunch: login PATH` warning that `pfm log --level warn` shows; one whose startup files leave a background process holding its output still gives the PATH it printed. A chat running through the update keeps its PATH until it is launched again. (cost)
- pfm: picker and pfm ls — the picker's default view no longer drops its oldest resumable chats on every refresh: its capped first frame read the 30 newest Claude and 15 newest Codex chats before knowing which were live, so each live chat took a resume slot until the full frame drew the missing ones back; it now re-reads around the live chats, and the header's empty and hidden counts no longer flip between the two frames. A native Herdr Codex seat on a forked thread no longer leaves a duplicate resume row beside it in the picker or `pfm ls`.
- pfm: picker hidden chats — a chat hidden by a legacy `_HIDE` name is no longer counted as resumable by the picker's first frame, so with such chats the header no longer shows fewer hidden and more empty chats than the full frame, and a newer `_HIDE` chat no longer takes a resume slot.
