### 5. Verifying the unit on an Apple-Silicon Mac
- Stock Homebrew `rtl-sdr`/`librtlsdr` is the Osmocom driver and does **not** support the V4 — upstream closed the request "not planned" ([librtlsdr#77](https://github.com/steve-m/librtlsdr/issues/77)). You must build the vendor fork ([rtlsdrblog/rtl-sdr-blog](https://github.com/rtlsdrblog/rtl-sdr-blog)), which stays backward-compatible with V3:

```bash
brew uninstall rtl-sdr
brew install cmake libusb pkgconfig
git clone https://github.com/rtlsdrblog/rtl-sdr-blog
cd rtl-sdr-blog && mkdir build && cd build
cmake .. -DCMAKE_INSTALL_PREFIX="$(brew --prefix)" -DCMAKE_INSTALL_RPATH="$(brew --prefix)/lib"
make -j"$(sysctl -n hw.ncpu)" && sudo make install
rtl_test -t
```

- Authenticity check: EEPROM manufacturer string must read **`RTLSDRBlog`** and product string **`Blog V4`** (the V4L reads `Blog V4L`); a device reporting generic `RTL2832U`, a default serial like `00000001`, or failing to tune HF is a clone ([rtl-sdr.com/genuine](https://www.rtl-sdr.com/genuine/), [rtl-sdr.com/v4](https://www.rtl-sdr.com/v4/)).
- Physical tells of a genuine V4: side screws mounted **diagonally/offset** (clones use straight horizontal/vertical alignment), an all-**brass** SMA female connector (clones use nickel/silver), internal **thermal pads** to the aluminium shell (clones omit them and overheat after ~10 min), working bias-tee and HF upconverter ([rtl-sdr.com/genuine](https://www.rtl-sdr.com/genuine/), [SDRstore clone-warning guide](https://www.sdrstore.eu/is-your-rtl-sdr-fake-clone-warning-signs/)). Per the EOL post, most fake V4s are a copied V4 enclosure over V3-clone or FC0012-class internals.
- **The V4L has no macOS driver support at all** — rtl-sdr.com: "we are not aware of any maintainers that have updated drivers to support the V4L yet" ([V4L guide](https://www.rtl-sdr.com/v4l/)). For this buyer, receiving a V4L instead of a V4 is not a downgrade, it is an unusable device.
