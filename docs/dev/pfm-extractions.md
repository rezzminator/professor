# pfm extractions — phase P2d "cmd/pfm units leave package main"

**Status:** DESIGN, brownfield, executable. Measured on `wave/reliability-gates @ 6e9d0b13` (2026-09-17) with a `go/ast` walk over `cmd/pfm` (every identifier a unit's files use that another `package main` file declares, and the reverse), `pfm/`-relative paths (module `hostops/pfm`). Method: `/quality:llm-codebase` (brownfield, incremental — 8.7K of 17.5K `cmd/pfm` lines move, every move a package the tree already names). Companions: `docs/dev/pfm-layout.md` (P2c; its § Scope ruling deferred these four units here) and `docs/dev/pfm-architecture.md` steps 3–7, which this design executes with three departures, each argued in § (b). Measured while P3 was executing in the same worktree (its identifier renames were in the tree, uncommitted; the coupling walk re-run after them was identical). Runs AFTER P3 and P4: every anchor below is a **symbol**, never a line; a symbol P3/P4 renamed is found with `grep -rnw` under its new spelling, and a symbol that is gone is a stop-and-report, never re-created.

**The coupling, re-measured.** P2c counted the `package main` symbols each unit reaches: doctor 11, hook entries 22, update 10, picker 11. On HEAD the walk finds doctor **20** (`askAction chatCommand closeCommandResource commandRuntime configCommand doctorCommand expectedEngineCapabilities harvesterServer headlessCommand indexCommand installCommand jsonFormat mcpDaemonReachability newFlagSet parseFlags printProfessorDoctor toggleOffFlag version versionCommand` + the alias), hook entries **25**, update **11**, picker **10** — P2c's numbers omitted the `*Command` string constants and `version`. Eleven of the doctor's 20 and eight of the hook entries' 25 are those constants, and each is a **literal that never was one concept** (the `configCommand` the pre-push doctor passes is `git config`; the `installCommand` the baselines file joins is the `install/` path segment; the `agentsCommand mcpCommand updateCommand` set in the launch entry are Claude Code's own subcommands): they become local literals in the new package, not an exported registry. What remains is a web of **26 real shared helpers** (§ a, "Shared main-package symbols"), and every one of them has a package that already owns the concept. No unit is a rewrite; two files split (`internal_update_check.go`, `doctor_external_test.go`) and one signature changes shape (the two intercept entries take the front they call as a parameter, which is what their test seams already do).

## (b) Dependency order, the cycles, and the departures from the architecture doc

**Order.** Support moves first, then the unit that others print through, then the two independent units:

1. `cli`, `semver`, the `config` additions, `deps.EnvironmentWith`, `tmux.Binary`, `spawn.FreshSocket`, `action/dispatch.go`, `chat/{open,kill_server,inject_engine}.go`, `fleet.OpenKillManager`, `mcpserv/daemon_status.go`, the `testjail` fixtures — none depends on a unit; each is imported by two or more of them.
2. `professor` (scaffold, source repo, project update, `PrintDoctor`) then `update` — `doctor.Run` prints `professor.PrintDoctor`, so professor precedes doctor; `update.Run` dispatches `professor.RunProjectUpdate`, so professor precedes update.
3. `doctor` — after professor and mcpserv.
4. `picker` — takes the picker half of `internal_update_check.go`, which must leave before the hook entries move.
5. `hookentry` — last; after step 4 it depends on no unit, only on `chat spawn action deps tmux config fleet cli`.

**Departures from `pfm-architecture.md` steps 3–7.** (1) Step 3's registries (`command_table.go`, `hooks/table.go` feeding `installer/expected_hooks.go`) are **not** built here: they change what C14/C15 parse (`main.go`'s `run()` switch and `runInternal` if-chain) and the installer's wiring — a mechanism change, where P2d moves bodies; the if-chain stays the dispatcher and C15 stays meaningful.
