# v0.85.0 — 2026-10-31

pfm's Go test suites no longer run on the machine that starts them: a host `go test` of a pfm package re-runs itself in the fence or, with no fence reachable, refuses with exit 1, which breaks anyone who ran pfm's tests directly on a host. The `pcm` agent is now machine-global, linked by `pfm install` like the other shared agents, so every project has one without a copy of its own. The project templates for `pcm` and its audit checklist are retired: each adopted project reports its copies as `GONE-UPSTREAM` and closes them, keeping a copy only where it is a deliberate customization. `pfm chat open` works over ssh again.

## Breaking

- pfm: test suites — every pfm package's tests run only in the fence or on a GitHub-hosted runner; a `go test` started anywhere else re-runs its package through `dev.sh iso run`, refuses with exit 1 when no fence is reachable, and clears `PFM_STATE_DB` and `PFM_CACHE_DB`, so an exported variable can no longer point a test at the live database; `make -C pfm cover` on a host runs in the fence too.
#### → For: adopters who run pfm's Go tests · after update · `go test` in the clone's `pfm/` — run them with a reachable docker daemon so they re-run in the fence, or through `.claude/scripts/dev.sh iso test pfm` from the clone; done when the run reports its result from the fence instead of exit 1.

## Changed

- Global: pcm agent — `templates/global/agents/pcm.md` is a machine-global agent that `pfm install` links into `~/.claude/agents/` (and compiles as a Codex role), with its audit checklist at `templates/global/pcm/audit-scopes.md`; a project's own `.claude/agents/pcm.md` overrides it, and a project's `docs/commands/pcm/references/audit-scopes.md` overrides the checklist.
- pfm: pcm-guard — the refusal now names `pcm` as machine-global and tells a host where no `pcm` is registered to run `pfm install --yes`; `themer`'s refusal and who may write which file are unchanged.
- Global: professor rule — the always-on rule `templates/global/rules/professor.md` drops its "ask the user where no `pcm` is registered" fallback, and `/pfm:workbench` sends `.claude/**` and `CLAUDE.md` writes to the `pcm` agent rather than the project's.
- Repo: dev.sh — on the host, `.claude/scripts/dev.sh test|cover|all|verify|gate` re-run as `dev.sh iso …` instead of refusing.

## Fixed

- pfm: `pfm chat open` over ssh — it no longer dies with "identify native move caller: … permission denied": a process another user owns in the caller's ancestry, such as sshd's session, is passed over instead of failing the lookup.

## Removed

- Project: pcm templates — `templates/project/agents/pcm.md` and `templates/project/docs-commands/pcm/references/audit-scopes.md` are retired: `pfm init` no longer scaffolds them, `pfm doctor --project-updates` reports each project copy `GONE-UPSTREAM`, and a copy left in place keeps overriding the machine-global `pcm` and its checklist.
#### → For: every adopter · per project · `.claude/agents/pcm.md` — unless the project keeps it as a deliberate customization, have the `pcm` agent delete the file (pcm-guard refuses the deletion from any other caller); either way run `pfm update drop .claude/agents/pcm.md` while its `GONE-UPSTREAM` row is listed; done when `pfm doctor --project-updates` no longer lists it.
#### → For: every adopter · per project · `docs/commands/pcm/references/audit-scopes.md` — unless the project keeps it as a deliberate customization, delete the file; either way run `pfm update drop docs/commands/pcm/references/audit-scopes.md` while its `GONE-UPSTREAM` row is listed; done when `pfm doctor --project-updates` no longer lists it.
