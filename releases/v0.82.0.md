# v0.82.0 — 2026-10-17

Update engine-sync to 0.4.0 before this update: the newly built pfm that runs the install at the end of `pfm update` refuses an older engine-sync, and the update rolls back. `pfm chat inject` is now `pfm chat call`, pfm's MCP tools are `mcp__chat-professor__*` and `mcp__harvester-professor__*`, `pfm codex` and `pfm opencode` give way to `engine-sync codex` and `engine-sync opencode`, engine-sync's machine policy moves to `~/.claude/engine-sync.json`, and the ultimate family becomes `/imagine:build`, `/imagine:build-spec`, `/imagine:build-fast` and `/imagine:callmeter`, so chats open during the update restart and your own prompts and scripts take the new names. Machine-global agents now list sub-agent-compact's `forward_handoff` and `look_back` in place of `compact`, which they keep only with the plugin at 0.8.0 and its forward-handoff option on. In each project the `codex-sync.sh` hook bridge gives way to the engine-sync plugin's own hooks and `/pcm retro` reads `docs/retro/{owner}/`; `flights-speccer` writes specs for novel work, the GPT twins `gpt-rr`, `gpt-rr-pro` and `gpt-rr-pro-max` join, and the harvester bounds its read answers and distrusts cached Jina snapshots.

## Breaking

- pfm: engine-sync 0.4.0 — the newly built pfm that runs the install ending `pfm update` requires engine-sync 0.4.0-alpha or later (v0.81.0 required 0.3.0-alpha.4). It runs the binary `ENGINE_SYNC_BIN` names, else `~/.local/share/engine-sync/bin/engine-sync`; against a 0.3.x binary it stops with `engine-sync {version} is older than required 0.4.0-alpha — update the plugin …`, `pfm install` exits 1 and the update rolls back. engine-sync also joins the default `claude.plugins` as `engine-sync@engine-sync` from rezzminator/engine-sync: a release `pfm install` adds that copy whenever it is missing, even beside an `engine-sync@professor` copy, which it neither disables nor reports, so both copies' hooks run; `pfm doctor` warns `claude.plugins omits engine-sync — no hook rebuilds the Codex and OpenCode mirrors; add engine-sync to claude.plugins` when a `claude.plugins` you set leaves it out.
#### → For: every adopter · before update · engine-sync plugin — when `jq -r '.plugins | keys[]' ~/.claude/plugins/installed_plugins.json` does not list `engine-sync@engine-sync`, run `claude plugin marketplace add rezzminator/engine-sync` and `claude plugin install engine-sync@engine-sync`; when it lists `engine-sync@professor`, run `claude plugin uninstall engine-sync@professor`; then start a new Claude session so the plugin's wrapper links its binary; `~/.local/share/engine-sync/bin/engine-sync version` (or the binary `ENGINE_SYNC_BIN` names) prints 0.4.0 or later, and the same `jq` lists `engine-sync@engine-sync` as the only `engine-sync@` id.
#### → For: adopters who set `claude.plugins` · after update · `claude.plugins` — add `engine-sync` to `claude.plugins` in `pfm.config.json`, then `pfm install --yes`; `pfm doctor` prints no `claude.plugins omits engine-sync` line.
- pfm: chat call and MCP family names — `pfm chat inject` is now `pfm chat call` (the old verb prints `pfm chat: unknown command "inject"` and exits 2), and pfm's MCP servers are `chat-professor` and `harvester-professor`, so the tools read `mcp__chat-professor__*` (`call`, `read`, `digest`, `last`, `find`, `ls`, `status`, `whoami`, `new`, `save`) and `mcp__harvester-professor__*` (`read`, `download_file`, `search_literature`, `search_web`) where they read `mcp__professor__chat_*` and `mcp__professor__harvester_*`. `pfm install` replaces the `professor` registration it wrote in account `.claude.json` files and the Codex and OpenCode configs with the two family entries, keeps a `professor` entry it did not write (`preserve foreign … MCP client professor`), and restarts the MCP daemon, which serves `/mcp/chat-professor` and `/mcp/harvester-professor` and answers the old `/mcp/professor` routes with HTTP 410 and `restart the chat to reconnect with the current MCP registrations`. A chat started before the update has lost those tools until it restarts. A new chat's stdio start probes the daemon's status, then its family route, each probe bounded at 2 s, and serves the family in-process when the daemon lacks it.
#### → For: every adopter · after update · open chats — exit every Claude, Codex and OpenCode chat started before the update and every `pfm ls` picker, then open them again; in a reopened Claude chat `/mcp` lists `chat-professor` and `harvester-professor`.
- pfm: pfm codex and pfm opencode retired — both now exit 2 with `pfm: "pfm codex" is retired — run "engine-sync codex ..."; port this project's files with "pfm doctor --project-updates"` (and its `opencode` twin), where v0.81.0 forwarded them to engine-sync; `pfm install` links `~/.local/bin/engine-sync`, so `engine-sync codex build|check` and `engine-sync opencode build|doctor` run from your PATH.
#### → For: every adopter · after update · scripts, CI jobs and aliases — replace each pfm codex call with `engine-sync codex` and each pfm opencode call with `engine-sync opencode` in your own scripts, CI jobs and shell aliases; `command -v engine-sync` prints a path, and `rg -n 'pfm (codex|opencode)'` over those files prints nothing.
- pfm: engine-sync machine policy file — engine-sync 0.4.0 reads its machine policy from `~/.claude/engine-sync.json`, which `pfm install` renders on every install from the clone's `templates/global/engine-sync.json` and this host's targets, leaving the file alone once it no longer carries `"managedBy": "professor"`. The install removes a `~/.config/engine-sync/config.json` link into the clone and a `~/.config/engine-sync/targets.json` holding only pfm's keys (`codexHomes`, `claudeConfigDirs`, `sourceRepo`, `capabilities`), and leaves a `config.json` or `targets.json` you wrote, carrying none of its keys over. engine-sync refuses to run while an old file exists and the new one does not (`engine-sync: {path} is no longer read; move its keys …`), and `pfm doctor` reports a leftover old file as `old engine-sync machine config, no longer read while … exists`.
#### → For: adopters who wrote their own `~/.config/engine-sync/config.json` or `targets.json` · after update · `~/.config/engine-sync/` — note the keys you still need, then move each file aside, e.g. `mv ~/.config/engine-sync/config.json ~/.config/engine-sync/config.json.retired`; `ls ~/.config/engine-sync/config.json ~/.config/engine-sync/targets.json 2>/dev/null` prints nothing.
- Global: imagine family replaces ultimate — `/ultimate-spec` and the `ultimate` agent are removed: `/imagine:build` specs a vision through the new `imagine` agent and builds it with the new `imagination` agent (sonnet, xhigh), `/imagine:build-spec` writes the spec alone, `/imagine:build-fast` makes one piece in the chat, and `/imagine:callmeter` takes over callmeter's `/callmeter:ultimate-visualization`, exploring a read-only snapshot of the callmeter store before it runs `/imagine:build`. Every member loads the new `imagine-core` skill, whose live and visual rules sit in `imagine-core/live.md`, loaded only for pages, canvases and scenes. `/ultimate` stays, now a skill a user or a model invokes. A spawn of `ultimate` fails the moment the clone moves; one `pfm install --yes` removes the dangling `~/.claude/agents/ultimate.md`, `~/.claude/commands/ultimate.md` and `~/.claude/commands/ultimate-spec.md` links pfm made, and engine-sync retires the generated Codex role.
- Global: compaction tools — every machine-global agent whose `tools:` named `mcp__sub-agent-compact__compact` now names `mcp__sub-agent-compact__forward_handoff` and `mcp__sub-agent-compact__look_back` instead. sub-agent-compact 0.8.0, the version `plugins/sub-agent-compact` now pins, reads its options only from `SUB_AGENT_COMPACT_*` environment variables and registers `compact` and `look_back` by default, `forward_handoff` only with `SUB_AGENT_COMPACT_FORWARD_HANDOFF_TOOL` set to `1` or `true`, which also turns `compact` off, the main chat's included. With the defaults those agents can read back their own transcript but can neither compact nor hand off; a release `pfm install` never updates an installed plugin, so a host on an older sub-agent-compact keeps it.
#### → For: adopters who run sub-agent-compact · after update · sub-agent-compact plugin — when `jq -r .version "$(jq -r '.plugins["sub-agent-compact@sub-agent-compact"][0].installPath' ~/.claude/plugins/installed_plugins.json)/.claude-plugin/plugin.json"` prints a version below 0.8.0, run `claude plugin marketplace update sub-agent-compact` and `claude plugin update sub-agent-compact@sub-agent-compact`, then start a new Claude session; the same `jq` prints 0.8.0 or later.
#### → For: adopters whose agents should hand off · after update · `claude.env` — add `"SUB_AGENT_COMPACT_FORWARD_HANDOFF_TOOL": "true"` under `claude.env` in `pfm.config.json`, then `pfm config validate` exits 0 and `pfm install --yes` prints a `claude.env: {n} keys in {settings.json}` line; agents in a new Claude session hold `forward_handoff`.
- pfm: retired-name report — `pfm doctor --project-updates` now reports these under `RETIRED-NAME` (`path:line   name — retired kind, now {successor}`): `pfm chat inject` (now `pfm chat call`), `chat_inject` (now `mcp__chat-professor__call`), `mcp__professor__` (now `mcp__chat-professor__*` / `mcp__harvester-professor__*`), `pfm codex` and `pfm opencode` (now `engine-sync codex` / `engine-sync opencode`), `scripts/codex-sync.sh`, `/ultimate-spec` (now `/imagine:build`), `/callmeter:ultimate-visualization` (now `/imagine:callmeter`), the `ultimate` agent (now `imagine`), and v0.81.0's renames it did not report then, `gpt-foreman`, `gpt-lander`, `gpt-executor` (now `gpt-flights-foreman`, `gpt-flights-lander`, `gpt-flights-mechanical-executor`) and `terra` (no successor). A project that defines its own `ultimate` or `terra` agent is exempt, `/ultimate` has no row because it stays live, and the `mcp__chat__`, `mcp__harvester__` and `/chat:` rows now name the `-professor` tools. The report `pfm update` appends inside a project still comes from v0.81.0's pfm, without these rows; `pfm doctor --project-updates` shows them.
#### → For: every adopter · after update · custom prompts and agents — make the same replacements in your own files under `~/.claude`; `rg -n -e 'chat inject' -e 'chat_inject' -e 'mcp__professor__' -e 'pfm (codex|opencode)' -e 'ultimate-spec' -e 'ultimate-visualization' -e 'subagent_type: "?ultimate' ~/.claude/CLAUDE.md ~/.claude/agents ~/.claude/commands ~/.claude/skills 2>/dev/null` prints nothing left to change.

## Added

- Global: flights-speccer agent — the new machine-global `flights-speccer` (opus, xhigh) writes `spec.md` in the flight directory for novel, large work, the simplest design that meets the request with an existing tool first and every element priced in tokens against its real use; `flights-foreman` spawns it when its closest-pattern search finds none and builds from its `SPEC`. A buildable spec with an element left unbuilt returns `SPEC` with that element in `## Open`. With `claude.gptAgents`, `gpt-flights-speccer` runs it on GPT.
- Global: GPT research twins — with `claude.gptAgents` set, `gpt-rr`, `gpt-rr-pro` and `gpt-rr-pro-max` run `rr`, `rr-pro` and `rr-pro-max` on GPT sol at low, medium and medium effort, with the same tools, body, budget and save law; they are Claude-only, with no Codex or OpenCode mirror, and their `sub-rr` and `clone-distiller` diggers stay Claude agents. (opt-in)
- Global: tracer recall — every `tracer` spawn through pfm's intake hook carries `{RUN}/recall.txt`: earlier runs' answer lines on the same repository, re-checked against the tree now and marked `FRESH`, `DELTA`, `STALE`, `GAP` or `CHANGED`, with `ANSWERED Q{n}` for a question its fresh lines settle, capped at 12 KB with a `RECALL CUT` line; the tracer quotes fresh lines verbatim and traces only the rest, and intake refuses a `sub-tracer` card whose questions are all `ANSWERED` unless it carries `REASON:`. `tracetree.py recall ROOT [--since-hours N] [--before RUN]` prints the same.
- Global: flights cut and cut gate — `tracetree.py segment ROOT --seed …|--seeds FILE` cuts a door list into `SPINE` contracts and segments, each `DECIDE S{n} CHILD|KEEP`, ending `VERDICT SPLIT k | SOLO | EMPTY`. `flights-foreman` runs it right after its doors (step 4), saves the kit to `cut-kit.txt` and reads it whole, spawns each `CHILD` segment as a child foreman (three deep at most), keeps each `KEEP`, logs a checkable `OVERRIDE` for a `CHILD` it keeps, and logs a `run.md` `{unit} DONE` line per verified child. Its new `tracetree.py cutgate` PreToolUse hook denies a code edit, or a Bash write into the tree, until its transcript holds a `segment` run with a verdict other than `EMPTY`, caching under `~/.local/state/pfm/cutgate/`; `flights-foreman`, `flights-lander` and `flights-mechanical-executor` also attach pfm's `call-cap` hook.
- pfm: call-cap hook — `pfm internal call-cap`, a PreToolUse hook, counts the calling agent's model requests from its own transcript, compactions included, keeping a tally under `~/.local/state/pfm/call-cap/`; from four fifths of the agent's cap (foreman 250, lander 200, other roles 150) it injects `call-cap: {n} of your {cap} model requests used …`, and at the cap it orders the stop, never denying a tool.
- pfm: store-guard hook — every launch's settings, and `pfm install`'s, carry `pfm internal store-guard`, a PreToolUse Bash hook that denies a `claude` run whose `CLAUDE_CONFIG_DIR` is the shared store `~/.claude` or inside it (`Drop the CLAUDE_CONFIG_DIR override and run claude as it is …`); a command form it cannot read passes with a stderr line naming the cause.
- pfm: claude.env — `claude.env` in `pfm.config.json`, an object of upper-snake names to string values, is written by `pfm install` into the `env` of the primary account's `settings.json` (else the config dir's), tracking the keys it set so it removes one you delete while it still holds pfm's value and reports a value you set by hand that differs; it refuses `CACHE_LIVE_CONTROL_MAIN_TTL`, `CACHE_LIVE_CONTROL_AGENTS_TTL`, `CALLMETER_HOME` and `ENGINE_SYNC_HOME`, which a launch or pfm itself owns, and `pfm doctor`'s `claude_env` rows report missing and unknown keys. (opt-in)
- pfm: coverage acceptance — the retired-name scan reads up to 8 MiB per file and 4 MiB per line (v0.81.0 stopped at 1 MiB per file), and a file past either bound is an `INCOMPLETE` row that `pfm update accept <path> --coverage --reason "<why>"` now closes, `--undo` with `--coverage` reversing it; the report prints that command under every incomplete surface, a read failure stays an `UNREADABLE` row to fix, and a coverage rule cannot carry a name (`BASELINE-MALFORMED`). A project that records one gets a version-3 `.professor/baseline.json`, which v0.81.0's pfm reports as `UNREADABLE BASELINE-VERSION 3: unsupported`.
#### → For: every adopter · per project · `pfm doctor --project-updates` — after this note's other `per project` actions, close every remaining row with the verb its guide names, an `INCOMPLETE` row you have reviewed with `pfm update accept <path> --coverage --reason "<why>"`, and re-run until it ends `clean`.
- Repo: plugin-lab — `infra/plugin-lab` is an isolated live-test lab for plugin checkouts, with scenarios for sub-agent-compact, cache-live-control and effort-live-control (`docs/dev/testing/plugin-lab.md`).
- Repo: plugin-logs script — `scripts/plugin-logs.sh report|rotate [--dir D] [--archive YYYY-MM-DD] [--today YYYY-MM-DD] [--root R]` reads the folder `PLUGIN_LOG_DIR` or `--dir` names: `report` prints `plugin logs: {dir} · span: … · last rotate: … · contract-skipped: {n}`, an archive line when asked, then `ERRORS`, `WARNINGS` and `INFO`, and `rotate` renames the logs by date and prints `rotated: {dir} · {date}`; a missing folder exits 3, an unreadable one 4, and its scratch lives in `/tmp/{project}/{purpose}/`, refused when another user owns it or it is world-writable without the sticky bit. `scripts/test-plugin-logs.sh` is its fenced self-test.
