# v0.80.0 — 2026-10-12

This release needs two things on the host before `pfm update`: the separate engine-sync binary, which now writes the machine-global agent links and every Codex and OpenCode artifact, and `python3`, which the tracer's kit runs on; without either, the install that ends the update fails and the update rolls back. It renames commands and roles (`pfm price` is `pfm model-cost`, `/reminder` and `pfm chat reminder` are `/pfm:schedule` and `pfm chat schedule`, `/tokens` and the `transcript` skill are the `chatlog` skill, `close-out` is `done-herewith`, `tracer-rr` is `clone-distiller`) and moves each project's docs hub from `docs/agents/` to `docs/`. It adds a tracer that leads haiku sub-tracers over the checked `tracetree` kit, a durable record of flight work that finished without landing, a per-call cost ledger that is on by default, and `pfm chat watch --no-working`; the GPT twin agents ship in the clone, but `pfm install` does not link them in this release. Status line, installer, harvester and pricing fixes round it out, and the open issues accepted for this release are listed under Changed.

## Breaking

- pfm: engine-sync binary — `pfm install` renders the machine-global agent links and every Codex and OpenCode artifact through the separate `engine-sync` binary, and `pfm codex` and `pfm opencode` forward to it. On a host with a Professor clone or a configured Codex home, the install applies its other steps, then exits 1 with `engine-sync binary unavailable: …` and the repair `install the engine-sync plugin`, and `pfm update` rolls back on that error (exit 5). `pfm install` never installs engine-sync, `pfm update` does not check out the clone's `plugins/` submodules, and `pfm install --check` does not report the binary.
#### → For: every adopter · before update · engine-sync binary — run `claude plugin marketplace add rezzminator/professor` and `claude plugin install engine-sync@professor`, start a new Claude session so the plugin's hook downloads the release binary, checks it against the plugin's `SHA256SUMS` and links it, then `test -x ~/.local/share/engine-sync/bin/engine-sync && echo ok` prints `ok`.
#### → For: every adopter · after update · engine-sync version — when `pfm install --yes` or `pfm doctor` reports engine-sync `older than required`, run `claude plugin update engine-sync@professor`, start a new Claude session and rerun `pfm install --yes`; `pfm doctor` then prints no engine-sync `FAIL` row.
- pfm: python3 dependency — `pfm install --check`, the install preflight and `pfm doctor` require `python3` on Linux and macOS, as they do `git` and `tmux`, because the tracer's `tracetree` kit and its launch hook run on it; pfm checks it and never installs it. Without it the install that ends `pfm update` stops before its first write with `pfm install: required dependency preflight failed`, and the update rolls back. (cost)
#### → For: every adopter · before update · python3 — install `python3` with the system package manager if it is missing; `python3 --version` prints a version.
- pfm: renamed commands — `pfm price` is removed and answers `unknown command`; `pfm model-cost [--json] [--force] MODEL_ID | --all | --check` replaces it. `pfm chat reminder` is `pfm chat schedule` (`set`, `ls`, `rm`), with no alias. `node ~/.claude/commands/tokens/token-audit.mjs` is `pfm tokens`, with `--prices FILE` in place of `TOKEN_AUDIT_PRICES`, and `python3 ~/.claude/skills/transcript/transcript.py` is `pfm transcript`, with the same verbs, flags and failure text. A `pfm.prices.json` override now holds version-2 rows (USD per million tokens), and a key no model id resolves to is refused.
#### → For: adopters with scripts, aliases or schedulers that call the old names · after update · custom scripts — replace each old invocation with its successor; `rg -n 'pfm price|pfm chat reminder|token-audit\.mjs|TOKEN_AUDIT_PRICES|transcript\.py' ~/.claude/CLAUDE.md ~/.claude/agents ~/.claude/commands ~/.claude/skills 2>/dev/null` prints no reference left to change.
#### → For: adopters with a `pfm.prices.json` override · after update · `pfm.prices.json` — rewrite its rows in the version-2 shape, keyed by a model id `pfm model-cost --all` lists; `pfm doctor` then prints its prices row without a warning.
- Global: renamed and retired roles, commands and skills — `/reminder` is `/pfm:schedule`; the `/tokens` command (which Claude Code also listed as `/tokens:SKILL` and `/tokens:README`) and the `transcript` skill merge into the `chatlog` skill; the `close-out` skill is `done-herewith`; `tracer-rr` is `clone-distiller`, a general investigator of any external repository whose brief takes an optional `OUT-DIR:` in place of `RR-DIR:`; `tracer-pro` and `tracer-pro-max` are retired, leaving one `tracer`. The install that ends the update links the new names and removes the dead links under `~/.claude/{agents,commands,skills}` and the generated Codex roles of the retired agents; a real file or directory copy at a retired name is left in place.
#### → For: adopters with custom prompts, agents or scripts · after update · custom role, command and skill references — replace `/reminder` with `/pfm:schedule`, `/tokens` and the `transcript` skill with `chatlog`, `close-out` with `done-herewith`, `tracer-rr` with `clone-distiller`, and `tracer-pro` or `tracer-pro-max` with `tracer`; `rg -n '/reminder|/tokens|skills/transcript|close-out|tracer-rr|tracer-pro' ~/.claude/CLAUDE.md ~/.claude/agents ~/.claude/commands ~/.claude/skills 2>/dev/null` prints no reference left to change.
#### → For: adopters who scheduled reminders · after update · schedules — `pfm chat schedule ls` lists every reminder you had, carried over when the new pfm first opened its state database; recreate any missing one with `pfm chat schedule set`.

## Added

- Global: tracer and the tracetree kit — `tracer` (sonnet) looks wide once and hands each thread to a haiku `sub-tracer`, which writes its hops through the new `tracetree` skill; the kit re-checks every quoted line against disk, opens each view with a `WARNINGS` block naming any reader that broke the hop contract, maps a run as text, JSON or a self-contained HTML page, and serves `show`, `answer` and `book` views of a run. The new `/tracer:use` command is the caller's manual, and `reviewer`, `reviewer-pro`, `clone-distiller` and `flights-foreman` read runs through it.
- pfm: tracer intake hook — every Claude session pfm launches carries a `PreToolUse` hook on `Agent|Task` that opens a tracer spawn's run and adds `RUN:` to its brief; it is passed at launch, never written to `~/.claude/settings.json`, and fails open, letting the spawn go on without a run. `pfm doctor` proves it with a `tracer-intake` row: a missing `python3`, an unreadable kit or a failed smoke is a `FAIL` row naming the fix, and doctor exits 3. Each `Agent` call starts `python3` once, about 40–60 ms. (cost)
#### → For: every adopter · after update · tracer intake hook — run `pfm doctor`; its `tracer-intake` row reports `ok` with the `python3` path, the kit path and `smoke passed`, or names the fix to apply before rerunning `pfm doctor`.
- Global: GPT twin agents — `gpt-foreman`, `gpt-foreman-pro`, `gpt-lander`, `gpt-executor`, `sol`, `luna`, `terra` and `astra` are Claude agent definitions that run on GPT models for a host with a GPT route, opt-in through `claude.gptAgents` in `pfm.config.json` (default `false`); in this release `pfm install` does not pass that opt-in to engine-sync, so it links none of them even when the key is `true`. (opt-in)
- pfm: GPT twin hook scripts — every `pfm install` links `gpt-return-watch.py` and `gpt-agent-stop.py` into `hooks/` of `~/.claude`, the shared Claude store and each account's config directory, whatever `claude.gptAgents` says, and refuses an operator file already at that path, which fails the install; `pfm doctor` reports a missing or drifted script with `run pfm install --yes`.
#### → For: adopters with their own `gpt-return-watch.py` or `gpt-agent-stop.py` under a Claude config's `hooks/` · before update · `hooks/gpt-*.py` — move each such file aside; `ls ~/.claude/hooks/gpt-return-watch.py ~/.claude/hooks/gpt-agent-stop.py` reports both missing, and the same holds in each account's config directory.
- Global: new agents — `conflict-resolver` settles the conflicted files of a stopped merge, pull, stash pop or submodule merge for `gitter` alone and returns `RESOLVED` or `UNRESOLVED` with a row per file, a `dropped` change listed first; `reviewer-pro` is `reviewer` plus a hostile-input hunt, which `flights-lander` picks for a change that adds a sink; `foreman-pro` is `flights-foreman` on opus; `chat-investigator` hands a transcript digest over 30 KB to haiku `sub-investigator` readers; `clone-distiller` hands its code questions to `tracer`.
- Global: new commands and skills — `/housekeeping` classifies worktrees, branches and stashes as merged, landed or waiting and clears the landed through `gitter`; `/iterative-improvement` raises a target round by round against one metric fixed up front, keeping its lab under `$HOME/.local/state/pfm/iterative-improvement/`; `/context-audit` is a user-only audit of loaded-but-unused context, applied per row; the `chatlog` skill answers what a run did, what it cost and what a model costs across Claude, Codex and OpenCode; `done-herewith` is the closing sweep.
- Global: unlanded flight work — a flight whose gate passed without a commit order writes `UNLANDED.md` in its flight directory and returns `PARTIAL … UNLANDED` with a `LANDING` line instead of `DONE`; `/done-herewith` sweeps every worktree holding unlanded work and every `UNLANDED.md`, and `/housekeeping` inventories them.
- pfm: cost ledger — on by default, each interactive Claude session pfm launches runs under `pfm internal cost-launch` and exports Claude Code's OpenTelemetry events (`CLAUDE_CODE_ENABLE_TELEMETRY=1`, OTLP to `127.0.0.1`) to a local sink, which writes one priced row per API call under `~/.local/state/pfm/cost-ledger` (`PFM_COST_LEDGER_DIR` overrides it). The status line shows one dollar figure, adding a resumed or pre-ledger chat's earlier spend; `pfm tokens` splits side calls per agent and query source; `pfm doctor` prints a `cost ledger` row; an unreadable `settings.json` keeps the ledger off. (cost)

## Fixed

- pfm: installer and doctor — `pfm install` keeps a user's own file or directory at a shipped name and replaces only a proven byte-equal copy, which `pfm doctor` reports as `COPY`; it reloads a launch agent a binary swap left stale instead of reporting the MCP daemon running, retires the orphaned migrations journal and 30-day-old backups and archives, and uninstall finishes every unwire step after an engine-sync failure; doctor's harness-prompt capture runs in its throwaway config directory, so a settings-level `ANTHROPIC_BASE_URL` no longer fails it, and hook, runtime-state and ownership rows report their real state.
- pfm: pricing — the price refresh keeps generation-range and preview labels without inventing a model, prices modeless OpenAI grouped tables as standard, and ties its once-a-day stamp to the binary that parsed the pages; gateway-served gpt sub-agents, advisor calls and interleaved responses are priced and counted once in the status line and `pfm tokens`; from the next update on, an update rollback restores a refreshed price table.
- pfm: chat and fleet state — a promptless `pfm chat branch` fork is a live row named by its branch, and branch refuses instead of guessing the parent account when several are configured; `pfm archive` relocates a transcript as one guarded transaction; transcript tail readers read past an over-long last line; account 0 opens on the default cache; kill, inject and run-accounting defects are closed, and `pfm.db` stays at schema v3 so an older pfm still opens it.
- pfm: harvester reliability — the failed-walk cache race and the races a chaos suite found are closed, a cancelled sidecar logs at INFO instead of ERROR, superseded harvester environments are pruned, and the harvester cache sweeps daily (30 days, 2048 MB).
