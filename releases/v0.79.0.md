# v0.79.0 — 2026-10-07

This release renames the research tiers, retires the old flights cast and built-in callmeter, and requires custom references to those names to move with it. It adds nested workbenches, the fleet-deck picker, recurring chat reminders, account synchronization, self-landing flights with one lander per flight, and a larger set of tracing and quality tools. The update also hardens chat delivery, project-template adoption, installation, and harvesting while preserving the final installer model: managed Claude plugins install once through the selected primary account, with no install journal or `pfm install --rollback` promise.

## Breaking

- Global: renamed and retired roles and commands — `super-rr` is now `rr-pro`, `heavy-rr` is now `rr-pro-max`, and `collector-rr`, `mapper`, `flights-speccer`, `flights-orchestrator`, `general-orchestrator`, `general-mechanical-executor`, `flights:orchestrate-live` and `flights:orchestrate-nested` are retired; `flights-foreman` owns the flight from build through landing.
#### → For: adopters with custom prompts or scripts · after update · custom role and command references — replace the retired names with `rr`, `rr-pro`, `rr-pro-max`, `tracer`, or `flights-foreman` as appropriate; `rg -n 'super-rr|heavy-rr|collector-rr|mapper|flights-(speccer|orchestrator)|general-(orchestrator|mechanical-executor)|orchestrate-(live|nested)' ~/.claude ~/.codex 2>/dev/null` prints no remaining custom references.
- pfm: callmeter command — the built-in callmeter and its hook are removed; callmeter continues as the standalone Claude Code plugin.
#### → For: adopters who used the built-in callmeter · after update · Claude Code plugins — run `claude plugin marketplace add rezzminator/professor` and `claude plugin install callmeter@professor`; `claude plugin list` shows `callmeter@professor` enabled.

## Added

- pfm: workbenches and fleet deck — `/pfm:workbench` creates or adopts nested sub-projects marked by `.professor/workbench.json`; their persona, engine mirrors and numbered chats stay distinct while the picker groups them beneath the parent project. The picker is now a fleet deck with per-row model and effort, working-state orbit, panels, arrival and refresh cues, and a 30 fps renderer.
- pfm: chat reminders — `pfm chat reminder` and `/reminder` schedule recurring prompts against a chat lineage; a fire resumes an exited chat, injects the prompt, and pins its picker row until opened.
#### → For: every adopter · after update · reminder scheduler — run `pfm install --yes`, then `pfm doctor`; the reminder scheduler row reports `ok` before creating reminders with `/reminder` or `pfm chat reminder`.
- pfm: account synchronization — Claude accounts share one session store while retaining identity-only account data; launches carry their pfm names, live renames are read back, and read-only host checks name operator-owned conflicts without rewriting them.
#### → For: every adopter · after update · Claude account wiring — run `pfm install --yes`, then `pfm doctor`; all account, shared-store and launch rows report `ok` or an intentional ignored warning.
- pfm: project updates — `pfm doctor --project-updates` reports `UPDATED`, `NEW`, `GONE-UPSTREAM` and `LOCAL-DELETED` with upstream intent; `pfm init --render` fills placeholders once and `pfm update adopt|pin|ignore|drop` records each decision. The compatibility alias `pfm update check` now prints the same report and points to the current command; bare `pfm update` returns 5 for an update/configuration failure before the project report, whose verdicts remain 0 clean, 1 review and 3 failure.
- pfm: chat and MCP tools — `chat_new` routes chat and model launches through MCP with the agent role, `chat_digest` returns one line per transcript event, `pfm chat new --harness-prompt PATH` launches a Claude seat on another system prompt, and multi-seat watch reports blocked, sub-agent, interrupt and quiet-working states.
- pfm: source-fetched skills and Claude plugins — `pfm install` fetches registered host-global skills into its managed store and links them into the active Claude skills directory and `~/.agents/skills`; it installs `cache-live-control`, `sub-agent-compact` and `agent-effort` once through the selected primary Claude account. `god-speed` is delivered as a source-fetched skill. #### → For: every adopter · after update · managed skills and plugins — run `pfm install --yes`, then `pfm doctor`; every `skill-source` and `claude_plugins` row reports `ok`.

- pfm: harvester — LinkedIn entities render from signed-out page data while login, sign-up and bot walls retain their failure kind; Wayback copies identify the archive source, and parallel reads use a bounded converter pool with per-conversion deadlines and cancellation.
- Global: flights — `flights:init` maps build units and their commands, `flights-foreman` batches work by project and area, one `flights-lander` runs each project's full suite once, and a finished flight lands through the repository's own merge rules.
- Global: tracing and completion tools — `tracer-rr`, `agent-optimizer`, `chat-investigator`, the `transcript` skill, `quality:claude-md`, `github-marketing`, `ultimate`, and `close-out` join the machine-global tools; transcript targets accept chat names and can list agents.
- Global: Codex role settings — `codex-model` and `codex-effort` frontmatter select Codex twins, measured executor tiers pin their models and effort, and an unmapped plain `model` value now refuses the build with the available map keys.
- Repo: marketplace and community — Professor is a Claude Code plugin marketplace and now carries contributor, conduct, support and issue/PR entry points plus listings for cache-live-control, agent-effort, buddy and callmeter.

## Changed

- pfm: update and installation behavior — updates serialize the source and host operations, preserve operator state on rollback, and show truthful residue; these updater protections first govern the update after v0.79.0 because the move onto this release is driven by the previously installed binary. `pfm install --check` previews host checks and scheduler gates, and the final installer performs no legacy config/database migration and exposes no install journal or `pfm install --rollback` command.
#### → For: every adopter · after update · pfm installation — run `pfm install --yes`, then `pfm doctor`; follow every printed fix until `pfm doctor` exits 0.
- pfm: probes and validation — MCP daemon probes allow 2 seconds, classify timeouts as unresponsive, retry dial errors through the retry window, and may spend one final dial beyond it; probe homes younger than 10 minutes are excluded from leak warnings. Project-update object names must be 4–64 hexadecimal characters, a regular file named `.professor` walks discovery to its parent, render refuses symlink escapes, and OpenCode mirror failures distinguish rebuildable output.
