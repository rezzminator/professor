# git-guard

`git-guard` is the machine-global `PreToolUse` hook on `Bash` that holds one rule at the call instead of in the prompt: only `gitter` writes shared git state, and a repository's `worktree.sh` is the main chat's alone ([Who is exempt](#who-is-exempt)). Body: `pfm/internal/hookentry/git_guard.go`. The fleet's other hooks, the ownership rule and the `pfm doctor` check that proves each hook is installed live in [hooks.md](hooks.md); there `git-guard` is one row of the inventory.

Decisions live in this file. A change lands here first, then in the code, then in every surface under [Surfaces that stay in sync](#surfaces-that-stay-in-sync).

## Why

An agent that made its own worktree left it behind: nothing tore it down, and stale worktrees and branches piled up in every repository. A prompt rule ("only gitter writes git") was read and then broken; a hook is not.

## Where it runs

`claudelaunch.HookTemplates` names it — event `PreToolUse`, matcher `Bash`, command `pfm internal git-guard` (`pfm/internal/claudelaunch/hooks.go:48`) — and `claudelaunch.Render` carries it in the launch-line `--settings` of every Claude chat a pfm door starts ([hooks.md](hooks.md)); `pfm doctor` spawn-audit expects it in each live chat's payload like every pfm hook. It is an internal verb (`pfm/cmd/pfm/main.go:78`, dispatched at `:476`). Because it rides every launch and not one project's settings, it runs in every repository, whether pfm manages it or not.

Codex and OpenCode carry no git-guard, and their `gitter` role writes no git either: their [engine-guard](engine-guard.md) judges git by the same reading and denies every git write to every caller.

## Who is exempt

A payload whose `agent_type` is exactly `gitter` is always allowed (`git_guard.go:33`, checked at `:138`). The hook reads only the name, so any gitter qualifies: a project's own (`.claude/agents/gitter.md`, scaffolded from `templates/project/agents/gitter.md`) or the machine-global one (`templates/global/agents/gitter.md`, which `pfm install` links into every account and a project's own gitter overrides by name). Every other caller is checked, a main chat (no `agent_type`) included, with one allowance below.

A repository's worktree script is the main chat's alone. `GitGuard` passes `mainChat = hook.AgentID == ""` to `gitGuardCheck` (`:141`); `agent_id` is set by Claude Code only inside a sub-agent (`gitGuardHookInput.AgentID`). `gitGuardPart` (`:241`) reads a run of the script as a part whose program ends `.claude/scripts/worktree.sh`, or whose program is a shell (`gitGuardScriptRunners`: `bash`, `sh`, `zsh`, `dash`, `ksh`, `source`, `.`) with an argument ending so, with any verb or none; a program that only reads the file (`cat`, `grep`) runs no script. It lets the run through when all hold:

- The script is found: its path is absolute, or every directory change before it is one the guard follows. `gitGuardCheck` starts from the hook `cwd` and follows each `cd` part in order (`gitGuardChdir`, `:280`): `cd ABS`, `cd REL` joined onto the directory so far, `cd`, `cd ~` and `cd ~/x` from `HOME`, `cd $HOME/x` (the parse is seeded with `HOME`). It stops following at the first change it cannot follow: a `pushd` or `popd`, `cd -`, a target holding an expansion the parse cannot know (`cd $D`), or a `cd` that is not `Lasting` (cmdparse: a `cd` in a subshell, a pipeline, a background job, a `-c` or `eval` string, an `if`, `case` or loop body, or on the right of `&&` or `||`, whose reach the parts after it cannot count on). After that a relative script path is unfound and denied, and the deny names the change (`gitGuardLost`, `:43`). So `cd /repo && .claude/scripts/worktree.sh create x` and `cd /tmp && /repo/.claude/scripts/worktree.sh list` pass while that script is committed, and `(cd /repo); .claude/scripts/worktree.sh list` and `true && cd /repo; …` are denied.
- The engine reading is off: Codex and OpenCode call `gitGuardCheck(…, true, false, …)` and block every script run.
- The script path, resolved against that directory with `gitGuardJoin`, is absolute and `gitGuardScriptCommitted` (`:305`) proves it committed: `engineGuardCommitted` finds git tracking the script unchanged from HEAD, and, when a `worktree/` directory sits beside it (the helpers an adopter's script sources as its verbs), `git status --porcelain --untracked-files=all --ignored` reports no modified, staged, untracked or ignored file in it. No caller widens the allowance by editing the script or a helper first.

There is no verb exception: every verb, `list`, `prune` and `--discard` included, is the main chat's while those hold, and denied to every sub-agent and to the main chat when one fails; the deny sends the caller to gitter.

## How it reads a command

A non-Bash tool returns at once (`git_guard.go:138`). Every Bash command goes through the shell parser (`pfm/internal/cmdparse`), so a `git` spelled through quotes (`g''it push`) is read as `git`; the parser unwraps wrappers (`timeout`, `env`), follows `&&`, `;`, pipes and subshells, resolves literal variables (`G=git; $G push` is a `git` call) and word-splits an unquoted one standing alone (`c="status --short"; git $c` is `git status --short`), parses an inner `bash`, `sh`, `zsh`, `dash` or `ksh -c` string and an `eval`'s words joined as shell, emits the command of a `find -exec`, `-execdir`, `-ok` or `-okdir` (up to `;`, or `+` after `{}`) as its own part, and walks a `for` loop's body once per literal item with the variable bound to that item (`for c in status commit; do git $c; done` is `git status`, then `git commit`; a loop over a word it cannot know, or nested past 64 body walks, has its variable unbound); a heredoc body and an `echo git …` argument are data, never a git call. The parser expands brace lists but never a glob: an unquoted `*` reaches the guard as the literal `*`, never as the file names a shell would expand it to. A pathspec is wide (`gitGuardAnyWide`, `:566`) when it is `.`, `:/`, `*`, `:(top)` or a path resolving to the repository's top level, or an all-star glob (`gitGuardAllStarGlob`, `:598`): with one leading magic prefix (`:(…)`, `:/` or a lone `:`) and a leading `./` stripped and a trailing `/` trimmed, its `/`-separated elements after the literal prefix (the elements before the first holding `*` or `?`) are at least one, each only `*` and `?` with at least one `*`, and that prefix is empty, `.`, or resolves to the top level. So `?*`, `**`, `./*`, `:(glob)**`, `**/*` and `{top}/*` are wide; `src/*`, `*.go` and `.*` are not. One `checkout` operand that is not an existing path is a branch or revision whatever glob characters it carries, since a commit expression (`HEAD^{/fi.*}`, `:/fi.*`) may hold `*`, `?` or `[` (`gitGuardCheckout`, `:427`). Two bounds keep any command from holding the hook: a command over 64 KiB (`maxCommandBytes`) is one unparsed part never handed to the shell parser, and a literal `-c` string nested past 8 levels (`maxShellDepth`) is one unparsed part in place of its parse; the parser marks each `Bounded`. For each part whose program is `git`, git's global options (`-C`, `-c`, `--git-dir`, `--work-tree`, `--no-pager` and the rest) are skipped, `-C` naming the repository, joined onto the directory the command's `cd` parts lead to (`gitGuardSplit`, `git_guard.go:327`); the subcommand and its arguments decide (`gitGuardBlocks`, `:357`).

## What it blocks

| Area | Blocked | Allowed |
| --- | --- | --- |
| worktrees | every `worktree` form but `list` (bare `worktree`, `add`, `remove`, `prune`, `move`, `lock`, `unlock`, `repair`, anything newer); every run of `.claude/scripts/worktree.sh`, any verb or none | `worktree list`; the main chat's run of `worktree.sh`, any verb, under the conditions of [Who is exempt](#who-is-exempt) |
| history | `commit`, `merge`, `rebase`, `cherry-pick`, `revert`, `am`, `pull`; every `reset` (a mode, a commit, paths, or bare); `reflog` but its reads | `log`, `show`, `diff` and every other read; `reflog`, `reflog show`, `reflog exists` (`engineGuardGitReflogReads`) |
| branches and tags | `switch`; `checkout -b`, `-B`, `--orphan`, `--track`, `--detach`, or one operand that is not an existing path, glob characters or not (a branch or revision switch); `branch` with a name or `-d`, `-D`, `-m`, `-M`, `-c`, `-f`, `-u`; `tag` with a name or `-d`, `-a`, `-s`, `-m`, `-f`; `update-ref`; `symbolic-ref` with two operands or `-d` | `branch` bare, `--list`, `-a`, `-r`, `-v`, `--show-current`, `--contains`, `--merged`, `--no-merged`; `tag` bare, `-l`, `--list`, `--contains`, `--points-at`; `symbolic-ref HEAD` |
| remotes | `push`, `fetch`; every `remote` form but its reads (`add`, `remove`, `rename`, `set-url`, `set-head`, `set-branches`, `prune`, `update`, anything newer) | `remote`, `remote -v`, `remote show`, `remote get-url` (`gitGuardRemoteReads`); `ls-remote` |
| staging | `add`, `rm`, `mv`, `restore --staged` / `-S`, `apply --index` / `--cached` / `--3way`, `update-index`, `hash-object -w` | `add -n`, `rm -n` (`--dry-run`); `apply` to the working tree, `apply --check`; `hash-object` |
| whole-tree destruction | `stash` with no pathspec (bare, `push` or flags without paths, `save`), `stash drop`, `clear`, `store`, `branch`; `clean`; `checkout`, `restore` or `stash push` of `.`, `:/`, `*`, an all-star glob (`?*`, `**`, `./*`, `:(glob)**`, `**/*`) or the repository root | `stash push -- <paths>`, `stash pop`, `apply`, `list`, `show`; `clean -n`; `checkout -- <file>`, `checkout -- *.txt`, `restore <file>` |
| repository settings | a `config` write: a write flag (`--add`, `--unset`, `--edit`, …), any git 2.46 subcommand but `get` and `list` (`set`, `unset`, `edit`, `rename-section`, `remove-section`, anything newer: a first operand with no dot, never a key), or a key given a value (`gitGuardConfigWrite`, `:477`); `gc`, `prune`, `filter-branch`, `filter-repo`, `replace`; `notes` except `show` and `list`; every `submodule` form but its reads (`add`, `update`, `init`, `deinit`, `sync`, `set-url`, `set-branch`, `absorbgitdirs`, anything newer), and a `submodule foreach` whose command the same judge denies | `config --get user.name`, `config --get-regexp`, `config -l`, `config user.name`, `config get`, `config list`; `notes show`; `submodule` bare, `status`, `summary` (`gitGuardSubmoduleReads`), and `submodule foreach` running a read: its words after `foreach` and its `--quiet`/`--recursive` flags, joined, go back through `gitGuardCheck` (`gitGuardForeach`, `:417`), so `submodule --quiet foreach 'git log -1'` passes and `submodule foreach 'git commit -m x'` is denied |

Git reads by allowlist, and so do `worktree`, `remote` and `submodule`: a form their read list does not name is blocked. A subcommand no row judges is allowed only when `engineGuardGitReads` (`pfm/internal/hookentry/engine_guard.go:116`), the one read list Claude and the engines share, names it, so `archive`, `bisect`, `sparse-checkout`, `init` and an alias are blocked; bare `git` with only global options (`git --version`) is allowed. A single-path stash stays open on purpose: an agent parks its own file and restores it, which touches nobody else's work.

## The deny

One message names every blocked part of the call as its words read, then `Only gitter writes this: spawn Agent(subagent_type: "gitter") with the repo path and the exact change. Never retry, rephrase, split or wrap the denied command to get past the guard.` (`git_guard.go:35-36`, the one line of the project-tier `git-writes-through-gitter` rule a sub-agent, which never reads that main-chat rule, needs; composed by `gitGuardReason`, `:654`). A worktree block adds the right way for its repository: the `-C` directory, else the payload's `cwd`, walked up to the directory holding a `.git` entry without running git (`gitGuardTopLevel`, `:632`). When that repository has `.claude/scripts/worktree.sh`, the line reads `worktrees go through {repo}/.claude/scripts/worktree.sh — the main chat's alone, run while git tracks it (and its worktree/ helpers) unchanged from HEAD; every other caller goes to gitter.` (`:675-676`); otherwise `gitter creates and removes worktrees (Phase SETUP).` (`:40`). A blocked `git stash` adds, once, ``To park only your own files, `git stash push -- <path>...` is allowed (restore with `git stash pop`); a whole-tree stash moves every other agent's uncommitted work.`` (`gitGuardStashHint`, `:48-50`), so an agent parking its own files to watch a test fail against the unchanged code stashes those paths instead of giving up. A main chat's worktree script denied only because a directory change before it could not be followed adds ``git-guard cannot follow `{change}` to the worktree script it runs: run the script by its absolute path, without the directory change.`` (`gitGuardLost`, `:43`), naming the change as written (`cd $D`, `pushd /repo`, a subshell's `cd /repo`).

## How it fails

- **Payload unreadable or undecodable:** one `pfm internal git-guard: … (fail-open)` stderr line, the call allowed, like every pfm hook (`git_guard.go:125-137`).
- **The parser itself errors:** fail-open the same way (`:161-167`); a parser failure must never freeze every Bash call on the machine.
- **One part of the command does not parse, and the command mentions git:** denied with `could not read this command; split it so each git call is its own simple command.` alone, without the gitter line, whose "never split" would forbid the fix (`:37`, decided at `:182-184`), because allowing it would let any git write through by breaking the quoting. A command mentions git when it holds the token `git` with the string's edge or a non-word character (anything outside `[A-Za-z0-9_]`) on each side — `git push`, `"git"`, `git;`, `git<`, `git` before a tab or newline — or `.claude/scripts/worktree.sh` (`gitGuardMentionsGit`, `:211`). `digits`, `legit` and `mygit` are not git, so an unparsable command whose only `git` sits inside a word is allowed.
- **A `bash`, `sh`, `zsh`, `dash` or `ksh -c` string, or an `eval`'s words, the parser cannot know, and the command mentions git:** denied with the same reason (decided at `:187`). The parser marks such a part `Unread` and parses none of the string, so the commands it runs are among no part: `bash -c "git push $X"` is denied, while `bash -c "echo $X legit"` mentions no git and is allowed.
- **A parse bound cut the command short:** denied whenever the command holds `git` or `worktree.sh`, even inside a word, with ``could not read this command in full: it passes a parse bound (over 64 KiB, or a `-c` string nested past 8 levels). Shorten the command; write long content to a file with the Write tool.`` (`gitGuardBounded`, `:38-39`, decided at `:176-180`). Past a bound nothing is read, so no spelling of git (`"git" push`, `'git' push`, `G=git; $G push`) can be told from the text around it. The reason never tells the agent to split git calls the command may not hold, and alone it adds no gitter line: a shortened command is read and judged like any other.
- **The deny cannot be written:** stderr line and exit 1 (`:145-148`).

## Named gaps

- **Python snippets.** The parser no longer reads Python, so `python -c` and heredoc Python are not inspected and the hook never spawns `python3`; a git call made from inside Python (`subprocess.run(["git", "push"])`) is not seen by the guard.
- **Unresolved words.** A `$VAR` or other word the parser cannot resolve is read as written, so `git $CMD` passes unless its literal words are a blocked form.
- **Obfuscated git in an unparsable command.** A command that does not parse and spells git only through quoting or escapes (`g\it`, `"gi"t`) does not mention git, so it is allowed.
- **A glob program word.** Globs are never expanded, so `/usr/bin/gi? push` runs Program `/usr/bin/gi?`, not `git`, and is allowed.
- **An absolute glob naming the root.** `git checkout -- /abs/rep?` names the repository root only once expanded; read literally it resolves to no top level, so it is not wide.
- **Split values beside text.** An unquoted `$X` holding a blank is split only when it stands alone in its word; `x$X` is read as written, unresolved.
- **Command substitution as the program.** `$(which git) push` leaves its program word unresolved, read as written with status OK, and is allowed.
- **An empty brace alternative.** `{git,} push` expands to Program `git` with an empty first argument, read as the subcommand, so `push` is never judged.
- **Unknown wrappers.** `env -S`, `stdbuf`, `caffeinate` and `flock` are not unwrapped, so a git call behind one is not seen.
- **ANSI-C quoting.** `$'\x67it'` is taken as its raw text, never decoded to `git`.
- **Uncapped arrays.** Arrays expand without a cost cap, so a command built to expand hugely can hold the hook; `for` loops stop at 64 body walks.
- **CDPATH.** A relative `cd` is joined onto the directory so far; a `CDPATH` that would send it elsewhere is not read.
- **Last assignment wins.** A variable keeps its last literal assignment across subshells and both arms of a conditional, so `$G` may resolve to a value the shell would not hold there.
- **Wide globs outside the all-star rule.** A bracket or mixed glob that still covers the whole tree (`[a-z]*`) is not read as wide.
- **Exclude-only pathspecs.** git reads a pathspec list of only exclusions (`':!a.txt'`) as the whole tree minus them; the guard does not read it as wide.
