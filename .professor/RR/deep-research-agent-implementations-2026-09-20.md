# RR — Implementations and techniques of "deep research" agents that dig the whole internet to answer one query

Question: implementations of "deep research" agents — an LLM agent that digs the whole internet to answer one query (search, fetch, follow leads/rabbit holes, fan out sub-agents, synthesize a cited report). Collect the different NOVEL implementations and techniques people have actually built and reported working.

---

## The answer in two sentences

The field has converged on four distinct architectures — a single long-horizon loop (OpenAI DR, Kimi-Researcher, Step-DeepResearch), a lead-plus-workers orchestrator (Anthropic, LangChain ODR, GPT-Researcher, Onyx), a graph/queue frontier (Jina's FIFO gap queue, Devin's deterministic MapReduce, Argus's shared evidence DAG), and RL-trained research *models* (Search-R1, WebSailor/Tongyi, MiroThinker) — and the single loop with aggressive context compaction now sits within ~1.4 points of the best multi-agent entry at the top of BrowseComp, so orchestration is no longer the main lever. The techniques with real measured payoff are narrower than the hype: context compaction and offloading, self-contained non-overlapping sub-agent briefs, verbatim (not summarized) sub-agent returns, a post-hoc citation-verification tool, URL-level evidence deduplication, and width-over-depth fan-out — while intermediate retrieval rewards, prompt-level trusted-domain allow-lists, and simply doing more tool calls are all reported to *hurt*.

## 1. Proprietary systems

**OpenAI Deep Research.** A single-loop agent on an o3 variant "trained using end-to-end reinforcement learning on hard browsing and reasoning tasks," learning to plan, backtrack and react to live information, with browser + Python tools and sentence-level citations ([OpenAI](https://openai.com/index/introducing-deep-research/)). HLE 26.6% (vs o3-mini-high 13.0), GAIA 67.36 avg pass@1 / 72.57 cons@64. Budget is compute-shaped (5–30 min), and the announcement publishes a "pass rate vs max tool calls" scaling curve whose data is not in text. Stated limits: hallucination, poor confidence calibration, difficulty separating authoritative sources from rumor. The promised system card is UNVERIFIED — not located.

**Gemini Deep Research.** Explicit plan-then-execute: the user reviews and refines a research plan before execution, and the model "intelligently determines which subtasks can be tackled simultaneously" under an asynchronous task manager that survives client disconnect ([Gemini](https://gemini.google/overview/deep-research/), [API docs](https://ai.google.dev/gemini-api/docs/interactions/deep-research.md.txt)). API mandates `background=true`; tools are Google Search, URL Context, Code Execution, plus MCP and File Search; 60-minute cap, ~$1–3/task standard and ~$3–7 Max. Citations return as a field Google tells developers to verify themselves. It carries by far the highest effective-citation count on DeepResearch Bench (165.34) at 78.30 citation accuracy. No RL claim anywhere; the "shared planner/task state with graceful error recovery" claim is UNVERIFIED at any Google source.

**Perplexity Deep Research.** A prompt-level iterative loop — "iteratively searches, reads documents, and reasons about what to do next, refining its research plan as it learns" — then a separate synthesis pass; dozens of searches over hundreds of sources, most tasks under 3 minutes ([Perplexity](https://www.perplexity.ai/hub/blog/introducing-perplexity-deep-research)). HLE 21.1%, SimpleQA 93.9%. No base model, context strategy, or verification technique disclosed — the thinnest architecture documentation of the majors.

**Kimi-Researcher (Moonshot).** Explicitly rejects multi-agent role assignment in favour of one agent trained end-to-end with agentic RL over three tools (parallel internal search, text browser, code execution) ([Moonshot](https://moonshotai.github.io/Kimi-Researcher/)). Techniques: REINFORCE with strict on-policy rollouts (tool-call format enforcers disabled), negative-sample discarding against entropy collapse, gamma-decay reward r·γ^(T−i) favouring shorter trajectories, and a context manager that discards spent documents — worth +30% more rollout iterations in ablation. Infra: Gym-like async rollouts and turn-level partial rollouts replayed with updated weights, ≥1.5x speedup. HLE 26.9% pass@1 from an 8.6% start, 40.17% pass@4, xbench-DeepSearch 69%; behaviourally ~23 reasoning steps, 200+ URLs, 70+ queries per task.

**Step-DeepResearch (arXiv 2512.20491).** A single-agent ReAct 32B (Qwen2.5-32B base) whose novelty is context mechanics: patch-based file editing (−70% output tokens), implicit context offloading with **demand-paging to disk for "virtually infinite context,"** and a stateful todo tool ([HTML v4](https://arxiv.org/html/2512.20491v4)). Training is agentic mid-training 32K→128K (150B tokens) → SFT with strict citation formatting → PPO with a Checklist/Rubrics Judge and binary rubric rewards. 61.42 on ResearchRubrics, comparable to OpenAI/Gemini DR; notably reports **no BrowseComp number**.

**Grok DeepSearch — dead end.** No primary technical documentation found; "4-agent Society of Mind" claims are third-party and UNVERIFIED ([DeepWiki mirror](https://deepwiki.com/xai-org/grok-prompts/3-deepsearch-feature)). Exa is the one vendor in this tier with real engineering writing (below). Elicit's report modes, Consensus, You.com, Manus: no primary technical docs surfaced.

## 2. The orchestrator-worker school

**Anthropic's multi-agent research system** is the reference design ([Anthropic](https://www.anthropic.com/engineering/multi-agent-research-system)). Opus 4 lead + Sonnet 4 subagents; lead decomposes into subtasks each carrying **objective, output format, tool/source guidance, and explicit boundaries**; effort scales by rule (1 agent/3–10 calls simple; 2–4 subagents × 10–15 calls for comparisons; 10+ for complex); 3–5 parallel subagents each making parallel tool calls cut research time up to 90%. Context: plan externalized to memory before the 200K truncation point, subagents writing artifacts to the filesystem and passing lightweight references back. A dedicated **CitationAgent** post-processes documents and report to attach claims to sources. Evidence: +90.2% over single-agent Opus 4 on an internal eval (methodology undisclosed), ~15x chat token cost, and the striking finding that **token usage alone explains 80% of performance variance** (tool calls + model choice the next 15%). Its failure list is the field's best: 50 subagents spawned for simple queries, three subagents duplicating identical searches, endless hunts for nonexistent sources, over-specific opening queries, and consistent preference for SEO content farms over authoritative sources.

**LangChain open_deep_research** is the same shape with published prompts ([repo](https://github.com/langchain-ai/open_deep_research), [blog](https://www.langchain.com/blog/open-deep-research), [prompts.py](https://raw.githubusercontent.com/langchain-ai/open_deep_research/main/src/open_deep_research/prompts.py)). Three phases: Scope (clarification JSON → a first-person research brief that forbids invented constraints and names source preferences), Research (supervisor with exactly three tools — `ConductResearch`, `ResearchComplete`, `think_tool` — where `think_tool` is mandatory before delegating and after every result), Write (one-shot). Control rules are explicit: **"Bias towards single agent"** unless parallelization is clear, caps on supervisor iterations and concurrent units, "delegate clear, distinct, non-overlapping subtopics," and each instruction must be standalone because "sub-agents can't see other agents' work." Researchers carry their own budget (2–3 searches simple, ≤5 complex) and a convergence stop: *"Your last 2 searches returned similar information."* Compression is **anti-summarization** — rewrite verbatim, "DO NOT summarize," emit Queries/Findings/All Relevant Sources, because a later LLM merges reports and losing sources is the named failure. Four model roles (summarization gpt-4.1-mini, research/compression/report gpt-4.1). DeepResearch Bench RACE 0.4309 at $45.98 / 58M tokens, 0.4401 at $187.09 with Sonnet 4, 0.4943 with GPT-5 — a 4x cost spread buying ~2 RACE points. LangChain's deepagents runtime adds mechanical compaction: offload tool I/O >20K tokens to files at 85% context utilization, summarize at 85% of max input keeping 10% recent ([docs](https://docs.langchain.com/oss/python/deepagents/context-engineering)).

**GPT-Researcher.** Planner → one crawler agent per sub-question in parallel, each resource summarized and source-tracked → publisher aggregating 20+ sources ([repo](https://github.com/assafelovic/gpt-researcher)). Deep mode is a recursive tree: breadth 4 parallel paths per level, depth 2, concurrency 4, failed queries silently skipped ([docs](https://docs.gptr.dev/docs/gpt-researcher/gptr/deep_research)). ~5 minutes and ~$0.40 per deep run on o3-mini. Tavily default with JS-enabled scraping and MCP. Its real-world breakage is documented: [#1386](https://github.com/assafelovic/gpt-researcher/issues/1386) accumulated context blowing a TPM ceiling, [#1332](https://github.com/assafelovic/gpt-researcher/issues/1332) a crash *inside the context trimmer* making deep mode "always error out."

**Onyx** is architecturally contrarian: a deliberately **shallow ≤2-level pipeline** (clarify → plan → orchestrator → research sub-agents → intermediate + final report) where the orchestrator only gathers and delegates and **never searches itself**, to avoid what it calls "deep-frying" ([blog](https://www.onyx.app/blog/building-the-best-deep-research)). Protocol: 30-min cap, ≤2 min between user-facing outputs, ~10k-token reports ([bench repo](https://github.com/onyx-dot-app/onyx_deep_research_bench)). Its "#1 on DeepResearch Bench" is real but a 2026-02-07 snapshot (54.92 vs Cellcog 54.54); the live board now ranks it 18th at 54.54.

**AOrchestra (arXiv 2602.03786)** is the cleanest published orchestration ablation: an orchestrator whose only actions are Delegate(Φ)/Finish scores GAIA 80.00 vs OpenHands 66.06, and its context ablation on 50 GAIA samples reports **curated context 96.0% beating both full shared context 84.0% and instruction-only 86.0%** ([HTML](https://arxiv.org/html/2602.03786v2)) — directly contradicting Cognition's "share full traces" prescription. The curation algorithm itself is unspecified, which is the single biggest hole behind that number.

## 3. Frontier and queue designs (the lead-management layer)

**Jina node-DeepResearch** is the budget-forcing school ([guide](https://jina.ai/news/a-practical-guide-to-implementing-deepsearch-deepresearch/)). One `while (tokenUsage < tokenBudget && badAttempts <= maxBadAttempts)` loop over four actions — search, read, reflect, answer. Reflection's gap questions enter a **FIFO queue** (new gaps to the front, the original question always pushed to the back, one shared context), chosen over recursion explicitly because DFS makes budget forcing nearly impossible ("no clear rule of thumb for how much budget should be granted for sub-questions") and risks infinite descent. On exhaustion, **"beast mode"** disables every non-answer action and forces a best-effort answer. No vector DB — memory lives in context; embeddings used only for cross-lingual query dedup; URL ranking by frequency + path-structure decay + reranker; evaluation split into "determine criteria" then per-criterion judging.

**dzhng/deep-research** is the recursion pole: breadth × depth with fan-out halving each level (`newBreadth = ceil(breadth/2)`), learnings threaded down as context, dedup only at the end via `new Set(...)`, overlap prevention nothing but a prompt line ([source](https://raw.githubusercontent.com/dzhng/deep-research/main/src/deep-research.ts)). Firecrawl for search and extraction; goal of <500 LoC; no benchmark.

**Devin's Agentic MapReduce** removes overlap by construction: Plan → a **deterministic Shard stage** bucketing work into bounded non-overlapping batches → one child session per batch → a Reduce session that deduplicates, reconciles local conclusions and applies global prioritization over compressed conclusions rather than replayed contexts, with agents used "only where reasoning is required" ([Devin](https://devin.ai/blog/agentic-map-reduce)). Security Swarm: 72% CVE recall at $90.23 vs Claude Security 68% at $131.87. Stopping is queue exhaustion; no fan-out sizing guidance, and no head-to-head against a monolithic long-context agent.

**Argus (arXiv 2605.16217)** is the most interesting frontier design found. Parallel Searchers write into a **shared DAG of URL-tagged evidence nodes and claim nodes with ±1 support/contradict arcs**; evidence is **deduplicated at the source-URL level "preventing any single page from inflating the support count of a claim"**; a Navigator labels every claim supported / contradicted / unverified each round and emits one batch of verification queries targeting only unverified claims, contradictions and uncovered aspects. 25.6M accumulated Searcher tokens compress into a 21.5k Navigator context (~1,200:1) at K=64. BrowseComp 62.2% (K=1) → 74.5% (K=8) → **86.2% (K=64), log-linear with no saturation in the tested budget** ([HTML](https://arxiv.org/html/2605.16217v1)).

**STORM / Co-STORM (Stanford)** decompose by *perspective* rather than sub-question: survey similar articles to discover perspectives, simulate a writer-expert conversation grounded in retrieval, curate into an outline, then write ([repo](https://github.com/stanford-oval/storm), [arXiv 2402.14207](https://arxiv.org/html/2402.14207v1)). Measured: heading soft recall 86.26 vs 73.59 baseline, expert study organization 4.00 vs 3.25 (70% vs 45% rated ≥4) — but **verifiability was not significantly different (3.80 vs 3.85, p=0.843)**, ~15% of sentences unsupported, dominant failure "improper inferential linking," and 7/10 editors called outputs emotional/non-neutral from source bias. Co-STORM ([arXiv 2408.15232](https://arxiv.org/html/2408.15232v2)) adds rotating experts, a **moderator that generates questions from *uncited* sources reranked to be topic-relevant but far from the current question** (cos(i,t)^α(1−cos(i,q))^(1−α)) after L=2 consecutive expert turns, and a **dynamic mind map** tree reorganized when a concept exceeds K=10 items. WildSeek: depth 3.77 vs 3.26/3.43, novelty 3.05, unique URLs 6.04 vs ~2.9; serendipity preferred 70% over search (p=0.030); mind map accurate 71% of the time.

## 4. RL-trained research models

**Search-R1 (arXiv 2503.09516)** trains Qwen2.5-3B/7B to emit `<search>` mid-reasoning, stabilized by two things: **retrieved-token masking** (loss only on model-generated tokens) and a **pure outcome reward** with no process reward — +41% (7B) over RAG baselines. **R1-Searcher (2503.05592)** reaches the same behaviour via two-stage outcome-supervised RL with no distillation or cold start; **R1-Searcher++ (2505.17005)** adds a reward for using *internal* knowledge plus a memorization mechanism folding retrieved facts back into parameters to cut retrieval calls (numbers UNVERIFIED — abstract only).

**WebThinker** pairs a QwQ-32B reasoning loop with a **Deep Web Explorer sub-agent that returns only a condensed answer to the main chain**, and drafts report sections *during* reasoning rather than after ([repo](https://github.com/RUC-NLPIR/WebThinker), [paper](https://arxiv.org/html/2504.21776v1)). Trained by iterative online DPO with cascading preference criteria (correctness > fewer tool calls > shorter thinking). GAIA 44.7→48.5, HLE 13.0→15.8 — but report quality barely moves, a notable asymmetry: RL buys search skill, not writing.

**Alibaba Tongyi (WebWalker → WebDancer → WebSailor → WebShaper → Tongyi DeepResearch).** The pipeline: agentic continual pre-training (AgentFounder), SFT cold start on rejection-sampled trajectories, then customized on-policy GRPO with token-level gradients, leave-one-out variance reduction and conservative negative sampling against format collapse, run over an **offline Wikipedia simulator and cached tool sandbox** specifically to dodge live-search nondeterminism ([blog](https://tongyi-agent.github.io/blog/introducing-tongyi-deep-research/), [report](https://arxiv.org/html/2510.24701v2)). Data synthesis is the real contribution: **SailorFog-QA** random-walk-expands an entity graph then *obfuscates* references ("early 2010s", "institution founded by someone with initial 'F'") to force cross-source intersection; **DUPO** duplicates within-batch samples with non-zero reward std instead of sequential re-rollout, ~2–3x faster than DAPO ([WebSailor](https://arxiv.org/html/2507.02592v1)); WebShaper formalizes tasks as intersections of Knowledge Projections ([alphaXiv](https://www.alphaxiv.org/abs/2507.15061v1)). **IterResearch / "Heavy mode"** is the standout inference trick: each round conditions on a **reconstructed workspace holding only the question, an evolving report S_t as compressed memory, and the last interaction** — the trajectory is discarded and the report *is* the memory — with n parallel agents diverging in strategy and a synthesis model consolidating their compressed reports (n and the conflict rule unstated). Tongyi-DeepResearch-30B-A3B: HLE 32.9→38.3, BrowseComp 43.4→58.3, GAIA 70.9, xbench 75.0. WebSailor scales 3B→72B on BrowseComp-en 3.3→12.0; WebShaper GAIA 60.1 but **reports no BrowseComp at all** (confirmed absent, not a failed lookup).

**MiroThinker / MiroFlow** proposes **"interactive scaling"** — RL-training for deeper/more frequent environment interaction as a third axis beyond parameters and context, up to 600 tool calls in a 256K window ([arXiv 2511.11793](https://arxiv.org/abs/2511.11793)). v1.0 published: BrowseComp 47.1, GAIA 81.9, HLE 37.7. v1.7's BrowseComp 74.0 / BrowseComp-ZH 75.3 exists **only on the repo with no technical report** — the lookup succeeded, the document does not exist. Repo mechanics: **recency-based context retention keeping only the K most recent tool responses (e.g. K=5) while preserving full reasoning traces**, ~300 tool calls/task, three MCPs (E2B, Serper, Jina) ([repo](https://github.com/MiroMindAI/MiroThinker)).

**Others.** ASearcher ([2508.07976](https://arxiv.org/abs/2508.07976)) uses fully asynchronous RL to lift the usual ≤10-turn cap to 100+ tool calls and 400K output tokens per trajectory (xBench 51.1, GAIA 58.7). OpenResearcher ([2603.20278](https://arxiv.org/html/2603.20278)) removes the live web entirely — a 15M-doc offline corpus with search/open/find primitives, 97K trajectories, 54.8% BrowseComp-Plus (+34.0 over base) — and reports the revealing split P(correct | search-hit) 61.8% vs P(correct | open-hit) 86.7%, i.e. reading beats finding. Search-o1 ([2501.05366](https://arxiv.org/abs/2501.05366)) is the pre-RL ancestor with a Reason-in-Documents refiner; ODS ([2503.20201](https://arxiv.org/abs/2503.20201)) is prompt-only (88.3 SimpleQA / 75.3 FRAMES). II-Researcher is a think–act–reflect loop with BAML-typed outputs, two-stage compression (embedding filter at threshold 0.3, then optional LLM compression), pluggable search/scrape, 84.12% FRAMES ([repo](https://github.com/Intelligent-Internet/ii-researcher)).

**smolagents open Deep Research (HuggingFace)** belongs here for one result: a CodeAgent writing actions as Python over a Magentic-One-derived text browser + text inspector scores **55.15% GAIA pass@1**, and swapping the identical setup to JSON tool-calling **instantly degraded it to 33%**, with code actions needing 30% fewer steps ([blog](https://huggingface.co/blog/open-deep-research), [example](https://github.com/huggingface/smolagents/blob/main/examples/open_deep_research/README.md)). Their named limiting factor is the browser, not the model.

## 5. Search and fetch stack

The layer splits into SERP proxies (Serper/SerpAPI, title+URL+snippet, ~$0.30–1.00/1k) and agent-oriented APIs folding extraction, semantic retrieval and reranking into one call (Exa ~$1.50/1k, Tavily with source-credibility metadata, Firecrawl search+scrape with query-relevant highlights, Brave's independent index) ([Firecrawl comparison](https://www.firecrawl.dev/blog/best-web-search-apis) — a vendor page; its own ranking claims are marketing). Naive scraping fails on bot blocks, JS-rendered pages, paywalls/auth and inline PDFs, none of which SERP APIs solve.

**The one controlled experiment that retrieval quality dominates:** Exa vs a Google SERP proxy under an identical Qwen3-4B + LoRA agent trained with Dr. GRPO for 100 steps — Exa-trained reaches SimpleQA 0.767 vs 0.692 and 2WikiMultihop 0.839 vs 0.798, hitting equal performance with **69% fewer tokens, 62% fewer search calls, 58% fewer turns**, returning answer-bearing pages 10.7% more often; cross-backend evaluation shows the training effect and the inference effect are separable ([Exa](https://exa.ai/blog/rl-search-outcomes)). Exa Deep Max fans out dozens of *parallel* search/contents calls over a sub-second in-house index: Deep Search QA 90% @64s, FRAMES 94% @11s, HLE-Search 80% @25s ([Exa](https://exa.ai/blog/deep-max)). No neutral four-backend comparison exists.

**DeepResearchGym ([2505.19253](https://arxiv.org/pdf/2505.19253))** is the reproducibility answer: a free frozen ClueWeb22 + FineWeb dense index with DiskANN, beating commercial API latency and giving **stable rankings across runs** — the point being that live commercial search makes any deep-research result irreproducible.

**AutoSearch** is MCP-native retrieval across ~40 parallel channels including 10+ Chinese sources (Weibo, Bilibili, Zhihu, Xiaohongshu) with dedup and source attribution, but publishes no benchmarks and no dedup/ranking algorithm ([autosearch.dev](https://www.autosearch.dev/)). **n8n template 2883** is an inspectable low-code architecture (query generator ≤4 queries → SerpAPI loop → Jina scraper → relevance/credibility evaluator → conditional re-query) ([n8n](https://n8n.io/workflows/2883-open-deep-research-ai-powered-autonomous-research-workflow/)). **local-deep-researcher** is the canonical local loop (summarize → reflect on gaps → re-query, `MAX_WEB_RESEARCH_LOOPS=3`, DuckDuckGo default, documented JSON-mode fragility on small models) ([repo](https://github.com/langchain-ai/local-deep-researcher)); **LearningCircuit/local-deep-research** reports 95.7% SimpleQA and 77.0% xbench on a single RTX 3090 with self-noted grader-noise and contamination caveats ([README](https://github.com/LearningCircuit/local-deep-research/blob/main/README.md)).

## 6. Benchmarks and what they actually rank

- **BrowseComp**: 1,266 short-answer questions, hard to find and trivially verifiable, plain accuracy. The [Steel leaderboard](https://leaderboard.steel.dev/leaderboards/browsecomp/) preserves per-entry scaffold notes: GPT-5.6 Sol Ultra 92.2% ("4 parallel agents"), GPT-6 Astra 91.5% (single agent, max effort), Kimi K3 91.2% (**"context compaction triggered at 300K tokens; 90.4% with full 1M-token context"** — compaction *beats* full context), Claude Opus 5 90.8% (single agent, compaction at 200k). The board warns rows mix pass@1 and best-of-N without flagging which, so single-vs-multi comparisons there are not apples-to-apples.
- **GAIA** (multi-step tool tasks) and **HLE** (2,500 graduate questions) — aggregator numbers only, treat as UNVERIFIED against official boards.
- **DeepResearch Bench**: 100 PhD-level tasks (50 EN / 50 ZH) with two metrics — **RACE** (reference-based adaptive criteria) and **FACT** (extract claims + cited URLs, **re-scrape the source**, judge support) ([paper](https://arxiv.org/pdf/2506.11763)). The live board (legacy Gemini-2.5 evaluator track, updated 2026-05-19) ranks Qianfan/DuMate 58.03, ZTE-Nebula 57.27, iFlow-Researcher 57.08, Zhipu 57.06 — with **Gemini-2.5-Pro DR at 49.71 and OpenAI DR at 46.45** ([leaderboard.csv](https://huggingface.co/spaces/muset-ai/DeepResearch-Bench-Leaderboard/raw/main/data/leaderboard.csv)). Critically, **the RACE leaders publish no FACT numbers at all**, and a GPT-5.5 evaluator migration on 2026-05-11 may reorder everything.
- **DR³-Eval ([2604.14683](https://arxiv.org/abs/2604.14683))** pairs each task with a static per-task sandbox corpus of supportive docs, distractors and noise, and reports that retrieval robustness and hallucination control are where agents break. **ResearchQA**: 21.4K questions, ~7.5 hybrid rubric items each.
- Surveys: [2506.12594](https://arxiv.org/abs/2506.12594) taxonomizes 80+ systems on four orthogonal dimensions (foundation model, tool use, planning/execution control, synthesis) rather than architecture buckets; [2512.02038](https://arxiv.org/abs/2512.02038) organizes by query planning / information acquisition / **memory management** / synthesis and splits planning into parallel vs sequential vs tree-based — memory appearing as a first-class component is the visible shift between the two.

**Cost**: Parallel publishes per-thousand-query costs from actual benchmark usage — Parallel Pro $100 CPM up to Ultra8x $2,400, vs OpenAI GPT-5 $488–628, Exa $402, Perplexity $538–709, **Anthropic $5,194** ([parallel.ai](https://parallel.ai/blog/deep-research-benchmarks)) — i.e. roughly $0.40–$5.19 per query, with no latency figures. Open-source self-reported: GPT-Researcher ~$0.40/task, open_deep_research $0.20–$1.00/task.

## 7. Grounding and verification — measurement vs mitigation

**The measurement is damning.** *Cited but Not Verified* ([2605.06635](https://arxiv.org/abs/2605.06635)) parses claim-citation pairs from Markdown, re-fetches every cited URL and judges three separate dimensions: **link validity >94% and relevance >80% coexist with Fact Check of only 24–77%** (Claude Opus 4.5 76.8%, GPT-5.4 47.7%, OSS-120B 24.4%) — the real failure is a working URL under a fabricated claim. Worse, **factual accuracy falls ~42% on average as tool calls scale 2→150** (GPT-5.4: 78.6%→16.7%): more retrieval makes citations worse. DeepTRACE ([2509.04499](https://arxiv.org/abs/2509.04499)) finds citation accuracy 40–80% across engines, with deep-research modes improving thoroughness but still carrying large unsupported-statement fractions. The Tow Center/CJR study (1,600 queries, 8 tools) found >60% incorrect citations overall — Perplexity 37%, ChatGPT Search 67%, Grok-3 94%, Gemini 1 fully correct of 200 — and **Perplexity Pro was *more* error-prone than free Perplexity** ([CJR](https://www.cjr.org/tow_center/we-compared-eight-ai-search-engines-theyre-all-bad-at-citing-news.php)). PING/DeepHalluBench ([2601.22984](https://arxiv.org/html/2601.22984v1)) localizes the damage: **hallucination concentrates in summarization (~0.51 combined) not planning (~0.18)**, with proprietary agents showing early cascading fabrication (>57% of source errors early) and open-source frameworks suffering late-stage context collapse (>40% late errors); it proposes fixes and tests none.

**Mitigations with an actual before/after number** — the short list:
- **Post-hoc citation verification with a tool**: agentic self-correction via a `urlhealth` tool drove non-resolving citations 16.0%→0.6% (GPT-5.1), 6.1%→0.1% (Gemini 2.5 Pro), 4.9%→0.8% (Claude Sonnet 4.5), p<10⁻³⁵, against baseline hallucinated-URL rates of 10.7% for deep research agents ([2604.03173](https://arxiv.org/html/2604.03173v1)).
- **Conflict-aware aggregation**: MADAM-RAG beats concatenation by +15.8 and Astute RAG by +11.4 on AmbigDocs, with ablation attributing +19 to the aggregator and only +5.3 to multi-round debate ([2504.13079](https://arxiv.org/html/2504.13079v1)).
- **Abstention shaping**: AWA-RL gives up to +10.3% absolute precision for marginal accuracy loss ([2607.10738](https://arxiv.org/abs/2607.10738)).
- **Cascade control**: HPR-Adaptive (dynamic trust weighting + external claim verification + selective isolation of unreliable agents) cuts hallucination 0.118→0.072 and pushes the effective reproduction number below 1 ([2606.07941](https://arxiv.org/abs/2606.07941)).
- **Reported as barely working**: putting a trusted-domain allow-list in the system prompt moved citations to listed domains only **12%→21%**, while 35% of web-search answers cited at least one untrustworthy or irrelevant source and "fluency and topical fit did not predict source trustworthiness" ([2607.05217](https://arxiv.org/abs/2607.05217)).

**Contradiction handling is largely unsolved in shipped systems.** Anthropic's write-up is silent on reconciling divergent subagent findings. The most concrete shipped design found is a small open-source agent that collapses near-duplicates via hashed word-shingles *before* corroboration counting (so wire-story republication cannot inflate confidence), grades claims well-corroborated (3+) / corroborated (2) / single-source / **disputed** with numeric tolerance, and verifies every quote by exact match against fetched text ([repo](https://github.com/hammas159/deep-research-agent)) — but it ships zero end-to-end benchmark. Argus's ±1 support/contradict claim graph is the strongest evaluated version of the same idea.

**Prompt injection**: OpenAI frames the research-agent case directly and lists layered defenses (Instruction Hierarchy training, updatable monitors, link-approval for un-cataloged sites, sandboxing, Watch Mode), plus an RL-trained auto-attacker that discovered a novel long-horizon attack class and drove an adversarially-trained checkpoint ([1](https://openai.com/index/prompt-injections/), [2](https://openai.com/index/hardening-atlas-against-prompt-injection/)) — with **no attack-success-rate numbers published** and the statement that it is "unlikely to ever be fully solved."

## 8. Cross-cutting: what recurs, what fails, what is genuinely novel

**Recurring in the successful ones**
1. **Context compaction beats more context.** Kimi K3 scores higher with compaction at 300K than with a full 1M window; Anthropic's ladder is summarize-and-restart → tool-result clearing ("the safest, lightest touch form") → note files → sub-agent isolation ([Anthropic](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)); Step-DeepResearch demand-pages to disk; IterResearch discards the trajectory and keeps only an evolving report; MiroThinker keeps only the K most recent tool observations.
2. **Externalize state to artifacts.** Anthropic's plan-to-memory before truncation and subagent-writes-to-filesystem, LangChain's >20K-token offload at 85% utilization, Anthropic's harness post reporting native compaction "isn't sufficient" for multi-window tasks and requiring a re-read-at-session-start progress file ([harnesses](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)).
3. **Self-contained, explicitly non-overlapping briefs.** Anthropic's four-field contract (objective / format / tools+sources / boundaries), LangChain's "standalone instructions, no acronyms, distinct non-overlapping subtopics" — the reported fix for the triplicated-subagent failure.
4. **Broad-then-narrow search.** Both Anthropic and Jina report over-specific opening queries as a primary failure; start short and broad.
5. **Explicit reflection between steps.** LangChain's mandatory `think_tool` before delegating and after every result; Anthropic's extended thinking as planning scratchpad; Jina's reflect action producing gap questions.
6. **Retrieval quality is a first-class lever**, worth 69% fewer tokens at equal accuracy in the one controlled test.
7. **Model tiering**, universally: strong lead + cheap readers/summarizers (Opus/Sonnet; gpt-4.1 / gpt-4.1-mini).

**Reported to FAIL**
- **More tool calls make citations worse** — ~42% accuracy decay from 2→150 calls.
- **Intermediate retrieval rewards consistently degrade RL performance**, while a random retriever teaches the agent to stop searching and BM25 induces query spam; reasoning-specialized backbones can collapse under GRPO ([2505.15117](https://arxiv.org/html/2505.15117v1)).
- **Prompt-level trusted-domain allow-lists** (12%→21%).
- **JSON tool-calling vs code actions** for the same agent (55%→33% GAIA).
- **Full shared context between orchestrator and workers** — worse than curated context *and* worse than instruction-only in AOrchestra's ablation.
- **Unbounded subagent spawning, vague briefs, endless hunts for nonexistent sources, SEO-source bias** (Anthropic's list), and **brute-searching instead of decomposing** plus quality decay as prompt context grows (HN practitioners, [thread](https://news.ycombinator.com/item?id=43553241)).
- **Depth past a knee**: newly-retrieved relevant documents "steadily decline and eventually disappear after several iterations" while agents still average 50+ searches; a stopping controller cut searches by up to 44 and raised accuracy up to 10% ([RAAC](https://arxiv.org/html/2608.15191v1)). AgentCPM's quality knee is ~9 deepening steps ([2602.06540](https://arxiv.org/html/2602.06540v1)).
- **Context trimmers crashing on their own data structures** (gpt-researcher #1332) — the unglamorous production failure.
- The **Anthropic vs Cognition contradiction** is unresolved: Cognition argues parallel subagents disperse decision-making and recommends single-threaded agents with a trained compression model ([Cognition](https://cognition.com/blog/dont-build-multi-agents)), while MAST's 1600+ annotated traces conclude multi-agent benchmark gains are "often minimal" and failures need structural not prompt-level fixes ([2503.13657](https://arxiv.org/abs/2503.13657)).

**Genuinely novel / unusual**
- **Argus's shared evidence DAG with URL-level dedup and a support/contradict claim graph**, compressing 25.6M worker tokens into a 21.5k lead context (~1,200:1) — the only design that makes corroboration *structural* rather than prompted.
- **IterResearch's workspace reconstruction**: discard the trajectory, carry only an evolving report as memory.
- **Jina's FIFO gap queue with the original question always at the back**, plus beast mode as a hard terminal.
- **Devin's deterministic sharding** — overlap prevented by construction, not by prompt.
- **Co-STORM's moderator generating questions from *uncited* sources** reranked to be topic-relevant but distant from the current question — an explicit novelty-seeking frontier operator.
- **SailorFog-QA's information obfuscation** to force cross-source intersection during training.
- **Kimi's gamma-decay reward** penalizing trajectory length, and its negative-sample discarding.
- **Step-DeepResearch's demand-paged context** and patch-based file editing (−70% output tokens).
- **"Don't Stop Early" (EDR)**: each step declares explicit **termination criteria naming the evidence that must exist** before execution, then loops until met — buying ~8 HAA points for ~46% more tool calls, and its parallel DAG saving 4.7x wall-clock ([2604.24978](https://arxiv.org/html/2604.24978v1)).
- **ParallelSearch**: RL-rewarding recognition of logically *independent* sub-queries, +12.7% on parallelizable questions at 69.6% of the LLM calls ([2508.09303](https://arxiv.org/abs/2508.09303)) — the gain concentrates exactly where the split is genuine.

## 9. What would improve our own shape (lead, ≤4 rounds, ≤4 batched diggers)

1. **Width scales, depth saturates.** Argus goes 62.2%→86.2% from K=1→64 with no saturation, while RAAC and AgentCPM both find new information stops arriving after a handful of rounds. Our 4-round × 4-digger box is likely mis-proportioned: prefer more diggers per round and fewer rounds.
2. **Add a shared visited-URL / evidence ledger.** Every system that dedups does it at source-URL level (Argus explicitly, to stop one page inflating corroboration); we currently have no cross-digger dedup, and Anthropic's named triplication failure is exactly our risk.
3. **Adopt an explicit sufficiency criterion per sub-query**, EDR-style: the digger declares what evidence would settle its question before searching, rather than stopping on a round count. Our fixed 4-round ceiling is the budget-stop that "Don't Stop Early" measures as premature.
4. **Reconsider the return shape.** LangChain's compressor forbids summarizing and returns verbatim findings + all sources because a later LLM merges them; the one controlled relay study finds **all loss concentrates at the first encoding step, not across hops**, and that precision-instructed natural language matches schema fidelity 26% cheaper ([2607.09678](https://arxiv.org/html/2607.09678v1)). Our "2-4 sentence cited finding per number" is a first-encoding compression — the highest-loss point in the pipeline.
5. **Verify citations post-hoc with a tool, not by trust.** The urlhealth result (16.0%→0.6%) is the cheapest measured win available, and PING says summarization — our synthesis step — is where hallucination concentrates.
6. **Make contradiction a first-class output.** Grade each claim corroborated / single-source / disputed; MADAM-RAG's +19 came from the aggregator, not the debate.
7. **Mandatory reflection before delegating** (LangChain's `think_tool` law) and a bias toward fewer, genuinely independent sub-queries — ParallelSearch shows splitting pays only where the split is real.
8. **Watch the tool-call/accuracy inversion**: more digging past a point measurably degrades citation fidelity. Depth budgets should be capped on evidence, not ambition.
