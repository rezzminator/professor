# v0.91.0 — 2026-11-24

The `/reload` command is renamed `/pfm:reload`: after the update typing `/reload` no longer reloads a chat, and the update's `pfm install` removes the old command card. `pfm restart` now brings back every chat that runs in a Herdr pane, with its workspace, tab and split, instead of ending it, typed `/pfm:space` and `/pfm:reload` run in pfm's prompt hook with no model turn, and a `/pfm:reload --then` message now reaches the reborn chat and is never lost. The coding, testing and life-cycle rules now come from the flights plugin as `flights-coding`, `flights-testing` and `flights-life-cycle`, the buddy plugin is retired, and `pfm install` clears every trace a retired plugin leaves while keeping any file of yours it cannot vouch for. pfm's own tests no longer wait on wall-clock time, and four faults that sweep found are fixed.

## Breaking

- pfm: /reload — the `/reload` command is renamed `/pfm:reload`, same flags; its card now ships from the clone as a machine-global command instead of a pfm-staged asset, and the update's `pfm install` removes `~/.claude/commands/reload.md` (a file or link of your own at that name is backed up under `~/.local/state/pfm/retired-config/` first, a link as a link; a folder or FIFO there stays, named in a `kept` skip line) and strips the retired `pfm internal reload-intercept` hook, which exits 0 silently for a chat still holding it. `pfm doctor --project-updates` now lists project-file mentions of `/reload` under `RETIRED-NAME`.
#### → For: every adopter · after update · /reload — type `/pfm:reload` wherever you typed `/reload`, with the same flags; `ls ~/.claude/commands/reload.md` reports no such file.
#### → For: every adopter · per project · /reload mentions — in each file `pfm doctor --project-updates` lists under `RETIRED-NAME` for `/reload`, write `/pfm:reload` instead; the report then lists no `/reload` hit.

## Added

- pfm: pfm restart — `pfm restart` brings back every chat that runs in a Herdr pane, with its workspace, tab and split: the chat keeps running, Herdr restores its pane on the restarted server, and the restart waits up to 1m40s for it, failing that chat with the `pfm chat open` line that reopens it (at once when the Herdr server did not start again). A tmux chat, a chat on another Herdr server or one Herdr cannot resume is ended with its reason; `pfm restart --no-restore` ends every chat as before.
- pfm: typed /pfm:space and /pfm:reload — typed in a Claude chat pfm launches after the update, `/pfm:space …` and `/pfm:reload …` run in pfm's `pfm internal command-intercept` prompt hook and never reach the model, so they cost no model turn; Codex and OpenCode chats, and a model asked to run them, still go through the command body.
- Global: templates/global/commands/pfm/reload.md — the `/pfm:reload` card, the former `/reload` card under its new name, says a typed `/pfm:reload` never reaches the model on a Claude seat and that its body serves Codex and OpenCode seats and the calls a user asks the model to make, and that on a native Herdr Claude chat a `--then` prompt is stored in `reload-herdr-<seat>.then` before `/exit` and, when it could not be typed, reaches the reborn chat's next prompt marked `PFM RELOAD FOLLOW-UP NOT TYPED`.
- Global: rr-mini agent — the new `rr-mini` agent reads facts from a source the caller names (a docs page, a repo file URL, a spec section) and returns each answer with its verbatim quote and URL; a page cut short is re-read through harvester and searched in full, and `rr` now points facts at a known page to it. Codex roles recompile at the update's install.
- Global: no-reader-proxy rule — the new always-on global rule `no-reader-proxy` forbids reading a page through `r.jina.ai` or any other third-party reader proxy; an unreadable page stays unread. The `pcm` agent also mirrors an edit to a versioned skill to that skill's source clone.

A machine without the flights plugin enabled no longer gets these rules. The coding rule now lists every place a change must reach before the first edit, marks a known-limit shortcut with a `shortcut:` comment, and closes a reply on written code with what was skipped and any risk; foreman returns gain `SKIPPED` and `RISK`.
#### → For: every adopter · after update · ~/.claude/rules/flights-*.md — start a new Claude chat, then `ls ~/.claude/rules/flights-coding.md ~/.claude/rules/flights-testing.md ~/.claude/rules/flights-life-cycle.md` lists all three; if one is missing, run `claude plugin update flights@professor` and start another chat.

## Fixed

- pfm: /pfm:space — a `/pfm:space` move takes the view along when the moved chat's pane is focused, and checks focus before it creates the target workspace; a cancelled Codex state read no longer reports as unreadable.
- pfm: Herdr chat resume — a Herdr chat older than the 7-day prune of its launch files resumes, because every Herdr engine start rewrites the pfm-owned MCP launch files its recipe names, also when the recipe names them through a link to the home folder; a restore whose saved resume line names an older conversation brings back the pane's own chat and says so; a resumed Claude that exits with a status from 1 to 128 within 10 s of starting marks its seat failed with the pane's last lines, and `pfm restart` fails that chat at once with its reopen line instead of waiting.
- pfm: chat reload in Herdr — a chat reload no longer refuses a healthy chat when Herdr lists its engine with an empty argv; both refusals name the pane and every row read.
- pfm: chat reload --then — a `pfm chat reload --then` message, the one `/pfm:reload --then` sends, now reaches the reborn chat: readiness is read only inside the reborn Claude's own input box, so the `claude --resume` shell line a Herdr-restored pane leaves on screen no longer fails the hand-off as a draft, and a real draft there is polled for the reload's whole wait and refused only if still there at the last read. On a native Herdr Claude chat the message is stored as `reload-herdr-<seat>.then` in pfm's session folder (`cc-sid` under the system temp directory, or `PFM_SID_DIR`) before `/exit` and removed once typed; one the reload could not type is named in its error and reaches the reborn chat's next prompt once, marked `PFM RELOAD FOLLOW-UP NOT TYPED`, and `pfm doctor` accepts the stored file.
- pfm: doctor and seat host — `pfm doctor` no longer counts a check that did not look, a lifecycle event as a Herdr reporter error or a Claude runtime lock file as unclassified, and a seat host keeps one cost sink.
- pfm: faults found by the test sweep — a chat reload with no account names the account it really runs on; `pfm log --follow` keeps a half-written record until its newline arrives instead of dropping it; a fleet database another pfm is still creating reads as "no primary account set" instead of failing with `no such table: meta`; the Herdr indicator hook stands down quietly when Herdr's socket is removed while it runs.
- pfm: Claude settings reads — a FIFO at a Claude settings file's path is an error naming that path in `pfm install`'s Claude plugin steps, no longer a hang.
- pfm: Herdr plugin registry — `pfm install` and theme sync read Herdr's plugin registry at `$XDG_CONFIG_HOME/herdr/plugins.json` when `XDG_CONFIG_HOME` is set, else `~/.config/herdr/plugins.json`, instead of always the latter; a FIFO or folder at that path is an error naming it, never a hang.
- pfm: tmux calls — a tmux call that exits 0 while the tmux server keeps its output pipe open past the 500 ms wait is a success with its output, logged at WARN, instead of an error to its caller.

## Removed

- pfm: buddy and retired plugin leftovers — the buddy plugin is retired; the update's `pfm install` wipes every trace a retired plugin with no successor leaves (its `enabledPlugins` entry in `settings.json` and `settings.local.json`, install record, cache, data and log folders), which also clears `effort-live-control`, `sub-agent-compact` and `flapboard` leftovers, and `pfm doctor` reports any trace left, naming the unread marketplace plugin list as the repair to make first when it cannot read it. Only pfm's own default log folder, `~/.local/state/pfm/plugin-logs`, is cleared unchecked: under a `PLUGIN_LOG_DIR` you set yourself, in `settings.json` or in `pfm.config.json`, a retired plugin's log folder is removed only when it is empty or holds only plugin log files, and one holding anything else is kept and named in a `kept` skip line. A `settings.local.json` pfm cannot read or parse stays as it is, named in a skip line and one `pfm doctor` warning, never a failed install or a rolled-back update. The update from v0.90.0 reads this release's retired lists without error.
#### → For: adopters who set PLUGIN_LOG_DIR in settings.json or pfm.config.json · after update · PLUGIN_LOG_DIR — for each folder a `pfm install --yes` skip line names as `kept`, delete the retired plugin's log files in it by hand and keep your own files; `pfm doctor` then reports no trace of a retired plugin.
#### → For: adopters whose settings.local.json pfm cannot read · after update · settings.local.json — if `pfm install --yes` prints a `claude plugins:` skip line naming a `settings.local.json`, repair that file's JSON (or replace a FIFO or folder at its path with the file), then run `pfm install --yes` again; it prints no such line and `pfm doctor` reports no trace of a retired plugin.
- pfm: herdr-shield — the update's `pfm install` unlinks the retired `herdr-shield` plugin from Herdr once Herdr's `default_shell` no longer runs `herdr-shield`; while it still does, when Herdr's plugin registry cannot be read, or when `herdr plugin unlink` does not answer within 30 s, the plugin stays linked and the install prints a skip line naming the repair instead of failing.
#### → For: Herdr users · after update · herdr plugin herdr-shield — if `pfm install --yes` prints a `herdr plugin herdr-shield stays registered` skip line, follow the repair it names, then run `pfm install --yes` again; it prints no such line.
- Repo: plugins/buddy — the submodule and its marketplace entry are gone.
