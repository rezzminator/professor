# Codex Integration Layer

OPTIONAL dual-runtime setup. `.codex/` is a **pointer layer** over `.claude/` — it holds routing and sandbox config, never protocol. Delete the whole directory and the pipeline runs unchanged on Claude Code alone.

## The one rule

**`.claude/` is the single source of truth. `.codex/` never restates it.**

Every file under `.codex/skills/` either symlinks a `.claude/` directory or is a generated pointer that says "read this `.claude/` file in full". The hand-authored bytes are `config.toml`, `rules/*.rules`, and the small cards covering harness mechanics that `.claude/` has no reason to know about. Agent TOMLs are generated from `.claude/agents/`.

If you catch yourself writing what to build inside `.codex/`, it belongs in `.claude/`.

## Layout

```
.codex/
├── config.toml                 ← model + sandbox reach. NOT launch flags.
├── rules/
│   └── repo-law.rules          ← execpolicy door lock (filename arbitrary)
├── agents/                     ← GENERATED active registry from every .claude/agents source
│   ├── gitter.toml             ← sole Git-writing role
│   ├── {root-role}.toml        ← one per root source agent
│   └── {role}-{project}.toml   ← one per project source agent
└── skills/                     ← GENERATED by `pfm codex build` + hand-written cards
    ├── {command-name}/SKILL.md ← generated pointer (one per single-file command)
    ├── {skill-name} -> ../../.claude/skills/{skill-name}     ← true dir symlink
    └── chat/SKILL.md           ← hand-written card (never overwritten)

AGENTS.md                       ← GENERATED from CLAUDE.md; Codex reads it by convention
```

## Setup

**1. Config** — fill the model and reasoning-effort values in `.codex/config.toml`. Read its comments before adding anything else; § "Settings deliberately absent" below explains what was removed and why.

**2. Rules** — fill the tool names in `.codex/rules/repo-law.rules`, then PROVE each rule fires:

```bash
codex execpolicy check --pretty --rules .codex/rules/repo-law.rules -- {command}
```

**3. Compile and check** — after the local `CLAUDE.md` and `.claude/` sources are final:

```bash
pfm codex build
pfm codex check
```

The compiler creates `AGENTS.md`, command and skill pointers, the `.codex/agents/` registry, and the managed MCP fence. It transforms runtime mechanics and model aliases while keeping the local Claude files as source. Never hand-edit generated output.

**4. Trust the repo** — Codex only loads a repo-level `config.toml` for a trusted project; it asks once, on first launch in the directory.

## The mirror compiler

`pfm codex build` is the single writer of generated mirror files. `pfm codex check` plans the same output, reports `MISSING`, `STALE`, `ORPHAN`, or `CONFLICT`, and writes nothing. Every managed file carries a generated marker; a foreign file at a managed path is reported and preserved.

`.codex/skills/` is **generated except for the shipped hand-written cards**. Never hand-edit a generated pointer, and never vendor a copy of a `.claude/` protocol into it — a vendored copy is stale the first time the source changes, and nothing tells you.

### Two shapes, and why the difference is not negotiable

| Claude entry point | Mirrored as | Why |
| ------------------------------------- | ---------------------------------------- | ------------------------------------------------------------- |
| a **skill** (already a directory) | true symlink to that directory | zero generated bytes; Codex follows a symlinked skill DIR |
| a **command** (a single `.md` file) | a real directory + generated `SKILL.md` | it has no directory to link, and linking the FILE loses it |

The second row is a **measured harness constraint**. Codex 0.144.1 follows a symlinked skill DIRECTORY, but silently DROPS a real directory whose `SKILL.md` is a symlinked FILE — no warning, no error, no log line; the skill simply does not exist. Measured on a 56-entry mirror: **9 skills discovered before the fix, 56 after**, with the same 56 directories on disk the whole time.

That failure mode is invisible, so a regression looks exactly like success. Re-probe before ever "simplifying" the pointers back into symlinks.

### Pointer paths are repo-relative — always

A generated pointer says `Read `.claude/commands/{x}.md` (relative to the repo root you were launched in)`. Repo-relative, never absolute, and this is load-bearing: worktrees materialize these committed files, so a lane must read **its own branch's** protocol. An absolute path would silently route every worktree lane to the main checkout's version — the lane would follow a protocol its branch does not contain, and every symptom would point somewhere else.

### Commands

```bash
pfm codex build    # reconcile generated outputs
pfm codex check    # read-only; exit 1 on any finding
```

`check` is CI / pre-merge-gate material: a command whose frontmatter changed leaves Codex routing on a stale description until the compiler runs again. The deployed `codex-sync.sh` hook bridge marks Claude-source edits dirty, then runs both commands at turn end; Bash-driven writes remain the audit/check backstop's responsibility.

### Hand-written cards

A card earns this status only when it carries Codex-specific mechanics with no project-local Claude command counterpart. It has no generated marker, so the compiler never treats it as owned output. One ships as a worked example:

- **`chat/`** — the ping toolset. It has no project-generated counterpart: chat is a host-level MCP surface, not a project-local `.claude/commands/` source, so this card is its Codex-side entry point.

A hand-written card still points at the binding protocol first and only then lists deltas. A card that explains what to build is a bug.

## Dispatch — how Codex spawns work

Codex discovers `.codex/agents/*.toml` at session start. `spawn_agent` selects a registered role with `agent_type`; the message supplies the bounded task, not the role protocol:

```
spawn_agent {
  agent_type: "{role}-{project}",
  task_name: "{task}",
  message: "{bounded task brief}",
  fork_turns: "all"
}
```

The compiler embeds each source agent's protocol into its TOML, applies model aliases, and marks source roles without write tools as read-only. Children share the working directory; their role-specific sandbox and repository law still bind. Rebuild the mirror and reload Codex after an agent source changes.

The `Executor:` stamp is not decoration: a downstream judge weighs an inline verdict differently from a forked one, and an unstamped verdict is unattributable.

## gitter registration

The compiler registers `gitter.toml` from `.claude/agents/gitter.md`. It is the only Codex subagent without read-only Git; every commit, merge, branch, tag, and push still follows that source protocol and its publication boundary. A global execpolicy rule that blocks Git writes would also block gitter, so Git ownership is enforced by role registration, sandbox selection, and the sole-writer law rather than a repo-wide Git deny.

## Settings deliberately absent from `config.toml`

An earlier version of this template shipped a Codex Teams orchestration model that **does not exist**. If you are upgrading and miss one of these, it was removed because it was untrue, not because it was trimmed:

| Removed | Why |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `CODEX_EXPERIMENTAL_AGENT_TEAMS = "1"` | Teams-gated `Agent(role, "...")` spawning is not the dispatch mechanism; `spawn_agent` is |
| `[agents] max_threads` / `max_depth` / `job_max_runtime_seconds` | configure a Teams scheduler that never runs the pipeline |
| `[features] personality` / `codex_hooks` | not load-bearing; voice comes from `AGENTS.md` and the role manuals |
| `approval_policy` set to never-ask | a LAUNCH decision (`-a never`), and this file is read by interactive sessions too |
| `sandbox_mode` set to Codex's full-access sandbox | same — a per-launch, explicitly-authorized escalation, never a repo default |
| `[shell_environment_policy]`, `project_doc_max_bytes` | not needed by the working config; add back only with a reason you can state |

**Launch flags belong with the launcher.** `-s workspace-write -a never` goes in the tmux command that starts a lane. Putting them here changes the human's interactive defaults out from under them.

## What NOT to do

- **Don't make Codex a requirement** — every pipeline operation must work on Claude Code alone.
- **Don't vendor protocol into `.codex/skills/`** — generated pointers come from local Claude sources; run `pfm codex build`.
- **Don't hand-edit a generated pointer** — the next build replaces marker-owned drift.
- **Don't let Codex edit `.claude/`, `CLAUDE.md`, or `AGENTS.md`** — those route through the framework-change command. Claude chats have hooks fencing them; **Codex has none**, so the written ban is the only fence and it is absolute.
- **Don't put pipeline logic in a `.toml`** — past ~30 lines of `developer_instructions`, the logic belongs in the `.claude/` manual.
- **Don't use loose parenthetical lists in `developer_instructions`** — Codex can read `"(commit, lock, push)"` as authorization to perform all three.
- **Don't claim a protection you have not pinned** — a comment asserting a security property names the pin that proves it, or it does not ship.
