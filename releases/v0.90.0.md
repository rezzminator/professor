# v0.90.0 — 2026-11-21

The standalone `cache-keepwarm` plugin is retired into `cache-live-control` 0.8.0, so a machine whose `claude.plugins` list still names `cache-keepwarm` fails the update's install and rolls back until that entry is replaced. `pfm install` now ships the fleet's setup flags itself: six new Claude Code environment variables and three dialog skips on every launch, the bypass consent written into each account's `settings.json`, Herdr's onboarding turned off, and `rule-control` among the default plugins. A chat started in a new Herdr space no longer leaves the pfm picker behind in that space, long-lived pfm processes move onto the installed build after an install, and `installPing` and `claude.pluginSource` join the machine config. The update chat that asks which projects to update, and the state-database restore on a failed update, both run from the binary you update from, so they show first on the update after this one.

## Breaking

- pfm: claude.plugins cache-keepwarm — `cache-keepwarm@professor` is retired for `cache-live-control`, which now carries keep-warm; a machine `pfm.config.json` whose `claude.plugins` still names `cache-keepwarm` fails the update's `pfm install` with `plugin cache-keepwarm is retired (now cache-live-control) but claude.plugins lists it`, so `pfm update` fails and rolls back. A machine with `claude.plugins` unset never listed it and is untouched.
#### → For: adopters whose pfm.config.json sets claude.plugins · before update · pfm.config.json claude.plugins — replace `"cache-keepwarm"` with `"cache-live-control"` (delete it where `"cache-live-control"` is already listed), keep `"professor"` listed, and add `"rule-control"` unless you mean to leave this release's new default plugin off; after the update `pfm doctor` prints `doctor: claude_plugins ok` and no `is retired (now cache-live-control)` line.

## Added

- pfm: rule-control default plugin — `rule-control` (per-loop rule delivery: a rule file names the loops that receive it) joins the default `claude.plugins` list, so a machine with `claude.plugins` unset gets it installed and enabled at the update's install; a machine whose list is set gets it only by adding it.
- pfm: herdr.settings — `pfm install` adds pfm's Herdr settings to Herdr's `config.toml` wherever the file lacks the key, keeping every value you set; the one shipped setting is `onboarding = false`, so Herdr's first-run onboarding no longer greets a pfm-managed Herdr. `herdr.settings` in the machine `pfm.config.json` is Herdr's `config.toml` as JSON, merged key by key over pfm's settings, a `null` removing one; `pfm config show` prints `config herdr.settings=…`.
- pfm: installPing — `installPing` (default `true`) in the machine `pfm.config.json`: `false` stops both the install-time and the daily anonymous ping, and an unreadable config sends neither; `DO_NOT_TRACK=1` and `PFM_INSTALL_PING_OFFLINE=1` still work. `pfm install` no longer prints a line about the ping, so the `pfm: install ping off (…)` line v0.89.0's action checked no longer appears. A pfm older than this release refuses the key. (opt-in)
#### → For: adopters who do not want the install ping · after update · pfm.config.json installPing — set `"installPing": false` in the machine `pfm.config.json`; `pfm config show` prints `config installPing=false (file)`.
- pfm: claude.pluginSource — `claude.pluginSource` in the machine `pfm.config.json` picks where Professor's own plugins install from: `"release"` (the default) from the GitHub catalog, or `"checkout"` from this clone's plugin checkouts under `claude.pluginCheckoutRoot` (else the clone's `plugins/`); `pfm doctor` prints the source in use as `doctor: claude_plugins source: …`. A pfm older than this release refuses the key. (opt-in)

## Changed

- pfm: claude.pluginSource on alpha builds — pfm's own version no longer picks the plugin source: an alpha build of pfm now installs plugins from the GitHub catalog like a release build unless `claude.pluginSource` is `"checkout"`. A release build is unchanged.
#### → For: adopters who build pfm from develop and install plugins from their checkouts · after update · pfm.config.json claude.pluginSource — set `"claude": {"pluginSource": "checkout"}` in the machine `pfm.config.json` and run `pfm install --yes`; `pfm doctor` then prints `doctor: claude_plugins source: claude.pluginSource=checkout (file)`.
- pfm: Claude launch defaults — every Claude launch adds the environment variables `CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1` (no rating survey swallowing the keys pfm types), `CLAUDE_CODE_DISABLE_BG_EXIT_HANDOFF=1` and `CLAUDE_DISABLE_ADOPT=1` (a chat that exits is never carried on by a Claude Code background worker), `CLAUDE_CODE_RETRY_WATCHDOG=1` (an unattended chat waits out overload and usage limits instead of failing the turn), `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP=2` (a turn ends after 2 consecutive Stop-hook blocks instead of 8) and `ENABLE_TOOL_SEARCH=true`, and the settings `skipAutoPermissionPrompt`, `skipWorkflowUsageWarning` and `skipDangerousModePermissionPrompt`; `pfm config claude` lists each with its reason, and a `null` for a key in `claude.settings` removes it. `pfm install` also writes `skipDangerousModePermissionPrompt: true` into each Claude account's own `settings.json`, adding it only where the file lacks the key and keeping every other byte, unless `claude.settings` sets it to `null`. (cost)
- pfm: update chat — the update chat that `pfm ls` opens from its PROFESSOR UPDATE banner is now seven plain numbered steps on the 1-hour prompt cache, and asks you two things with AskUserQuestion: whether to update now, after a summary and the merged checklist, and, after `pfm update` and `pfm doctor`, which of the projects with open rows to update, a project `pfm doctor` could not read (its warning reads `UNREADABLE`) offered as well, two to four projects per question and a single project as one update-it-or-skip-it question; on an engine without AskUserQuestion, such as Codex or OpenCode, each question is the last block of the chat's reply, the projects listed numbered, and the chat waits for your answer; only the picked projects are taken to clean, and the report names each one left out with the command that updates it later. The banner's chat comes from the pfm you update from, so this update into v0.90.0 still runs v0.89.0's chat, and the new one opens from the next update on.
- pfm: fleet prompt — the main chat's system layer, regenerated by the update's install, gains a `**From training data:**` block, placed last before a section's Verdict, where the model tells what its training holds on the subject as recall; the voice drops only on the leak or publication line, never because the user swears; and a term taken from the code or its docs now counts as a word the user has not used, to be explained in the same sentence.
- pfm: keep-warm state — pfm's statusline reads keep-warm state where `cache-live-control` writes it, `~/.local/state/cache-live-control/keepwarm/sessions/` (under `XDG_STATE_HOME` when set), and the override variable is renamed `CACHE_KEEPWARM_STATE_DIR` → `CACHE_LIVE_CONTROL_KEEPWARM_STATE_DIR`; a relative value is skipped for the next location, as the plugin does.
#### → For: adopters who set CACHE_KEEPWARM_STATE_DIR · after update · CACHE_KEEPWARM_STATE_DIR — rename the export to `CACHE_LIVE_CONTROL_KEEPWARM_STATE_DIR` (same absolute directory) wherever you set it, then in a new shell `env | grep KEEPWARM_STATE_DIR` prints only the new name.
- Repo: plugins — pinned at their releases: cache-live-control 0.8.0 (keep-warm folded in from cache-keepwarm; imports pass Claude Code 2.1.330's strict validator), forward-compaction 2.4.0 (a wake lists skills and later files instead of carrying them; a sub-agent keeps what its child agents return across a compaction) and flights 2.0.2 (god speed stays with the main chat; the speccer returns user forks as BLOCKED).
- Repo: infra/install-ping — this repo's own `/install-stats` command reads the live install counter, and `stats.sh` prints aligned tables, without `column(1)`, and every install id; `-dev` versions count as development builds.
- Repo: /pfm:release — `--hold {plugin,…}` leaves plugins out of a cut, and the plugin gate counts only commits that change a file.

## Fixed

- pfm: Herdr new space — a chat born in a new Herdr space takes the place of the space's starting shell tab, so killing the chat no longer leaves the space holding only the pfm picker.
- pfm: long-lived pfm processes — after a `pfm install` replaces the binary, a chat's pfm MCP server hands over to the installed pfm, and a chat's seat host re-runs the installed pfm at every engine start and at chat end, so a newer state database no longer fails calls, exit or chat end. A chat open during this update runs v0.89.0's server and seat host, which have no hand-over, and stays on the old build until it restarts; the hand-over works from the next install on.
- pfm: pfm update rollback — a failed `pfm update` returns the state database to its copy from before the update, so the restored binary never meets a newer schema. `pfm update` runs from the binary you update from, so this applies first to the update after this one.

## Removed

- Global: retired.json — `cache-keepwarm@professor` is retired for `cache-live-control`: the update's `pfm install` disables it once `cache-live-control` is installed. Its installed copy stays on disk, disabled, and its old state directory `~/.local/state/cache-keepwarm/` is no longer read; both may be deleted.
- Repo: plugins/cache-keepwarm — the submodule and its marketplace entry are gone.
