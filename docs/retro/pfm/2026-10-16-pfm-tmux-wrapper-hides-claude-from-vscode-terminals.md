# 2026-10-16 — the pfm `claude` wrapper's tmux layer hides a session from the VS Code terminal that launched it

Observed: building a VS Code extension that maps Claude Code hook events to the terminal they came from (terminal-pulse, experiment E3), the hook's process-ancestry walk reached the terminal's shell PID for a plain `claude`, but not for the user's normal `claude`: the pfm wrapper runs the session inside its own tmux server, so the ancestry ends at the tmux server and a TTY match fails too. Under the wrapper `/exit` also closes the terminal without the `claude` command's own shell-integration end event. A second open question surfaced: whether `pfm install` ever strips foreign hook entries from `~/.claude/settings.json` (`validateAccountHooks` only validates; the stripping path was not traced) — if it does, any third-party hook consumer is silently disconnected on every install.

Amend: judgment — any tool linking a Claude session to its terminal must resolve `$TMUX`/`$TMUX_PANE` through `tmux list-clients` to the client's parent chain; worth one line in the pfm chat/launch docs. Trace `pfm install`'s handling of foreign hooks in `~/.claude/settings.json` and document the answer.
