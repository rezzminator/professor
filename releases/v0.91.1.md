# v0.91.1 — 2026-11-24

A chat pfm launches after the update finds every tool your login shell puts on PATH — mise, nvm, asdf or Homebrew shims, and so `go`, `node`, `npm` and `python` — even when pfm itself runs with a bare PATH, as under a systemd unit or the chat MCP server. The picker no longer drops its oldest resumable chats on a refresh, and its header counts hold still between the first frame and the full one. Nothing needs doing beyond the update itself.

## Fixed

- pfm: chat PATH — a Claude chat pfm launches (a pane, a headless run, a chat started by the chat MCP server or a systemd unit) now gains the folders your account's login shell adds to PATH: pfm asks that shell (looked up with `getent` on Linux and `dscl` on macOS, else `$SHELL`) for its PATH once per pfm process, waiting at most 3 s, and adds only the folders the launch PATH lacks — after a pane shell's own PATH, or, for a launch pfm runs itself, where the login PATH places each — so a tool your shell already resolves keeps resolving to the same copy; a persona's own PATH is kept as written. A probe that fails (a slow startup file, a loaded host) leaves the launch PATH unchanged and is tried again after a minute instead of staying failed for the rest of the pfm process; a pane whose PATH is empty or unset gains no empty entry, and a fish default shell works unchanged.
- pfm: picker and pfm ls — the picker's refresh no longer hides its oldest resumable chats while the full view loads: the capped first frame now leaves live chats out of the 30 Claude and 15 Codex resume slots; the header's empty and hidden counts no longer change between the first frame and the full one, a chat hidden by a legacy `_HIDE` name now counting as hidden in both; a native Herdr Codex seat on a forked thread no longer leaves a duplicate resume row beside it in the picker or `pfm ls`.
- Repo: fence — a shared fence run started outside the fence container, as CI's gate runs on its runner, now ends on SIGTERM instead of hanging until its 120 s heartbeat limit; the fence's own path is unchanged.
