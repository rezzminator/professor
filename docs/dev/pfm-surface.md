## Global

- Config: `{clone}/pfm.config.json` (strict JSON; accounts, emoji, theme, permission posture, MCP, ask; `--config PATH` or `PFM_CONFIG` overrides). `mcp.thirdParty` holds non-pfm servers included in every Claude launch payload. Read-only host checks report legacy config and print fixes through doctor. `claude.systemPrompt` selects `production`, `lean` or `professor`; `claude.maxSubagentSpawnDepth` and `claude.maxConcurrentSubagents` set launch limits. `claude.costLedger` (default `true`, machine-wide) turns the per-call cost ledger on or off; `PFM_COST_LEDGER_DIR` relocates its directory. `claude.plugins` (machine-wide) lists the plugins `pfm install` ensures and `pfm doctor` checks: a bare name of ours, a full `name@marketplace` id, or `{"id", "source"}` for an id whose marketplace Claude Code does not know yet (`source` is what `claude plugin marketplace add` takes); unset, it is `cache-live-control`, `forward-compaction`, `auto-effort`, `tool-visibility-controller`, `engine-sync` and `flights`, and `[]` requests none through this list. An invalid entry fails config load naming its index, as does one marketplace given two different sources. `claude.pluginCheckoutRoot` names the plugin checkout root an alpha `pfm install` copies each listed bare name from (`{root}/{plugin}/plugins/{plugin}`); unset, the root is the source clone's `plugins/`, and a plugin without a checkout there falls back to its GitHub copy. Each build disables the copy of a bare name it does not install; a plugin the list does not name is never touched. `claude.env` (machine-wide) maps plugin-option variables (`{PLUGIN}_{OPTION}`, upper snake) to string values that `pfm install` writes into the primary account's `settings.json` `env`, owning only the names it wrote (ledger `claude-env-ownership.json` in the managed root); a bad name or a non-string value fails config load. Missing config uses defaults, including mandatory account 1; malformed config fails ordinary commands while doctor and config diagnostics name the error. `config show` redacts secrets.
- Harness prompts: `pfm install` and `pfm generate` assemble one prompt per engine from the source parts (`share/head.md`, the engine middle, `share/tail.md`; the Codex mapping applies after assembly, to the full Codex prompt) in the recorded clone's `pfm/harness-prompts/`, else, with no such tree (a binary-only install, whose tree holds only `generated/`), the copy embedded in the binary, and write `{clone}/pfm/harness-prompts/generated/{claude,codex,opencode}.md` before any consumer runs; a tree missing a part is an error naming it, never a fallback. `generated/` is gitignored and never embedded; nothing assembles prompts at build time. Managed Claude launches read `generated/claude.md` through `--system-prompt-file`; `pfm install` reads `generated/codex.md` into each configured Codex home's `config.toml` as `developer_instructions`, inside its installer-owned fence; OpenCode's `instructions` array references `generated/opencode.md`. A Codex agent role's in-memory fleet prompt (`codexprompt.FleetPrompt`) and doctor's `codex developer_instructions=` comparison are assembled from the same source parts. `pfm install` does not stage prompt copies.
- One binary, one dispatch. Everything below is `pfm <command> …`.

### install

Preview by default. A BLOCK host check exits 4 before writes; warnings continue. A quiet gate permits a lossless store build: create missing shared entries and real account dirs, link shared entries to `~/.claude`, preserve existing data. Registries are written once into the store; Claude plugins install once through the primary account; an alpha build installs every plugin the clone's marketplace lists from its checkout, enables those `claude.plugins` names, and fails the run on a listed one it leaves off its `{name}@professor` copy in `~/.local/share/professor-dev` or disabled. `claude.env` lands in the primary account's `settings.json` `env`; a name pfm wrote and the effective map dropped is removed unless changed by hand. Managed settings own cleanup. Source-fetched skills are stored under `~/.local/share/pfm/install/skills/{name}` and linked into `~/.claude/skills` and `~/.agents/skills`; failed fetches keep the last copy. Dead pfm-owned registry links are pruned; live foreign entries survive. Also builds Codex agents, marker-owned mirrors, scheduler and enabled MCP wiring. `--check` runs read-only pre-change checks.

### usage-hook

The hook and the `ls` Limits tab share the account cache in `usagehook.DefaultCacheDir` and reach the usage endpoint only through `usagehook.Fetch`. The hook uses its 180-second default TTL (`CC_USAGE_TTL`); the focused Limits tab uses sixty-second freshness (`LiveLimitsTTL`) and polls completed account results every two seconds. Accounts refresh independently, and pending requests are canceled when Limits loses focus or the picker closes. The display labels percentages as quota **used** and advances confirmation ages and reset countdowns every five seconds, including under `--no-sky`.

`usagehook.Fetch` answers, in order, from: a fresh `cc-rate-limits` statusline snapshot of the seat; a cache record fresh within the caller's TTL; an active shared backoff (the cached usage with the backoff's error); then, holding the `O_EXCL` refresh lock `acct-<id>.lock` (stale after 30 seconds; a caller that cannot take it answers from the cache; the holder re-reads the cache first), one request sent with `User-Agent: pfm/{version}`. A cached result retains its provider confirmation time. HTTP 429 responses impose a shared backoff of at least ten minutes, honoring a longer `Retry-After`, and the card reads `rate-limited — retry HH:MM` with the retry time first; other provider failures back off for sixty seconds. Cached values remain visible with the failure reason during a temporary outage. Refreshing an account never blocks the other cards. The hook writes a failed refresh to stderr.

### `pfm internal epic-inject` ✚

UserPromptSubmit hook. Resolves the pane's chat name each turn; on `^E_([A-Za-z0-9][A-Za-z0-9-]*)_` finds `docs/epics/{slug}/manifest.md` from cwd upward and emits it as additionalContext prefixed with marker `INJECTED EPIC {slug}/manifest.md` (visible provenance only). Once-only state is STRUCTURED: the shared store records `(session_id, slug)` — same epic never re-injects (not even on manifest edits; no content hashes), a rename into a different epic injects that one once, renaming back stays silent. No hook needed on `/rename` (per-turn re-check). Missing manifest → silent.

### `pfm internal reload-intercept` ✚

UserPromptSubmit hook. A prompt that is exactly `/reload` or starts `/reload` is split with a quote-aware word splitter and run through the `chat reload` front IN-PROCESS (no re-exec); the front's captured stdout+stderr — its own validation errors included — is written back to the hook's stderr prefixed `reload: `, and the hook exits 2 every time a `/reload …` prompt matched, success or failure, so it never reaches the model. An unmatched prompt or a malformed hook payload exits 0 silently. Claude only — Codex has no UserPromptSubmit hook, so a Codex seat's `/reload` still goes through the model and the `/reload` command body. A `/exit` the owner types while the reload still waits (the 1.5 s delay, or the chat's turn to end) ends the chat: the reload respawns nothing, closes a pane `remain-on-exit` kept, prints `pfm chat reload: the chat ended before its reboot, nothing respawned: {socket} {pane}`, and its state trail reaches `ended`.

### `pfm internal schedule-fire` ✚

The scheduler's tick for `pfm chat schedule` (no flags; an extra argument → rc 2). Under a flock on `schedule-fire.lock` beside the state DB it delivers every due schedule once: a live chat receives its schedule by session id, a dead one is resumed detached on a fresh tmux socket, its composer awaited (3 consecutive captures, 90 s bound; a folder-trust dialog fails at once with nothing typed), then receives a scheduled message from the chat that set it: `⏰ pfm schedule <id> (every <interval>): <prompt>`, or `(once)` for a one-time schedule. A delivered schedule is rescheduled `now + interval` (missed intervals fire once, never a burst) and marked unseen; a delivered one-time schedule never fires again and is deleted when its chat is opened. Stdout: `fired schedule <id> → <label or session>` per delivery. A delivery that fails keeps its schedule due with the error stored in `last_error`, and stderr names it: `pfm internal schedule-fire: schedule <id> (<label>, <session>): <error> — stays due` (rc 1); the remaining due schedules still fire. Another fire holding the lock → `skipped` on stderr, rc 0. Nothing due → no output, rc 0. Scheduled by `pfm install`: `pfm-schedule.timer` (`OnCalendar=*:0/5`, `Persistent=true`) driving the oneshot `pfm-schedule.service` on Linux, and the `com.professor.pfm.schedule` launch agent (`StartInterval` 300) on macOS. A mutating install waits up to 90 s for a running fire, then refuses if it is still running. `doctor: schedules scheduler=<systemd|launchd|none> unit=<timer|label> armed=<bool> state=<word>[ drift=<path>|drift=could_not_compare error=<err>] due=<n> overdue=<n> failed=<n>[ — hints]`; `db=unreadable error=<err>` replaces the counts when the state DB cannot be read; `could_not_ask error=<err>` when the manager gave no answer; a warning when the timer is missing or inactive, or a schedule is overdue (more than 15m) or failed, or an installed timer, service or launch agent differs from what install writes.

### `pfm internal exit-intercept` ✚

UserPromptSubmit hook. A prompt that is exactly `e` or `/e` runs the `chat kill` front IN-PROCESS as `--self --exit`; the front's captured stdout+stderr is written back to the hook's stderr prefixed `exit: `, and the hook exits 2 on a match, success or failure, so the prompt never reaches the model. Any other prompt — `exit`, `E`, `e` with trailing text, a normal sentence — or a malformed payload exits 0 and passes through untouched. Claude only; a Codex seat's `e` still goes through the model. The close itself sends `/exit` to the pane, so the TERMINAL is closed by `exit-close` below: one closer, two entry points, which is why the two spellings cannot drift.

### `pfm internal exit-close` ✚

SessionEnd hook. Closes the terminal a chat was being WATCHED through when the human ends it with `/exit`. The chat pane needs no help — a fleet seat is exec'd, so the engine is the pane root and the pane dies with it; what survives is the shell that SPAWNED `tmux attach` as a child (a VS Code tab's zsh), which returns to a prompt that is the tab left open. The hook reads the chat socket from `$TMUX`, lists the server's clients, and hangs up each client's PARENT when that parent is a terminal shell. Acts ONLY on reason `prompt_input_exit`: `clear` must fall through, because that chat keeps running. Guards, each reporting by name rather than as absence — a parent at pid <= 1, a parent that is not a shell, the hook's own pid, and a socket whose basename is not a fleet socket (the gate that keeps the hook off a human's own tmux, since the same settings file arms it for every Claude session on the host). Fail-open on every path: a hook that can refuse a session's exit is worse than a terminal left open. It leaves the terminal open only while a `pfm chat reload` holds the pane lock and the exit mark `{sid dir}/.{socket}.{pane}.reloadlock.exit` exists (`reload.ExitTyped`), that is from the reload's own `/exit` to its respawn; a `/exit` the owner types earlier closes the terminal. It detaches each tmux client first (`detach-client`), waits up to 2 s for it to exit, and only then hangs up the terminal's shell.

### `pfm internal herdr-state` ✚

`pfm internal herdr-state [--engine claude|codex|opencode] <start|working|blocked|idle|end|notification|title>` (Claude also `agent-start|agent-stop`), `pfm internal herdr-state <attach|sync|detach|name> --socket {tmux socket} --session {tmux session} [--client {tmux client pid}]`. Hook backend of the Herdr reporter: Claude's ten launch rows, Codex's seven `hooks.json` handlers and the OpenCode plugin run it with the hook JSON on stdin (`session_id`, `cwd`, `agent_id`, `hook_event_name`, `source`, `reason`, `notification_type`, `message`, `tool_name`, `tool_input`, `is_interrupt`). Tmux-backed chats and the Codex/OpenCode reporters send `pane.report_agent` or `pane.release_agent` to `$HERDR_SOCKET_PATH` under source `pfm`. A native (non-tmux) Claude in a pane where Herdr sees it gets no state, session or `resume_argv` from pfm: Herdr's screen detection and its own Claude integration own it, and `nativeSeat` keeps the durable seat bookkeeping and the name, releasing only a report it left there under `pfm` while the pane read otherwise. Where Herdr lists a pane foreground without Claude, Herdr sees no agent, so a native Claude there reports under `pfm` with custom `[pfm, chat, open, --restored, {SID}]` argv. `retireNativeTargets` removes an older build's native targets (under `herdr:claude`, or with no `source`) from `Targets` under the activity lock and releases each once, retaining positively proved tmux targets and native ones under `pfm`; an old worker shares that lock and rereads the list; `pfm install` runs it over every record once (`hookentry.ReleaseNativeClaudeReports`). Tmux and native Claude activity share the lock and its watchdog. The twenty-three Claude hooks and non-state integration remain in place; `attach` registers the attaching tmux client with its Herdr pane and re-reports the state the chat stored in its session option `@pfm_herdr` (the chat server's `client-attached[50]` hook); `sync` re-binds a registered client whose pane moved (`client-resized[50]`), `detach` releases its pane (`client-detached[50]`), `name` re-sends the chat name (`window-renamed[50]`). A sub-agent event (a payload `agent_id`, or an OpenCode child session) never touches the pane, except Claude's `SubagentStart` and `SubagentStop` (`agent-start`, `agent-stop`), tmux-backed or native, which keep a per-session set of running agents. It exits 0 on every path and is a silent no-op outside a Herdr pane. Design: `docs/design/hooks/hooks.md` § Herdr reporter.

### `pfm internal herdr-indicators` ✚

`pfm internal herdr-indicators`, no arguments. Command of pfm's Herdr plugin `professor.indicators`, run by Herdr at server start and on the pane, tab and workspace events of `herdr.IndicatorEvents()`. It paints the sidebar state marks on the Herdr server at `$HERDR_SOCKET_PATH`: per pane and per workspace, the custom token its Herdr `agent_status` maps to (`pfm_working` `●`, `pfm_blocked` `●` blinking at 1 Hz, `pfm_done` `✓`, `pfm_unknown` `○` for a plain shell or unrecognized program, idle none), under the source `pfm-indicators`, writing only what changed; while anything is blocked or done, or an eligible chat tab exists, one run per socket keeps reconciling, the lock and the socket's record (which `pfm theme off` clears the tokens through) in `~/.local/state/pfm/herdr/`. The same run paints sole-chat tab labels from `SeatInspector` through `chat.PaintHerdrIndicators`, using `chat.herdrTabStatus` (`emoji` default, `text`, `off`). The run holds one fleet store open across its ticks (`store.Held`, `pfm/internal/chat/herdr_indicators_run.go`): its scans, pane proofs and tab validations reuse those connections, each scan rereading the cache's `transcripts` and `rollouts` only where written since the last one (`pfm/internal/store/rowcache.go`), and the store opens again only when a database file is removed, replaced or migrated in place by another pfm (its `user_version` moved; a file newer than the binary is then refused as at any open), or 10 s after its shared half failed to open. Only blocked and error tab markers pulse (every other state is one still frame); newer working/idle/dead observations stop the pulse. Errors go to stderr (Herdr's plugin log) and the persistent Herdr error log, exit 1; an unset `$HERDR_SOCKET_PATH` is an error naming it. A painter whose Herdr server is shutting down (`server_unavailable`, `herdr.ServerStopping`) stands down with a stderr note and exit 0, in its paint, its blink and its theme-off clear. Design: `docs/design/hooks/hooks.md` § Herdr reporter, Sidebar indicators.

### `pfm internal herdr-places` ✚

`pfm internal herdr-places`, no arguments. Second startup command of pfm's Herdr plugin `professor.indicators`, run by Herdr once when its server starts: on the server at `$HERDR_SOCKET_PATH` it moves every live native chat that sits outside its place's workspace into it (`spawn.ReconcileHerdr`), creating the workspace a place lacks. An unset `$HERDR_SOCKET_PATH` does nothing, exit 0, no output. A chat it could not move, or a scan or Herdr failure, is a `pfm internal herdr-places:` stderr line (Herdr's plugin log), exit 1. Design: `docs/design/engines/claude-launch.md` § Herdr places.

### `pfm internal herdr-shell resume-pending` ✚

`pfm internal herdr-shell resume-pending`, no arguments. Called by the shim's auto-open before it opens the picker: reads `$HERDR_SOCKET_PATH` and `$HERDR_PANE_ID` and prints `pending` when Herdr itself resumes this pane's agent (the pane was restored with an agent session), else `no`. Exits 0 on every path; a read it cannot make prints `no` and logs one WARN naming the pane.

## MCP surface

The pfm daemon serves `/mcp/chat-professor`. The independent Harvester plugin registers its own `harvester` server through each engine's native plugin system.

### Family server registrations

The chat registration is `chat-professor`; its stdio command is `pfm mcp serve --stdio --family chat`. Claude Code and Codex see `mcp__chat-professor__<verb>`; OpenCode sees `chat-professor_<verb>`. The Inputs columns below are a reading aid. Each server's own `tools/list` answer is the contract.

If an enabled family fails configuration, its server still lists that family's normal bare tools. Each call returns an explicit configuration error naming the corrective config key or file and directing the client to reconnect with `/mcp` or start a new chat; the healthy family remains independently available. In-process fallback serves the same error tools for the failed family.

#### Family chat

Toggled by `mcp.servers.chat.enabled`.

The chat MCP family has no transcript-reading verbs: old-transcript inspection goes to the `agent-investigator` agent or `/chatlog`, while the CLI `read` and `find` verbs and `pfm transcript show` stay shell commands. `save` and the live-state tools (`last`, `status`, `capture`) stay MCP tools.

| Tool | Status | Inputs | Returns |
| --------------------------- | ------ | --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ls` | ● | `{all?, killed?, project?, limit?}` | Fleet rows (accounts, engines, sizes, liveness), including chats still booting. `project` filters case-insensitively on project label or directory; rows are capped (200 default, 1000 max) with `matched`/`truncated` reporting the cut. Without `all`, rows are scoped to the caller's repository (a linked worktree counts as its repo) when `_meta` resolves the caller; `scope` names the repo or `all repos — caller cwd unknown`, `elsewhere` counts the rows left out. `all` also adds killed and background rows, unlike `pfm chat ls --all`, which stays on live chats. |

## pfm model-cost

**CLI:** `pfm model-cost gpt-6.1-sol`, `pfm model-cost --json --all` or `pfm model-cost --check` · **Consumers:** `pfm tokens`, the `chatlog` skill and its `chatlog.py` kit (prices only), the status line, `pfm doctor`, `pfm install`

One price source: `pfm/internal/pricing/prices.json` in the Professor clone — tracked, embedded into pfm, and the refresh target. Each row carries a model key, its engine and USD per million tokens: `in` and `out`, plus Claude `hit`/`w5m`/`w1h` or OpenAI `cached` where the publisher lists them (an absent rate is unpublished, never 0), and an optional `long` tier that applies when one call's context is above its `above`. `pfm.prices.json` beside `pfm.config.json` overrides rows by key and may name the Claude billing route ([Billing route and region](#billing-route-and-region)).

Every call refreshes first, at most once a day per pfm binary: the table is current while the check stamp `~/.local/state/pfm/prices-checked` (`{time} {sha256 of prices.json} {binary}`, the binary `exe-sha256:` and the sha256 of the executable the running pfm started from; one replaced on disk since is no binary) confirms the clone file, was written by this binary and is under 24 hours old; a stamp from another binary or one naming none is stale, so a refresh just before a host install never keeps the old parse, and a machine with no clone file keeps the embedded table while its `fetched_at` is under 24 hours old; otherwise both official pages ([Anthropic pricing](https://platform.claude.com/docs/en/about-claude/pricing.md), [OpenAI pricing](https://developers.openai.com/api/docs/pricing.md)) are fetched and the rows derived, and the clone file is rewritten only when they change. `--force` refreshes regardless; `PFM_PRICES_OFFLINE=1` never fetches, `--force` included. A failed fetch serves the loaded table with a warning (exit 1 only under `--force`).

The text output is one `prices:` summary line (rows, fetch time, where the table came from, the refresh status, the override) and a table; `--json` prints the document `pfm tokens --prices` reads, `--check` the summary line only, exit 1 when the table cannot load. An id resolves after normalization (case, provider prefix, Bedrock and Vertex suffixes, Claude dots) to its exact key, else to its key without a trailing snapshot date; any other id exits 1 naming `pfm model-cost --all`.

Coverage is the direct API Standard list prices on these pages, unless `pfm.prices.json` names another billing route. Negotiated rates, account-specific discounts and other service modes are outside the table; `pfm.prices.json` carries a negotiated rate. `pfm tokens` estimates recorded usage at these current rates and reports missing prices as unavailable; it does not claim historical billing amounts.

### Billing route and region

`pfm.prices.json` is `{"version":2,"billing":{"route":"bedrock","region":"geo"},"rows":[…]}`; `billing` is optional and strict (`pfm/internal/pricing/billing.go`). The pair is never inferred from the environment, and an unlisted pair is an error naming the file:

| Route | Regions | Claude 4.5+ published rates |
| --- | --- | --- |
| `direct` | `global` | list price, the default |
| `bedrock` | `global`, `geo` | `global` at list price, `geo` times 1.1 |
| `vertex` | `global`, `regional` | `global` at list price, `regional` times 1.1 |

- **Scope.** The premium applies only to published Claude rows of 4.5 and later (`regionalPremium`), long tier included; older and unversioned keys are not marked up. A `pfm.prices.json` row is a final billed rate and is never multiplied.
- **Provenance.** A `bedrock` or `vertex` route adds that cloud's pricing page to the table's sources; `claude-sonnet-5-5` cache reads are set to 0.10 under those routes, the rate both partner lists carry.
- **Surfaces.** `--json` carries `billing` (`route`, `region`, `configured`, `multiplier`), `--check` and the text summary line end `· billing: {route}/{region}` with `(default; cloud rates may differ)` when none is configured, and `pfm tokens` states the same in its pricing and data-gaps lines.

## pfm tokens

**CLI:** `pfm tokens [--since 24h|3d] [--root DIR]… [--project SUBSTR] [--family SUBSTR] [--family-rx RE] [--session SID] [--top N] [--out FILE] [--view FILE] [--briefs FILE] [--host-label NAME]`, `pfm tokens --codex [--since 24h|3d] [--project SUBSTR] [--codex-root DIR] [--top N]`, `pfm tokens --opencode [--since 24h|3d] [--project SUBSTR] [--opencode-root DIR] [--top N]`, `pfm tokens --tree SESSION|AGENT [--worktree DIR --base SHA] [--root DIR]… [--json] [--out FILE]`, each with `[--prices FILE]` · **Consumers:** the `chatlog` skill (documents it; its `chatlog.py` kit parses natively), `/flights:doctor` (reads `--tree`)

The read-only audit of agent transcripts: where did the tokens go. It replays Claude Code transcripts (pfm's resolved Claude roots, or `--root`) and Codex rollouts (`sessions/` and `archived_sessions/` of every Codex home pfm resolves, or `--codex-root`) and OpenCode sessions (each assistant message's own token record in the `opencode.db` of every OpenCode root pfm resolves, or `--opencode-root`, read through `internal/index`; OpenCode's recorded cost shows beside the estimate, never in its place), prices every call from the table `pfm model-cost` serves (or a saved `pfm model-cost --json --all` document or `prices.json` via `--prices`), and traces each dollar to the context that caused it. A text report on stdout; `--out`, `--view` and `--briefs` write JSON. `--tree` measures one Claude Code spawn tree, read from `{projects}/{project}/{session}.jsonl` and its `{session}/subagents/agent-{id}.jsonl` with each `agent-{id}.meta.json` (`agentType`, `parentAgentId`): a session id roots it at the main session and takes every sub-agent, an agent id at that agent and its descendants, searched under every `--root`, else `$CLAUDE_CONFIG_DIR/projects` then pfm's resolved Claude roots. Per agent: model, input, cache-read and cache-write tokens, USD, the bytes it wrote (`Write`, `Edit`, `MultiEdit`, `NotebookEdit` inputs whose target is under `--worktree`, else the session's cwd, never under `/tmp` or `/private/tmp`), the text bytes of every tool result it received, and their ratio, a transcript line that is no record counted in the row's `undecodableLines` (the text row's tail), its writes and reads in neither byte total; per tree: total input tokens, the silent share (input taken by agents that wrote nothing), written/read per agent type, and with `--worktree DIR --base SHA` the landed code lines (`git diff --numstat` against the base plus untracked files, tests, docs, generated, lock and binary files excluded under the rules `landed-rules/1` in `internal/tokens/landed.go`) and landed lines per million input tokens; without the pair they print `NOT MEASURED — pass --worktree DIR --base SHA`; a landed-lines count that fails prints the report with `NOT MEASURED — --tree {ID}: landed lines: {error}`, names the failure on stderr and exits 1. `--json` prints the document `internal/tokens/tree.go` specifies, `--out` writes it; an agent it cannot read (its meta, its transcript or its parent chain) is a row marked `unreadable` and counted in `NOT READ`, and the run exits 1. An unpriced model renders `n/a`, never $0. A record without a timestamp counts, placed at the previous record's time, else the transcript's modification time, and the data gaps name it: `N records without a timestamp (placed at the previous record's time, else the file's)`. An invalid `pfm.prices.json` override prices every call by the published table, the first data gap `price override unusable ({error}) — dollars use the published table without it`. A Claude chat with a cost ledger adds a `== COST LEDGER` block: the session total (the status line's number), the side calls no transcript holds, the ledger-minus-Claude-Code difference, and cost and share per agent and per `query_source`; a chat without one prints `side calls not measured (no cost ledger)` (`docs/design/engines/cost-ledger.md`). Exit 2 on a usage error, 1 when a `--prices` file cannot load or anything could not be read.

## pfm transcript

**CLI:** `pfm transcript {show|locate|agents} TARGET [--root DIR]… [--only KINDS] [--tool NAMES]… [--since T] [--until T] [--grep RE [-i]] [--first N] [--last N] [--results brief|none|full|tail:N] [--err-lines N] [--text N] [--final N] [--lines FROM-TO] [--width N] [--out FILE]` · **Consumers:** `digest`, the `chatlog` skill (documents it; its `chatlog.py` kit parses natively), `agent-investigator`

The mechanical reader of one Claude Code, Codex or OpenCode transcript (`internal/transcript/digest`): `show` prints one line per event (prompt, reply, call with its result, note, final), its transcript line first; `locate` the resolved path; `agents` a top-level Claude session's sub-agents, nested workflows included, or an OpenCode session's child sessions. TARGET is a path, a Claude session or agent id or prefix, a Codex thread id or prefix, a Codex agent path (`/root/…`), a Claude chat's title, an OpenCode session id, prefix or title, or an OpenCode locator `{store}#{session id}`; ids resolve under pfm's resolved Claude roots and Codex homes plus each `--root`, and under pfm's resolved OpenCode roots. An OpenCode session is read from its store through `internal/index`: its line numbers are record numbers and its header's `STORE` line, in place of `FILE`, says no record carries a file line or a byte size. Every record not rendered is counted in the `SKIPPED` line. A failure is one `TRANSCRIPT FAILED — …` line on stderr, warnings `TRANSCRIPT WARNING — …`: exit 2 on a usage error, 1 when the transcript cannot be found or read.

## Shared engine `internal/ask`

Content-agnostic one-shot runner for pfm chat operations; `CheckModel` refuses, by name, an explicit model its engine cannot run (a Claude alias or a price-table row of that engine passes). **Two engines, selected in config** (`ask.engine`): `codex` (default `gpt-5.6-luna` @ `low`) and `claude` (headless `claude -p`, default `claude-haiku-4-5` @ `low`); per-call override via the CLI's `--engine`, `--model`, and `--effort` flags. The Codex runner uses `codex exec`; both binaries resolve through `internal/deps`, and each process uses the first account home from its configured engine roster. The default timeout is 60 seconds.

```
Engine.Run(ctx, AskInput) (AskResult, error)
  AskInput  { ContentFiles []string; SourceLabels []string; Prompt string;
              Engine, Model, Effort string /* "" → config ask.* */ }
  AskResult { Answer string; Evidence []Evidence; PerFile []FileStatus;
              Usage *TokenUsage; Duration time.Duration }
  Evidence  { File string; Label string; Span SourceSpan /* lines|turns|chunk */; Quote string }
```

The fixed harness prompt requires an `EVIDENCE` section with file numbers, locations, and short quotes. Current process adapters return that section inside `Answer`; they populate `Usage` only when the child emits recognized token counters, and leave `Evidence`/`PerFile` empty. A missing usage line leaves `Usage` nil.

The harvester owns source discovery, keeps each original input in `SourceLabels`, and passes full cache-file paths to the one model process. It does not substitute clipped terminal previews or run a hidden map-reduce pass. Failed sources become temporary JSON receipt files so the same model pass can name unavailable evidence explicitly.
