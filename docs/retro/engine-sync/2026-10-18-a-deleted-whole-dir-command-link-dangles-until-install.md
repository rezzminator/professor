# 2026-10-18 — a deleted whole-directory command leaves a dangling link that fails check and doctor until the next install

Observed: the imagine-family collapse (commit 471d4b63) deleted `templates/global/commands/imagine/`, which `pfm install` had linked as a whole directory (`~/.claude/commands/imagine`). The link dangled, and `engine-sync codex check .` and `engine-sync opencode doctor .` both exited 1 on `dangling source ~/.claude/commands/imagine` until the next install. `engine-sync global --plan` stopped at the same link as a conflict and never listed the command-mirror prunes it would make, though its own message says `engine-sync global` prunes an orphaned global-command link. The machine policy carries `retiredAgents` and `retiredFiles`, but nothing for retired commands or skills, so the retirement could not be declared in the change that made it.

Amend: `plugins/engine-sync/internal/config/config.go` (machine policy) and `templates/global/engine-sync.json` — add a retired-commands and retired-skills declaration that `engine-sync global` prunes, so check and doctor read a retired link as retired instead of dangling; and `engine-sync global --plan` lists the prunes it would make past a dangling link instead of stopping at it.
